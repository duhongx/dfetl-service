# 同步策略说明

> 文档最近代码对齐：2026-07-24。数据范围（FULL/INCREMENTAL/CUSTOM_WINDOW）与写入模式（TRUNCATE/APPEND/UPSERT）是两个维度。

同步策略决定 dfetl 如何读取源端、如何写入 Doris、是否推进水位线，以及同步成功后如何校验。

## 核心属性

| 属性 | 含义 | 作用 |
|------|------|------|
| **增量字段** | 用于判断哪些数据是新的或变化的 | 生成源端 WHERE 窗口 |
| **Upsert 键** | 业务主键，用于去重/覆盖 | Doris 建表的 UNIQUE KEY 列 |
| **分片字段** | SeaTunnel JDBC Source 并发读取字段 | 生成 `partition_column` |
| **Doris 表模型** | UNIQUE_KEY / DUPLICATE_KEY | 决定数据写入行为 |
| **校验方式** | ROW_COUNT / CHECKSUM | 判断源端和目标端是否一致 |

### 增量字段

- 通常是时间字段（如 `xiugaisj`、`chuangjiansj`、`updated_at`）
- 也可以是自增 ID（如 `id`、`feiyongid`）
- 要求：新增或修改数据必须能进入下一次窗口

### Upsert 键

- 物理表：自动读取数据库主键
- 视图：从医共体规范定义中读取业务唯一键
- 自定义 SQL：需手动指定
- 作用：相同 KEY 值的数据写入 Doris 时会覆盖旧记录

### 分片字段

- 只影响 SeaTunnel Reader 并发读取，不等同于 Doris 分区字段
- 小表不需要配置
- 大表建议选择数值主键、自增 ID 或分布均匀的字段
- 未配置时 Reader 实际并发固定为 1，避免重复读取同一条 SQL

## 策略一：全量同步

“全量同步”模板默认使用 TRUNCATE，因此每次清空目标表后写入全量数据。高级配置也可以用 FULL + UPSERT；FULL 只表示读取全量，不天然等于清空。

| 属性 | 配置 |
|------|------|
| 增量键 | 不需要 |
| Upsert 键 | 不需要 |
| 分片字段 | 可选；默认不配置 |
| Doris 表模型 | DUPLICATE_KEY |
| Reader 并发 | 默认 1 |

**适用场景：**
- 字典表、维度表、配置表
- 数据量小（< 100 万行）
- 没有可靠增量字段的表

**特点：**
- 每次全量覆盖，数据最一致
- 目标表使用 DUPLICATE_KEY，分区列无限制
- 执行频率建议：每天 1-2 次

**风险提示：**

- 大表全量耗时较长，会持续占用源库、SeaTunnel 和 Doris。
- 没有分片字段时不要把 Reader 并发调大。

---

## 策略二：全量 + 增量

首次执行跑全量，后续按增量字段只同步新增/变更数据。

| 属性 | 配置 |
|------|------|
| 增量字段 | **必填**（如 xiugaisj） |
| Upsert 键 | **必填**（如 bingrenid） |
| 分片字段 | 可选；大表可配置 |
| Doris 表模型 | UNIQUE_KEY + MoW |
| Reader 并发 | 有分片字段或 ID_RANGE 时可大于 1 |

**适用场景：**
- 绝大多数业务主表（患者、就诊、处方、费用等）
- 数据量 1000 万 - 5000 万
- 源端有可靠的修改时间字段

**特点：**
- 首次全量打底，后续只同步变化数据
- 同主键数据自动覆盖（UPSERT 语义）
- 增量执行速度快（通常几秒到几分钟）

**关键要求：**

- 增量字段必须可靠。UPDATE 后如果增量字段不变化，会漏同步。
- Upsert 键必须代表业务唯一记录。键选错会覆盖错行。
- 有物理删除时，需要软删字段、快照对账或人工处理流程。

---

## 策略三：仅增量 / 追加

不跑全量，只同步新增/窗口内数据，追加写入目标表。

| 属性 | 配置 |
|------|------|
| 增量字段 | **必填** |
| Upsert 键 | 可选 |
| 分片字段 | 可选 |
| Doris 表模型 | DUPLICATE_KEY（推荐） |

**适用场景：**
- 日志表、流水表、事件表
- 数据只追加不更新
- 不需要历史全量数据

**特点：**
- 追加写入，不去重
- 使用 DUPLICATE_KEY，分区列无限制
- 适合按时间分区（按月/按天）

**风险提示：**

- 如果源端会 UPDATE，同一业务记录可能在 Doris 中出现多条。
- 不适合需要“最新状态”的业务主表。

---

## 策略四：自定义窗口 / 高级

指定时间窗口补数/修数，本次执行不更新水位。

| 属性 | 配置 |
|------|------|
| 增量字段 | **必填** |
| Upsert 键 | 可选 |
| 分片字段 | 可选 |
| Doris 表模型 | 跟随原任务写入模式；补数优先使用可幂等的 UPSERT |

**适用场景：**
- 补历史数据
- 修复某个时间段的错误数据
- 特殊场景的一次性同步

**特点：**
- 手动指定窗口起止时间
- 不推进增量水位（不影响后续正常增量）
- 适合一次性处理，不建议长期调度
- APPEND 重复执行会重复写入；需要可重复补数时使用 UPSERT

---

## 决策矩阵

| 场景 | 推荐策略 | 表模型 | 增量字段 | Upsert 键 | 校验建议 |
|------|------|--------|--------|----------|---------|
| 字典表/小表 | 全量同步 | DUPLICATE_KEY | 不需要 | 不需要 | ROW_COUNT |
| 业务主表 | 全量 + 增量 | UNIQUE_KEY | 必填 | 必填 | CHECKSUM |
| 日志/流水表 | 仅增量 / 追加 | DUPLICATE_KEY | 必填 | 可选 | ROW_COUNT |
| 补数/修数 | 自定义窗口 | 按任务原模型 | 必填 | 按原任务 | 按影响范围选择 |

## 实际执行预览怎么看

新建任务页面会展示实际执行预览，重点看下面几项：

| 预览项 | 如何判断 |
| --- | --- |
| 写入语义 | 是否是清空写入、追加或 Upsert |
| `partition_column` | 无分片时应显示“无”；有分片时应是可信字段 |
| Reader 实际并发 | 无分片必须为 1 |
| 增量窗口 | 是否使用正确的增量字段和模式 |
| 校验 | 是否符合数据敏感度 |

> 原则：页面上的“配置并发”不如“实际执行预览”重要。最终以实际提交给 SeaTunnel 的 Job 为准。
