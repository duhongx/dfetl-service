# dfetl 平台概览

> 文档最近代码对齐：2026-07-24。

dfetl 是面向企业批量数据同步的管理平台。使用人员主要在页面上完成数据源接入、同步任务创建、任务运行监控、数据校验和异常处理；底层执行由 SeaTunnel 集群负责，目标端当前主要面向 Doris。

## 系统定位

| 模块 | 使用入口 | 主要用途 |
| --- | --- | --- |
| 源端数据源 | 数据源管理 → 源端数据源 | 管理 MySQL、PostgreSQL、Oracle、SQL Server 等源库连接 |
| 目标端数据源 | 数据源管理 → 目标端数据源 | 管理 Doris FE、HTTP、写入批量等目标端配置 |
| 同步任务 | 同步任务管理 | 创建、编辑、发布和运行同步任务 |
| 任务监控 | 任务运维 → 任务监控 | 查看执行状态、读写行数、失败原因和历史批次 |
| 数据校验 | 任务运维 → 数据校验 | 对比源端和目标端数据，发现差异 |
| 脏数据记录 | 当前无独立页面 | 后端保留 dirty-record API；日常先从监控、日志和 Doris load error 排查 |
| 日志中心 | 任务运维 → 日志中心 | 查询任务执行日志和异常摘要 |

## 同步链路

```text
源端数据库
  → dfetl 生成 SeaTunnel Job
  → SeaTunnel Cluster 读取源端数据
  → Doris Sink 写入目标表
  → dfetl 记录执行批次、状态、水位线
  → 同步成功后按配置触发数据校验
```

## 核心概念

| 概念 | 说明 | 常见问题 |
| --- | --- | --- |
| 增量字段 | 判断哪些数据是新增或修改的字段，如 `updated_at`、`xiugairq`、自增 `id` | 字段不可靠会漏同步 |
| Upsert 匹配键 | Doris UNIQUE KEY 的业务主键，用于覆盖同一业务记录 | 键选错会覆盖错数据 |
| 分片字段 `splitPk` | SeaTunnel JDBC Source 并发读取使用的字段 | 不配置时 Reader 必须单并发 |
| 水位线 | 记录上一次成功同步到哪里 | 只应在同步成功并通过必要校验后推进 |
| 校验配置 | 同步后对比源端和目标端 | 无主键只能做 ROW_COUNT |

## 推荐使用路径

1. 先在「源端数据源」和「目标端数据源」完成连接测试。
2. 在「同步任务管理」新建任务，选择源表或视图。
3. 选择同步策略，优先使用系统推荐配置。
4. 在确认页检查实际执行预览，重点看 `partition_column`、Reader 实际并发、写入语义和校验方式。
5. 发布任务后先手动运行一次，确认读写行数和校验结果。
6. 再开启定时调度。

## 日常关注指标

| 指标 | 正常情况 | 需要处理 |
| --- | --- | --- |
| 最近运行状态 | SUCCESS | FAILED、CANCELLED、长期 RUNNING |
| 读写行数 | 源端读数与目标写数接近 | 读数异常放大、写入失败、脏数据增多 |
| 当前水位 | 随成功任务推进 | 长时间不变或跳跃异常 |
| 校验结果 | PASS 或容忍范围内 | ROW_COUNT_DIFF、CHECKSUM_DIFF |
| Doris load 错误 | 无 | 字段类型、分区、唯一键、过滤比例错误 |
