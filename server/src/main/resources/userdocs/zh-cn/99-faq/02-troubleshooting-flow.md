# 同步失败排查流程

> 文档最近代码对齐：2026-07-24。

同步失败时，先不要重复点击运行。按下面顺序定位，可以避免重复写入、错误推进水位或扩大 Doris 写入压力。

## 1. 先确认失败发生在哪一段

| 现象 | 优先查看 | 常见原因 |
| --- | --- | --- |
| 提交后立即失败 | 任务详情 → 执行日志 | SeaTunnel REST 不通、任务配置非法、插件缺失 |
| 读数为 0 | SQL 预览、源端过滤条件 | 增量水位过新、字段名错误、时间格式不匹配 |
| 读数异常放大 | 执行配置、`partition_column` | 无分片却多 reader 重复读取 |
| 写入失败 | 执行详情、日志中心、Doris load error | 字段类型不兼容、分区不存在、过滤比例超限 |
| 同步成功但校验失败 | 数据校验页 | 目标表有旧数据、过滤条件不一致、增量窗口漏数 |

## 2. 查看执行批次

进入「任务详情 → 执行历史」。

重点看：

- 本次 `executionId`；
- 开始时间、结束时间；
- `read_rows`、`write_rows`、`failed_rows`；
- SeaTunnel `jobId`；
- 错误摘要。

如果错误摘要很短，再去「日志中心」按任务名、`executionId` 或 `jobId` 搜索。

## 3. 判断是否能重跑

| 写入模式 | 是否可以直接重跑 | 说明 |
| --- | --- | --- |
| TRUNCATE | 通过重采/共享目标表门禁后才可以 | 会清空目标物理表 |
| UPSERT | 通常可以 | 相同 key 会覆盖 |
| APPEND | 不可盲目重跑 | 非幂等，可能重复插入 |

如果远端终态不明确，先使用执行 reconcile/探测确认 SeaTunnel 结果。APPEND 任务重跑前必须确认目标表是否已有部分写入，并制定精确清理或去重方案。

## 4. 读数异常放大的排查

重点检查：

```text
partition_column
partition_num
env.parallelism
source.parallelism
```

规则：

- 没有 `partition_column` 时，Reader 实际并发必须是 1。
- 有 `splitPk` 或 ID_RANGE 增量字段时，才允许 Reader 并发大于 1。
- 如果源端 200 万行却读到 800 万行，通常是无分片并发重复读取。

## 5. 写入 Doris 失败的排查

当前没有独立脏数据页面，优先看执行详情、日志中心和 Doris load error。

常见原因：

- Doris 目标表字段类型不兼容；
- 目标分区不存在；
- UNIQUE KEY 列配置不符合 Doris 约束；
- 源端字符串超过 Doris 字段长度；
- 时间格式无法解析；
- `max_filter_ratio` 超限。

处理建议：

1. 先修目标表结构或字段映射；
2. 再小范围重跑；
3. 确认 `failed_rows=0` 后再恢复调度。

## 6. 校验失败的排查

| 校验失败类型 | 排查方向 |
| --- | --- |
| ROW_COUNT 不一致 | 源端 WHERE、目标端范围、软删除过滤是否一致 |
| CHECKSUM 不一致 | Upsert key 是否正确、字段映射是否一致、时间/数字精度是否一致 |
| 目标多数据 | 是否重复 APPEND、旧数据未清理、删除链路未启用 |
| 目标少数据 | 源端窗口漏数、Doris 写入失败、分区缺失 |

建议先查看校验报告，再决定是否触发修复。不要在原因不明时直接自动修复大批量数据。

## 7. 恢复运行

恢复前确认：

```text
[ ] 源端 SQL 能返回预期数据
[ ] 目标表结构和分区正常
[ ] 本次失败没有产生不可接受的重复数据
[ ] 校验配置与同步范围一致
[ ] 定时调度不会立刻再次触发同一错误
```

确认后再手动运行一次。手动运行成功并校验通过后，再恢复调度。
