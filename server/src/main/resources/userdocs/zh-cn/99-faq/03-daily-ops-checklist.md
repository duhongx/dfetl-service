# 日常运维检查清单

> 文档最近代码对齐：2026-07-24。

本文面向日常值守人员，用来快速判断 dfetl 是否健康。

## 每日检查

| 检查项 | 正常标准 | 异常处理 |
| --- | --- | --- |
| 任务监控 | 最近运行大多为 SUCCESS | 进入失败任务详情查看执行日志 |
| 待处理校验 | 无长期未处理 DIFF | 按校验报告定位原因 |
| 脏数据 | 无新增或数量很少 | 查看 Doris load error |
| 调度状态 | 关键任务 ENABLED | 被停用任务需确认原因 |
| 水位线 | 随任务成功持续推进 | 长时间不动需查是否失败或无新增 |

## 每周检查

- 抽查核心业务表的 CHECKSUM 校验结果；
- 检查 Doris 目标表分区是否覆盖未来窗口；
- 检查失败任务是否反复出现在同一张表；
- 检查源端视图是否发生字段新增、删除或类型变化；
- 检查日志中心是否出现大量连接失败或超时。

## 发布新任务前

```text
[ ] 源端连接测试通过
[ ] 目标 Doris 连接测试通过
[ ] 源端字段无大小写冲突
[ ] Upsert 匹配键已确认
[ ] 增量字段可靠
[ ] 无分片任务 Reader 实际并发为 1
[ ] 校验方式符合数据重要程度
[ ] 首次运行使用手动触发
```

## 修改已有任务前

修改前先确认：

- 是否会影响目标表结构；
- 是否会改变 Upsert key；
- 是否会改变增量字段或水位线；
- 是否会改变过滤条件；
- 是否需要暂停调度。

如果改动了增量字段、过滤条件或目标表名，建议先保存为草稿或在低峰期手动验证。

## 任务失败后的值守动作

1. 记录任务名、执行批次、失败时间。
2. 查看错误摘要，判断是提交失败、读取失败、写入失败还是校验失败。
3. 如果是 Doris 写入失败，先看脏数据和 load error。
4. 如果是读数异常，检查实际执行预览和 SeaTunnel Job。
5. 如果是校验失败，不要直接自动修复大批量数据。
6. 处理后手动重跑一次，成功后再恢复调度。

## 需要升级给开发处理的情况

| 情况 | 说明 |
| --- | --- |
| 同一任务连续失败超过 3 次 | 可能是配置或代码逻辑问题 |
| 源端读数与预期相差数倍 | 可能涉及分片、过滤条件或视图逻辑 |
| 校验反复 DIFF 但源端无变化 | 可能是字段类型、精度或目标范围问题 |
| Doris load error 不可解释 | 需要结合 Doris FE/BE 日志 |
| 水位线异常推进 | 需要立即暂停任务并排查 |
