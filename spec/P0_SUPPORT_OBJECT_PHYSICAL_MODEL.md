## 1. 总体原则

1. 支撑对象统一位于新 PostgreSQL 数据库的 `df_etl` Schema。
2. 用户、角色、权限、客户端、规则和配置是可变资源，使用 `revision bigint` 乐观锁。
3. 审计、请求日志、投递尝试、导出任务和幂等事实为追加式运行历史，不允许业务级联删除。
4. 密码和 Client Secret 只保存单向 Hash；数据库连接、Webhook、对象存储等可回读 Secret 保存带版本的 AES-256-GCM 密文。
5. 数据库不保存主密钥。主密钥由环境 Secret、KMS 或等价外部密钥源提供。
6. 前端权限控制只改善交互；服务端每个接口必须独立认证、鉴权和审计。
7. RabbitMQ 是 P0 唯一业务消息通道；Redis Stream 相关配置、依赖和表不进入目标模型。
8. Quartz 是调度投影，不是 Task 业务事实来源。`sync_task.schedule_enabled` 和当前 Task Version 才是业务事实。
9. 所有 C2/S1 操作必须携带 Reason，审计成功、失败和拒绝结果。
10. 除明确说明外，主键使用 `bigint GENERATED BY DEFAULT AS IDENTITY`，跨系统命令、会话和导出使用 `uuid`。

## 2. 账号、角色和权限

### 2.1 `user_account`

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| `id` | bigint identity | PK |
| `username` | varchar(100) | 原始显示值 |
| `username_normalized` | varchar(100) | 应用统一转小写；UNIQUE |
| `display_name` | varchar(200) | NOT NULL |
| `password_hash` | varchar(255) | Spring Security 编码前缀 Hash，例如 `{bcrypt}` |
| `status` | varchar(20) | `ENABLED/DISABLED/LOCKED` |
| `failed_login_count` | integer | 非负 |
| `locked_until` | timestamptz | 可空 |
| `token_version` | integer | 密码重置、账号停用时递增 |
| `password_changed_at` | timestamptz | NOT NULL |
| `last_login_at` | timestamptz | 可空 |

| `created_at/by` | timestamptz/bigint | 创建事实 |
| `updated_at/by` | timestamptz/bigint | 修改事实 |

约束和索引：

- `UNIQUE(username_normalized)`；
- `CHECK(failed_login_count >= 0)`；
- `CHECK(status IN ('ENABLED','DISABLED','LOCKED'))`；
- 索引 `(status, username_normalized)`、`(last_login_at desc)`。

P0 不允许删除账号，只允许停用。禁止停用当前自己和最后一个仍拥有系统管理权限的有效账号；该规则在同一事务中对相关账号/角色关系 `SELECT FOR UPDATE` 后校验。

## 3. 操作审计

### 3.1 `operation_audit`

追加式安全事实：

```text
id bigint identity
occurred_at timestamptz
request_id varchar(64)
trace_id varchar(64)
command_id uuid
idempotency_key_hash varchar(64)
actor_type = USER | EXTERNAL_CLIENT | SCHEDULER | SYSTEM
actor_id varchar(128)
actor_name_snapshot varchar(200)
source = WEB | EXTERNAL_API | SCHEDULER | SYSTEM
permission_code varchar(128)
operation_code varchar(128)
target_type varchar(64)
target_id varchar(128)
target_name_snapshot varchar(300)
institution_scope jsonb
result = SUCCESS | FAILED | DENIED
http_status integer
reason text
before_snapshot jsonb
after_snapshot jsonb
detail jsonb
error_code varchar(128)
client_ip inet
user_agent varchar(500)
```

安全边界：

- Secret、密码、Authorization、数据库完整凭据、预检敏感原值不得进入任何 JSON 或文本字段；
- Snapshot 通过字段白名单生成，不对任意 DTO 自动序列化；
- 应用数据库角色只拥有 INSERT/SELECT，不拥有 UPDATE/DELETE；
- P0 不自动删除审计，后续归档策略单独 Review。

索引：

```text
(occurred_at desc)
(actor_type, actor_id, occurred_at desc)
(target_type, target_id, occurred_at desc)
(request_id)
(operation_code, occurred_at desc)
(result, occurred_at desc)
```

按月 RANGE 分区，避免长期单表膨胀；分区创建由受控维护任务完成。

## 7. Quartz JDBCJobStore

### 7.1 使用官方表

使用当前依赖解析出的 Quartz 版本所附 PostgreSQL 官方脚本，表前缀固定 `qrtz_`：

```text
qrtz_job_details
qrtz_triggers
qrtz_simple_triggers
qrtz_cron_triggers
qrtz_simprop_triggers
qrtz_blob_triggers
qrtz_calendars
qrtz_paused_trigger_grps
qrtz_fired_triggers
qrtz_scheduler_state
qrtz_locks
```

不自创简化版 Quartz 表，不从老系统迁移 Scheduler State、Fired Trigger 或 Lock。

### 7.2 初始化规则

```yaml
spring:
  quartz:
    job-store-type: jdbc
    jdbc:
      initialize-schema: never
```

Quartz 表由目标模型签字后的 Flyway V1 创建。禁止使用 `initialize-schema=always`，因为 Spring Boot 标准初始化脚本可能在启动时删除已有 Quartz 表和 Trigger。

### 7.3 集群参数

目标配置：

```text
org.quartz.scheduler.instanceName = DfetlScheduler
org.quartz.scheduler.instanceId = AUTO
org.quartz.jobStore.isClustered = true
org.quartz.jobStore.driverDelegateClass = PostgreSQLDelegate
org.quartz.jobStore.tablePrefix = df_etl.qrtz_
org.quartz.jobStore.clusterCheckinInterval = 20000
org.quartz.jobStore.misfireThreshold = 60000
```

线程数由全局参数和节点容量配置，不写入数据库业务表。

### 7.4 业务事实边界

- Quartz JobDataMap 只保存稳定 `task_id`，不保存完整连接、密码、字段合同或可变 DTO；
- Trigger 触发时在 PostgreSQL 事务中锁定 Task，读取 `current_version_id`，创建固定 Task Version 的 Execution；
- 新 Task Version 发布后由投影服务更新 Quartz Trigger；
- `schedule_enabled=false` 时应暂停/删除派生 Trigger，但人工运行仍可用；
- 恢复任务以 `sync_task` 为事实重建缺失/多余 Trigger；Quartz 不反向覆盖业务配置。

## 8. 通用 Revision、删除和并发规则

1. 可编辑资源必须有 `revision bigint NOT NULL DEFAULT 0`。
2. 更新使用 `WHERE id=? AND revision=?`，成功后 `revision=revision+1`；0 行返回 412。
3. 关系表的更新在父对象 Revision 事务中完成。
4. 版本、运行、审计、投递尝试和请求日志不使用软删除，保持不可变历史。
5. Secret 重置、角色分配、危险设置和删除操作必须 C2/S1 确认并记录 Reason。
6. 活动任务/Run 互斥继续由业务表部分唯一索引保证，`operation_lock` 用于跨 PostgreSQL/Doris/RabbitMQ 的长操作租约，二者不能互相替代。

| 表 | 关键索引/清理 |

## 10. 当前代码的迁移处置

### 10.1 可保留的语义

- `AppUser` 的用户名唯一、密码 Hash、启停和 Token Version；
- `AuditLog` 的追加式思想；
- `AlertChannel/AlertRule` 的基本职责；
- Quartz JDBCJobStore、独立连接池和 `initialize-schema=never`；
- External API 的 Client 身份和机构授权思想。

### 10.2 不直接复用的旧物理结构

- `AppUser.role` 单字符串必须替换为角色/权限多对多；
- 旧 `AuditLog` 缺少 Request、权限、结果、失败、范围和不可变白名单 Snapshot，必须重建；
- 旧告警缺少 Event、Delivery 和 Attempt 分层；
- 旧 External Client Secret 若可解密或明文保存，必须替换为只显示一次的 Hash 模型；
- 当前配置中的 Redis Stream 默认传输必须删除，RabbitMQ 成为唯一 P0 通道；
- 现有表和运行数据不得 baseline 到新数据库。

## 11. 安全要求

1. 密码使用 Spring Security `DelegatingPasswordEncoder`，Hash 带算法前缀，允许后续透明升级。
2. Client Secret 使用抗暴力破解的单向 Hash；原值不持久化。
3. 可回读基础设施 Secret 使用带随机 Nonce 的 AES-256-GCM；每条记录保存 `crypto_key_id` 以支持轮换。
4. JWT/加密主密钥、数据库密码和对象存储 Secret 不写入仓库、Flyway 或初始化数据。
5. 错误响应不得区分“客户端不存在”和“Secret 错误”等可枚举信息。
6. 审计、日志和外部请求日志使用统一脱敏器。
7. 数据库应用账号对 Audit 和历史表不得拥有 UPDATE/DELETE。

## 12. 验收场景

1. 一个账号可关联多个角色，一个角色可包含多个权限。
2. 无页面权限时返回 403，前端隐藏菜单不能替代服务端拒绝。
3. 最后管理员和当前自己不能被停用。
4. 密码重置使所有既有 Session 失效，密码不进入审计。
5. 审计同时记录成功、失败和权限拒绝，且不含 Secret 或敏感原值。
6. 同 Revision 并发更新只有一个成功，另一个返回 412。
7. 同 Idempotency Key + 相同请求返回同一资源；不同请求返回 409。
8. 告警事件对每个通道只有一个逻辑 Delivery，重试形成独立 Attempt。
9. External Client Secret 创建/重置仅显示一次，数据库中无法恢复原值。
10. SELECTED Client 只能访问授权机构；ALL Client 不创建冗余机构关系。
11. Quartz 多实例只有一个节点获得同一 Trigger，Execution 仍固定 Task Version。
12. 应用重启不会重建或删除 Quartz 表；缺失 Trigger 可从 Task 事实恢复。
13. Redis 不参与 P0 业务消息发布。

## 13. 官方技术依据

- Spring Boot Quartz：JDBC JobStore 需显式启用；标准初始化脚本可能删除现有表，因此生产使用 `initialize-schema=never` 并由 Flyway 管理。
- Quartz 官方 PostgreSQL Schema：使用官方 `tables_postgres.sql` 对应表和索引。
- Spring Security：密码只保存编码 Hash，服务端独立鉴权。

具体 Flyway SQL、JPA Entity 和 Controller 在目标模型签字并取得实施授权后生成。
