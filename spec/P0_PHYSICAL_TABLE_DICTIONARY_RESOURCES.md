## 1. 本批次范围和结论

本批次完成以下目标对象的物理字段、约束、外键、删除行为和查询索引设计：

```text
institution
business_system_instance
source_datasource
target_datasource
target_datasource_fe_endpoint
business_system_instance_institution
business_system_instance_datasource
```

固定结论：

1. 机构是扁平集合，不保留 `parent_id`、机构树和层级继承。
2. 业务系统实例与机构、源数据源分别是显式多对多关系。
3. 实例—数据源关系是纯关联，不保存用途、优先级、主备或自动选择规则。
4. 源数据源不再直接保存 `institution_id`。
5. 源数据源支持 `HOST_PORT` 和完整 `JDBC_URL` 两种互斥连接方式，账号和密码不得嵌入 JDBC URL。
6. Doris 目标数据源表示一个逻辑部署；一个部署通过子表维护一个或多个 FE 端点，不管理 BE。
7. 删除旧目标数据源的 `environment` 字段；产品不再展示环境标识。
8. 用户启停状态与连接测试结果分开保存，不再用 `NORMAL/ERROR/TESTING` 混合表达配置状态和瞬时网络结果。
9. 第一阶段 Reader 固定单并发，因此源数据源不保存 `read_concurrency`。
10. 机构、实例和数据源均以稳定 `code` 作为业务身份；名称用于展示，可以重复。

## 2. 共同物理规则

### 2.1 稳定编码

- `institution.code`、`business_system_instance.code`、`source_datasource.code`、`target_datasource.code` 保存去除首尾空格后的原值。
- 编码按 `lower(code)` 建立唯一索引，避免仅大小写不同的重复身份。
- 编码创建后不可通过普通更新接口修改。
- 源视图中的医疗机构代码必须与 `institution.code` 保存值完全一致；查询和源端过滤使用保存的原始编码，不自动转换大小写。
- 名称不承担身份和外键职责，不建立名称唯一约束。

### 2.2 启停状态

机构、业务系统实例、源数据源和目标数据源统一使用：

```text
ENABLED
DISABLED
```

固定语义：

- `DISABLED` 记录继续保留，历史版本和运行记录仍可解释。
- 停用对象不再出现在新建链路和新建任务的默认可选范围。
- 任务执行前重新检查任务机构、业务系统实例、源数据源和目标数据源均为 `ENABLED`；任一停用时本次不创建执行并返回明确原因。
- 连接测试允许管理员对停用数据源执行，不会因为测试成功自动启用。
- 连接测试失败只更新测试结果，不自动把业务状态改为 `DISABLED`。

### 2.3 连接测试状态

源数据源和目标数据源的持久化测试结果只表示最近一次人工或受控测试：

```text
UNTESTED
SUCCESS
FAILED
```

目标 Doris 聚合多个 FE 端点时，目标数据源本身额外允许：

```text
PARTIAL
```

`PARTIAL` 表示至少一个启用端点成功、至少一个启用端点失败。瞬时的“测试中”只存在于接口响应和前端状态，不持久化为数据库状态。

### 2.4 物理删除边界

- 配置对象仍提供“删除”能力，但只允许删除从未被后续配置或历史对象引用的记录。
- 已经参与采集链路、链路版本、任务或运行历史的机构、实例和数据源不能物理删除，只能停用。
- 删除前必须返回引用数量和阻断对象，不允许依赖数据库异常向用户展示模糊错误。
- 所有删除、启停、凭据修改、关系调整和连接测试均按已确认规则记录成功或失败审计；密码、完整 JDBC URL 中的敏感参数和连接异常中的凭据不得进入审计摘要。

## 3. `institution`

职责：医共体内医疗机构主数据。机构为扁平集合，没有父子关系。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |

| `code` | `varchar(64)` | NOT NULL | 医疗机构业务编码；源视图必须使用相同原值 |
| `name` | `varchar(200)` | NOT NULL | 机构全称 |
| `short_name` | `varchar(100)` | NULL | 机构简称 |
| `institution_type` | `varchar(32)` | NULL | `HOSPITAL/CLINIC/CENTER/COMMUNITY` |
| `institution_level` | `varchar(16)` | NULL | `TIER_1/TIER_2/TIER_3` |
| `region_code` | `varchar(20)` | NULL | 行政区划代码 |
| `status` | `varchar(16)` | NOT NULL DEFAULT `'ENABLED'` | 用户控制的启停状态 |
| `description` | `text` | NULL | 说明 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

明确不建立：

```text
parent_id
path
level_no
ancestor_ids
organization_tree
```

### 3.2 约束

```text
CHECK (btrim(code) <> '')
CHECK (btrim(name) <> '')
CHECK (revision >= 0)
CHECK (status IN ('ENABLED','DISABLED'))
CHECK (institution_type IS NULL OR institution_type IN ('HOSPITAL','CLINIC','CENTER','COMMUNITY'))
CHECK (institution_level IS NULL OR institution_level IN ('TIER_1','TIER_2','TIER_3'))
```

应用规则：

- `code` 创建后不可修改。
- 保存前统一执行 `btrim`，但不改变内部大小写。
- 停用机构不会删除实例覆盖关系、链路、任务或历史。
- 已停用机构对应任务不能自动或人工运行，恢复机构后任务仍按原任务配置使用。

### 3.3 唯一与索引

```text
UNIQUE INDEX uk_institution_code_ci
    ON institution (lower(code))

INDEX idx_institution_status_id
    ON institution (status, id)

INDEX idx_institution_type_status_id
    ON institution (institution_type, status, id)

INDEX idx_institution_region_status_id
    ON institution (region_code, status, id)

INDEX idx_institution_name_ci
    ON institution (lower(name))
```

不建立机构层级索引。

### 3.4 删除行为

- `business_system_instance_institution.institution_id` 使用 `ON DELETE RESTRICT`。
- `collection_route_institution`、`sync_task`、预检/校验/执行历史等后续外键均使用 `RESTRICT` 或通过不可变快照保留。
- 只有不存在任何关联或历史引用时才允许物理删除。
- 已有引用时接口提示先停用，不通过级联删除清理关系。

## 4. `business_system_instance`

职责：表示医共体内真实部署的一套 HIS、LIS、PACS 或其他业务系统。厂商和系统类型只用于描述、筛选和统计，不用于自动合并实例。

### 4.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 内部主键 |
| `code` | `varchar(100)` | NOT NULL | 稳定实例编码，创建后不可修改 |
| `name` | `varchar(200)` | NOT NULL | 实例名称 |
| `system_type` | `varchar(50)` | NOT NULL | HIS/LIS/PACS 等应用注册或页面受控值；不把当前列表固化成数据库枚举 |
| `vendor` | `varchar(200)` | NULL | 厂商 |
| `product_version` | `varchar(100)` | NULL | 产品或部署版本 |
| `status` | `varchar(16)` | NOT NULL DEFAULT `'ENABLED'` | `ENABLED/DISABLED` |
| `description` | `text` | NULL | 说明 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 4.2 约束

```text
CHECK (btrim(code) <> '')
CHECK (btrim(name) <> '')
CHECK (btrim(system_type) <> '')
CHECK (status IN ('ENABLED','DISABLED'))
CHECK (revision >= 0)
```

`system_type` 不使用数据库 `CHECK` 限定 HIS/LIS/PACS 的固定集合，避免增加新的业务系统类型时必须先修改数据库结构；应用层设置注册表负责页面选项和格式校验。

### 4.3 唯一与索引

```text
UNIQUE INDEX uk_business_system_instance_code_ci
    ON business_system_instance (lower(code))

INDEX idx_business_system_instance_status_type
    ON business_system_instance (status, system_type, id)

INDEX idx_business_system_instance_vendor
    ON business_system_instance (vendor, id)

INDEX idx_business_system_instance_name_ci
    ON business_system_instance (lower(name))
```

### 4.4 生命周期

- 实例可以先创建，再配置覆盖机构和源数据源。
- 建立采集链路前，实例至少关联一家机构和一个源数据源。
- 实例停用后，已有关系和历史保留；新建链路不可选，引用该实例的任务执行前检查失败。
- 只有不存在采集链路及历史版本引用时才允许物理删除。
- 删除实例时可以级联删除其两张纯关联表中的关系；如果存在链路外键，删除由 `RESTRICT` 阻止。

### 5.2 连接模式约束

```text
CHECK (db_type IN ('MYSQL','POSTGRESQL','ORACLE','SQLSERVER','DORIS'))
CHECK (connection_mode IN ('HOST_PORT','JDBC_URL'))
CHECK (status IN ('ENABLED','DISABLED'))
CHECK (last_test_status IN ('UNTESTED','SUCCESS','FAILED'))
CHECK (port IS NULL OR port BETWEEN 1 AND 65535)
CHECK (query_timeout_seconds BETWEEN 1 AND 3600)
CHECK (connect_timeout_seconds BETWEEN 1 AND 300)
CHECK (socket_timeout_seconds BETWEEN 1 AND 3600)
CHECK (pool_max_size BETWEEN 1 AND 100)
CHECK (revision >= 0)
```

互斥连接参数：

```text
HOST_PORT:
    host IS NOT NULL AND btrim(host) <> ''
    port IS NOT NULL
    database_name IS NOT NULL AND btrim(database_name) <> ''
    jdbc_url IS NULL

JDBC_URL:
    jdbc_url IS NOT NULL AND btrim(jdbc_url) <> ''
    lower(jdbc_url) LIKE 'jdbc:%'
    host IS NULL
    port IS NULL
    database_name IS NULL
```

应用层额外校验：

- JDBC URL 中禁止出现数据库密码和明文凭据；账号和密码必须使用独立字段。
- `db_type` 必须与 URL 协议匹配。
- 更新时掩码密码表示保持原密文，不能把掩码再次加密。
- 连接参数或凭据变化后增加 `revision`，关闭旧连接池并使用新配置创建连接。
- `read_only` 不替代数据库权限；平台仍只生成只读源查询。

### 5.3 唯一与索引

```text
UNIQUE INDEX uk_source_datasource_code_ci
    ON source_datasource (lower(code))

INDEX idx_source_datasource_status_type
    ON source_datasource (status, db_type, id)

INDEX idx_source_datasource_name_ci
    ON source_datasource (lower(name))

INDEX idx_source_datasource_last_test
    ON source_datasource (last_test_status, last_tested_at DESC)
```

不建立 `institution_id` 查询索引。按机构查询数据源时通过：

```text
institution
→ business_system_instance_institution
→ business_system_instance
→ business_system_instance_datasource
→ source_datasource
```

并对结果按 `source_datasource.id` 去重。

### 5.4 删除行为

- `business_system_instance_datasource.source_datasource_id` 使用 `ON DELETE RESTRICT`。
- `collection_route` 和不可变链路版本对源数据源使用 `RESTRICT`。
- 只有解除所有实例关系且不存在链路/历史引用时才允许物理删除。
- 已经投入使用的数据源通过 `DISABLED` 撤出，不级联删除链路或任务。

```text
CHECK (btrim(code) <> '')

CHECK (btrim(username) <> '')

CHECK (status IN ('ENABLED','DISABLED'))
```

应用层规则：

- `default_write_database` 为空时解析为 `database_name`，执行快照保存最终生效值。
- 修改凭据、端点、数据库或写入参数时增加 `revision` 并关闭旧客户端连接。
- 目标数据源停用后不影响历史查询，但引用它的新执行在运行前被拒绝。
- 目标数据源不自动创建或修改业务表；建表/重建必须由用户显式发起。

```text
UNIQUE INDEX uk_target_datasource_code_ci
```

### 6.4 删除行为

- `target_datasource_fe_endpoint` 对目标数据源使用 `ON DELETE CASCADE`。
- `collection_route`、链路版本、删除快照运行和其他历史对象对目标数据源使用 `RESTRICT`。
- 只有不存在任何链路和历史引用时才允许删除；已经使用过的目标数据源通过停用撤出。

## 7. `target_datasource_fe_endpoint`

职责：保存一个 Doris 逻辑部署中的 FE 连接端点。共享目标数据源凭据，不保存 BE。

### 7.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 端点主键 |
| `target_datasource_id` | `bigint` | NOT NULL | FK `target_datasource(id)`，`ON DELETE CASCADE` |
| `ordinal_no` | `smallint` | NOT NULL | 确定性尝试顺序，从 1 开始 |
| `host` | `varchar(255)` | NOT NULL | FE 主机名或 IP |
| `query_port` | `integer` | NOT NULL DEFAULT `9030` | MySQL/JDBC 查询端口 |
| `http_port` | `integer` | NOT NULL DEFAULT `8030` | FE HTTP API 端口 |
| `stream_load_port` | `integer` | NOT NULL DEFAULT `8040` | 页面和现有实现保留的 Stream Load 端口配置 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否参与连接选择和测试 |
| `last_test_status` | `varchar(16)` | NOT NULL DEFAULT `'UNTESTED'` | `UNTESTED/SUCCESS/FAILED` |
| `last_tested_at` | `timestamptz` | NULL | 最近端点测试时间 |
| `last_test_error` | `varchar(1000)` | NULL | 脱敏端点错误摘要 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 7.2 约束和索引

```text
CHECK (ordinal_no > 0)
CHECK (query_port BETWEEN 1 AND 65535)
CHECK (http_port BETWEEN 1 AND 65535)
CHECK (stream_load_port BETWEEN 1 AND 65535)
CHECK (btrim(host) <> '')
CHECK (last_test_status IN ('UNTESTED','SUCCESS','FAILED'))

UNIQUE (target_datasource_id, ordinal_no)
UNIQUE INDEX uk_target_fe_endpoint
    ON target_datasource_fe_endpoint
       (target_datasource_id, lower(host), query_port, http_port, stream_load_port)

INDEX idx_target_fe_enabled_order
    ON target_datasource_fe_endpoint
       (target_datasource_id, enabled, ordinal_no)
```

### 7.3 跨行规则

在保存目标数据源和端点集合的同一事务中校验：

- 每个目标数据源至少存在一个启用端点。
- `STANDALONE` 必须恰好一个启用端点。
- `CLUSTER` 必须至少两个启用端点。
- `ordinal_no` 连续不是数据库硬约束，但服务保存时重新按页面顺序规范化为 `1..N`。
- 连接选择按 `ordinal_no` 尝试启用端点，不根据历史测试状态静默永久切换主端点。
- 连接测试逐个测试启用端点，并据此更新端点结果和目标数据源聚合结果。

## 8. `business_system_instance_institution`

职责：业务系统实例与覆盖机构的显式多对多关系。

### 8.1 字段和约束

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `instance_id` | `bigint` | PK/FK | FK `business_system_instance(id)`，`ON DELETE CASCADE` |
| `institution_id` | `bigint` | PK/FK | FK `institution(id)`，`ON DELETE RESTRICT` |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 关联时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

主键：

```text
PRIMARY KEY (instance_id, institution_id)
```

反向索引：

```text
INDEX idx_instance_institution_reverse
    ON business_system_instance_institution (institution_id, instance_id)
```

### 8.2 语义

- 不保存 `coverage_mode=ALL`；“覆盖全部机构”由页面一次选择当前全部机构并写入显式关系表达。
- 后续新增机构不会被系统静默加入已有实例，管理员按真实部署关系显式维护。
- 不保存厂商机构代码或源系统机构代码；源视图直接使用 `institution.code`。
- 关系移除前检查采集链路覆盖和任务引用。后续 `collection_route_institution` 通过 `(instance_id, institution_id)` 复合外键确保机构确属该实例覆盖范围。

## 10. 跨对象事务和引用约束

### 10.1 创建采集链路前置条件

后续链路服务必须在同一事务中确认：

```text
business_system_instance.status = ENABLED
source_datasource.status = ENABLED
target_datasource.status = ENABLED
(instance_id, source_datasource_id) 关系存在
每个链路覆盖机构均满足 (instance_id, institution_id) 关系存在
```

数据库层通过两张多对多表的主键提供复合外键目标，避免只依赖应用层集合比对。

### 10.2 执行前置条件

任务执行开始前重新读取当前对象状态：

```text
任务机构 ENABLED
任务版本绑定的业务系统实例 ENABLED
源数据源 ENABLED
目标数据源 ENABLED
目标数据源至少一个启用 FE 端点
```

状态不满足时不创建 `sync_execution`；失败原因写业务日志，人工请求同时记录失败审计。已经运行中的执行不因配置在中途被停用而被系统强制取消，继续使用启动时快照和已获取连接，维护人员需要停止时另行取消执行。

### 10.3 关系更新

- 更新实例覆盖机构或数据源集合时使用集合差异，不先全删再全插，避免短暂破坏复合外键。
- 移除被链路引用的关系时返回引用对象，不通过级联删除修改链路。
- 关系修改成功和失败都进入 `audit_log`，摘要只保存新增/移除 ID 和数量，不保存数据库凭据。

## 11. 高频查询与 Repository 方向

### 11.1 机构可用数据源

按机构查询可用源数据源：

```text
business_system_instance_institution
JOIN business_system_instance
JOIN business_system_instance_datasource
JOIN source_datasource
WHERE institution_id = ?
  AND instance.status = 'ENABLED'
  AND source.status = 'ENABLED'
```

结果按 `source_datasource.id` 去重。旧的 `SourceDataSourceRepository.findByInstitutionId/countByInstitutionId` 删除。

### 11.2 实例详情

实例详情分三次小查询或使用受控投影查询：

- 实例基础信息；
- 覆盖机构列表，按机构编码排序；
- 关联数据源列表，按数据源名称和 ID 排序。

不使用一个包含机构 × 数据源笛卡尔积的巨大 Join 直接映射实体集合。

### 11.3 列表查询

- 机构按编码、名称、类型、等级、区域和状态分页。
- 实例按编码、名称、系统类型、厂商和状态分页。
- 源数据源按编码、名称、数据库类型、状态和最近测试结果分页。
- 目标数据源按编码、名称、部署模式、状态和最近测试结果分页。
- 所有统计使用数据库聚合，不读取全表后在 Java 内存计算。

### 11.4 引用检查

删除或移除关系前使用显式计数/存在性查询，至少覆盖：

```text
collection_route
collection_route_version
collection_route_institution
sync_task
sync_task_version
precheck_run
sync_execution
validation_run
delete_snapshot_run
```

业务接口返回可理解的引用类型和数量；数据库 `RESTRICT` 是最终并发保护。

## 12. 旧对象到目标对象的修正

| 老系统字段/行为 | 目标处理 |

| `institution.parent_id` 及树查询 | 删除；机构为扁平集合 |

## 13. 本批次验收结论
