> 本次范围：全局约定、P0 支撑对象、删除识别控制对象、Quartz 标准表和 Doris 删除快照技术表

## 1. 全局物理约定

### 1.1 PostgreSQL Schema 和命名

- 所有新业务表、Quartz 表和 Flyway history 位于新数据库的 `df_etl` Schema。
- 应用连接显式设置 `search_path=df_etl,public`，Quartz 同时显式设置 `tablePrefix=df_etl.qrtz_`，不依赖默认 Schema 推断。
- 表名、列名、索引名和约束名统一使用小写 `snake_case`。
- 物理表名不复用已经废止且业务语义不同的老表名。

### 1.2 PostgreSQL 通用类型

| 用途 | 约定 |
| --- | --- |
| 元数据主键 | `bigint GENERATED BY DEFAULT AS IDENTITY` |
| 跨系统运行/事件标识 | `uuid`，由应用生成；数据库唯一约束 |
| 时间 | `timestamptz`，数据库默认 `CURRENT_TIMESTAMP` |
| 布尔值 | `boolean`，不得使用字符串或整数代替 |
| 计数 | `bigint`；小型配置数量可使用 `integer` |
| 金额/比例/阈值 | 按业务精度使用 `numeric(p,s)`，不使用浮点数保存精确值 |
| 状态和模式 | 受控 `varchar` + `CHECK`，不创建 PostgreSQL ENUM 类型 |
| 可扩展快照 | `jsonb`；必须检查为 object/array，不把高频查询字段藏入 JSON |
| IP | `inet` |
| Hash | SHA-256 使用 `char(64)` 小写十六进制，并检查格式 |
| 加密密文 | `text`；列名以 `_enc` 结尾，接口只返回掩码 |

### 1.3 通用审计列

可变配置表原则上包含：

```text
created_at       timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP
created_by       bigint NULL
updated_at       timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP
updated_by       bigint NULL
```

- `created_by/updated_by` 引用 `app_user(id)`，使用 `ON DELETE SET NULL`；本地账号目前不物理删除，但删除行为仍显式声明。
- 对外 client、调度器和系统后台任务造成的业务变化，通过 `audit_log` 保存实际操作者，不强行写入 `created_by/updated_by`。
- `updated_at` 由应用在成功更新时写入，不创建通用数据库 Trigger，避免隐藏写入行为。
- 不可变运行表通常只有创建、开始、完成时间，不使用通用 `updated_by`。

### 1.4 状态、窗口和计数约束

- 所有计数列使用 `CHECK (value >= 0)`。
- 时间窗口同时非空时使用 `CHECK (lower_bound < upper_bound)`。
- 完成时间存在时不得早于开始时间。
- `jsonb` 对象列使用 `CHECK (jsonb_typeof(column) = 'object')`；数组列使用 `array` 检查。
- 受控状态扩展必须通过新的不可变 Flyway 版本修改 `CHECK`，不得静默保存未知值。

### 1.5 外键删除原则

| 对象类型 | 默认删除行为 |
| --- | --- |
| 配置关系子表 | 父配置物理删除时可 `CASCADE`，前提是历史记录不依赖该子表 |
| 运行、版本、审计、消息和校验历史 | 对父对象使用 `RESTRICT` 或保留快照；不得级联删除历史 |
| 可删除配置在历史中的引用 | 历史表外键可 `SET NULL`，同时保存名称/编码快照 |
| 任务和链路 | 业务上逻辑删除，历史外键使用 `RESTRICT` |

## 2. 本地账号和操作审计

### 2.1 `app_user`

职责：本地管理员登录身份。允许一个或多个同权限账号；不保存角色，不物理删除。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 账号内部主键 |
| `username` | `varchar(100)` | NOT NULL | 登录名；保存去除首尾空格后的原值 |
| `password_hash` | `varchar(255)` | NOT NULL | BCrypt/Argon2 等单向 Hash；禁止记录明文 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 停用后拒绝登录和 Token 刷新 |
| `refresh_token_version` | `bigint` | NOT NULL DEFAULT `0` | 停用、重置密码、退出全部会话时递增 |
| `last_login_at` | `timestamptz` | NULL | 最近一次成功登录时间 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近账号信息变更时间 |

约束：

```text
CHECK (btrim(username) <> '')
CHECK (refresh_token_version >= 0)
```

唯一与索引：

```text
UNIQUE INDEX uk_app_user_username_ci ON app_user (lower(username))
INDEX idx_app_user_enabled ON app_user (enabled, id)
```

删除行为和事务规则：

- 不提供 `DELETE` 业务入口，不设置 `deleted_at`。
- 当前登录账号不能停用自己；最后一个启用账号不能被停用。这两项由事务内锁定启用账号集合后在服务层保证。
- Flyway V1 不插入固定账号和固定密码 Hash；首个管理员由部署启动引导或一次性初始化命令创建。

### 2.2 `audit_log`

职责：追加保存业务写操作的成功和失败事实；不承担认证安全日志和审批流。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 审计主键 |
| `occurred_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 操作完成或失败时间 |
| `actor_type` | `varchar(24)` | NOT NULL | `LOCAL_USER/EXTERNAL_CLIENT/SCHEDULER/SYSTEM` |
| `actor_user_id` | `bigint` | NULL | 本地用户；FK `app_user(id)`，`ON DELETE SET NULL` |
| `actor_client_id` | `bigint` | NULL | 外部 client；FK `external_api_client(id)`，`ON DELETE SET NULL` |
| `actor_name_snapshot` | `varchar(200)` | NOT NULL | 当时的用户名、client 名称或系统主体名称 |
| `source` | `varchar(24)` | NOT NULL | `WEB/EXTERNAL_API/SCHEDULER/SYSTEM` |
| `operation_code` | `varchar(100)` | NOT NULL | 受控领域操作编码 |
| `target_type` | `varchar(100)` | NOT NULL | 目标对象类型 |
| `target_id` | `varchar(128)` | NULL | 可容纳 bigint、UUID 或业务编码 |
| `target_name_snapshot` | `varchar(300)` | NULL | 目标名称/编码快照 |
| `result` | `varchar(16)` | NOT NULL | `SUCCESS/FAILED` |
| `request_id` | `varchar(128)` | NULL | HTTP 请求、外部幂等请求或后台关联标识 |
| `client_ip` | `inet` | NULL | Web/API 客户端 IP；系统任务为空 |
| `summary` | `jsonb` | NOT NULL DEFAULT `'{}'` | 小型脱敏参数和影响范围摘要 |
| `error_code` | `varchar(100)` | NULL | 失败业务错误码 |
| `error_message` | `varchar(1000)` | NULL | 脱敏错误摘要，不保存堆栈和敏感数据 |

约束：

```text
CHECK actor_type IN (LOCAL_USER, EXTERNAL_CLIENT, SCHEDULER, SYSTEM)
CHECK source IN (WEB, EXTERNAL_API, SCHEDULER, SYSTEM)
CHECK result IN (SUCCESS, FAILED)
CHECK jsonb_typeof(summary) = 'object'
CHECK LOCAL_USER 时 actor_user_id 非空且 actor_client_id 为空
CHECK EXTERNAL_CLIENT 时 actor_client_id 非空且 actor_user_id 为空
CHECK SCHEDULER/SYSTEM 时两个主体外键均为空
CHECK SUCCESS 时 error_code/error_message 均为空
```

索引：

```text
INDEX idx_audit_log_time ON audit_log (occurred_at DESC, id DESC)
INDEX idx_audit_log_actor ON audit_log (actor_type, actor_name_snapshot, occurred_at DESC)
INDEX idx_audit_log_operation ON audit_log (operation_code, occurred_at DESC)
INDEX idx_audit_log_target ON audit_log (target_type, target_id, occurred_at DESC)
INDEX idx_audit_log_result ON audit_log (result, occurred_at DESC)
INDEX idx_audit_log_request ON audit_log (request_id) WHERE request_id IS NOT NULL
```

边界：

- 表只插入，不提供普通修改和删除 API。
- 密码、密码 Hash、数据库密码、Webhook/外部 API secret、HMAC 签名和完整认证 Header 禁止进入任何字段。
- 登录失败、无效 Token 和 HMAC 验证失败写安全日志，不写 `audit_log`。

## 3. 系统设置

### 3.1 `system_setting`

职责：保存应用注册的少量系统设置。类型、默认值、是否敏感和范围由代码中的统一设置注册表定义。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `setting_key` | `varchar(200)` | PK | 稳定、大小写敏感的注册 key；建议统一小写点分命名 |
| `setting_value` | `text` | NULL | 普通值或加密密文；是否允许空由设置注册表判断 |
| `description` | `varchar(500)` | NOT NULL | 设置说明快照 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 首次写入时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

约束和索引：

```text
CHECK (btrim(setting_key) <> '')
CHECK (revision >= 0)
INDEX idx_system_setting_updated ON system_setting (updated_at DESC)
```

事务规则：

```sql
UPDATE system_setting
SET setting_value = ?, revision = revision + 1, updated_at = CURRENT_TIMESTAMP, updated_by = ?
WHERE setting_key = ? AND revision = ?;
```

- 更新 0 行表示版本冲突。
- 未注册 key 在服务层明确拒绝，不能通过通用 Map 自动插入。
- 规范库密码可保存密文并掩码返回；RabbitMQ、应用数据库、JWT 和加密主密钥等部署 Secret 不进入本表。

## 4. 告警配置和最小历史

### 4.1 `alert_channel`

职责：保存钉钉、企业微信 Webhook 渠道配置。允许在无规则引用时物理删除；历史投递通过快照解释。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 渠道 ID |
| `name` | `varchar(200)` | NOT NULL | 渠道名称 |
| `channel_type` | `varchar(24)` | NOT NULL | `DINGTALK/WECOM` |
| `webhook_url_enc` | `text` | NOT NULL | Webhook URL 密文；列表返回掩码 |
| `secret_enc` | `text` | NULL | 加签密钥密文 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否参与发送 |
| `message_format` | `varchar(16)` | NOT NULL DEFAULT `'TEXT'` | `TEXT/MARKDOWN` |
| `mentioned_mobiles` | `jsonb` | NOT NULL DEFAULT `'[]'` | 手机号字符串数组；最多 30 个由服务校验 |
| `at_all` | `boolean` | NOT NULL DEFAULT `false` | 是否 @所有人 |
| `description` | `varchar(500)` | NULL | 说明 |
| `last_test_status` | `varchar(16)` | NOT NULL DEFAULT `'UNTESTED'` | `UNTESTED/SUCCESS/FAILED` |
| `last_tested_at` | `timestamptz` | NULL | 最近测试时间 |
| `last_test_error` | `varchar(1000)` | NULL | 脱敏测试错误 |
| 通用审计列 |  |  | `created_*/updated_*` |

约束与索引：

```text
CHECK channel_type IN (DINGTALK, WECOM)
CHECK message_format IN (TEXT, MARKDOWN)
CHECK last_test_status IN (UNTESTED, SUCCESS, FAILED)
CHECK jsonb_typeof(mentioned_mobiles) = 'array'
UNIQUE INDEX uk_alert_channel_name_ci ON alert_channel (lower(name))
INDEX idx_alert_channel_enabled ON alert_channel (enabled, id)
```

### 4.2 `alert_rule`

职责：保存告警条件、严重程度、作用范围和静默窗口。指标编码由应用注册表控制，避免每增加一个指标都修改表结构。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 规则 ID |
| `name` | `varchar(200)` | NOT NULL | 规则名称 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否评估 |
| `metric_code` | `varchar(64)` | NOT NULL | 应用注册的指标编码 |
| `condition_op` | `varchar(8)` | NOT NULL | `EQ/NE/GT/GTE/LT/LTE` |
| `threshold` | `jsonb` | NOT NULL | 受控阈值对象；由指标定义校验类型 |
| `severity` | `varchar(16)` | NOT NULL DEFAULT `'WARNING'` | `INFO/WARNING/CRITICAL` |
| `scope_type` | `varchar(16)` | NOT NULL DEFAULT `'ALL'` | P0 仅 `ALL/TASK`；删除旧 task group 范围 |
| `scope_task_id` | `bigint` | NULL | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `silence_minutes` | `integer` | NOT NULL DEFAULT `60` | 同一规则静默时间 |
| `last_triggered_at` | `timestamptz` | NULL | 最近实际生成事件时间 |
| `description` | `varchar(500)` | NULL | 说明 |
| 通用审计列 |  |  | `created_*/updated_*` |

约束与索引：

```text
CHECK condition_op IN (EQ, NE, GT, GTE, LT, LTE)
CHECK severity IN (INFO, WARNING, CRITICAL)
CHECK scope_type IN (ALL, TASK)
CHECK silence_minutes >= 0
CHECK jsonb_typeof(threshold) = 'object'
CHECK scope_type=ALL 时 scope_task_id IS NULL
CHECK scope_type=TASK 时 scope_task_id IS NOT NULL
UNIQUE INDEX uk_alert_rule_name_ci ON alert_rule (lower(name))
INDEX idx_alert_rule_enabled ON alert_rule (enabled, id)
INDEX idx_alert_rule_task ON alert_rule (scope_task_id) WHERE scope_task_id IS NOT NULL
```

### 4.3 `alert_rule_channel`

职责：规则和渠道的结构化多对多关系，替代 JSON 渠道 ID 数组。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | `bigint` | PK/FK | FK `alert_rule(id)`，`ON DELETE CASCADE` |
| `channel_id` | `bigint` | PK/FK | FK `alert_channel(id)`，`ON DELETE RESTRICT` |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 关联时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

索引：

```text
PRIMARY KEY (rule_id, channel_id)
INDEX idx_alert_rule_channel_channel ON alert_rule_channel (channel_id, rule_id)
```

### 4.4 `alert_event`

职责：每次规则实际命中的不可变事实。不包含确认、认领或处理流。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 事件内部 ID |
| `event_uuid` | `uuid` | NOT NULL UNIQUE | 稳定事件标识 |
| `rule_id` | `bigint` | NULL | FK `alert_rule(id)`，`ON DELETE SET NULL` |
| `rule_name_snapshot` | `varchar(200)` | NOT NULL | 规则名称快照 |
| `metric_code_snapshot` | `varchar(64)` | NOT NULL | 指标快照 |
| `rule_snapshot` | `jsonb` | NOT NULL | condition/threshold/scope 等小型快照 |
| `severity` | `varchar(16)` | NOT NULL | `INFO/WARNING/CRITICAL` |
| `source_type` | `varchar(32)` | NOT NULL | `SYNC_EXECUTION/PRECHECK_RUN/VALIDATION_RUN/MESSAGE_OUTBOX/DELETE_SNAPSHOT_RUN/SYSTEM` |
| `task_id` | `bigint` | NULL | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `execution_id` | `bigint` | NULL | FK `sync_execution(id)`，`ON DELETE RESTRICT` |
| `precheck_run_id` | `bigint` | NULL | FK `precheck_run(id)`，`ON DELETE RESTRICT` |
| `validation_run_id` | `bigint` | NULL | FK `validation_run(id)`，`ON DELETE RESTRICT` |
| `message_outbox_id` | `bigint` | NULL | FK `message_outbox(id)`，`ON DELETE RESTRICT` |
| `delete_snapshot_run_id` | `bigint` | NULL | FK `delete_snapshot_run(id)`，`ON DELETE RESTRICT` |
| `title` | `varchar(300)` | NOT NULL | 标题 |
| `summary` | `text` | NOT NULL | 脱敏摘要 |
| `triggered_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 规则命中时间 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 入库时间 |

约束和索引：

```text
CHECK severity IN (INFO, WARNING, CRITICAL)
CHECK source_type IN (...受控集合...)
CHECK jsonb_typeof(rule_snapshot) = 'object'
INDEX idx_alert_event_time ON alert_event (triggered_at DESC, id DESC)
INDEX idx_alert_event_task ON alert_event (task_id, triggered_at DESC) WHERE task_id IS NOT NULL
INDEX idx_alert_event_execution ON alert_event (execution_id) WHERE execution_id IS NOT NULL
INDEX idx_alert_event_validation ON alert_event (validation_run_id) WHERE validation_run_id IS NOT NULL
INDEX idx_alert_event_severity ON alert_event (severity, triggered_at DESC)
```

`source_type` 与对应来源外键的一致性由数据库 `CHECK` 明确约束；`SYSTEM` 允许全部来源外键为空。

### 4.5 `alert_delivery`

职责：一个告警事件向一个目标渠道的汇总投递结果，不保存逐次重试明细。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 投递 ID |
| `event_id` | `bigint` | NOT NULL | FK `alert_event(id)`，`ON DELETE CASCADE` |
| `channel_id` | `bigint` | NULL | FK `alert_channel(id)`，`ON DELETE SET NULL` |
| `channel_name_snapshot` | `varchar(200)` | NOT NULL | 渠道名称快照 |
| `channel_type_snapshot` | `varchar(24)` | NOT NULL | 渠道类型快照 |
| `status` | `varchar(16)` | NOT NULL DEFAULT `'PENDING'` | `PENDING/SENDING/SUCCEEDED/FAILED` |
| `attempt_count` | `integer` | NOT NULL DEFAULT `0` | 汇总尝试次数 |
| `last_attempt_at` | `timestamptz` | NULL | 最近尝试时间 |
| `delivered_at` | `timestamptz` | NULL | 成功时间 |
| `last_error_code` | `varchar(100)` | NULL | 脱敏错误码 |
| `last_error` | `varchar(1000)` | NULL | 脱敏错误摘要 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 状态更新时间 |

约束和索引：

```text
CHECK status IN (PENDING, SENDING, SUCCEEDED, FAILED)
CHECK attempt_count >= 0
CHECK status=SUCCEEDED 时 delivered_at IS NOT NULL 且 last_error IS NULL
UNIQUE (event_id, channel_id)
INDEX idx_alert_delivery_event ON alert_delivery (event_id, id)
INDEX idx_alert_delivery_pending ON alert_delivery (status, created_at) WHERE status IN ('PENDING','SENDING')
INDEX idx_alert_delivery_channel ON alert_delivery (channel_id, created_at DESC) WHERE channel_id IS NOT NULL
```

## 5. 外部任务 API

### 5.1 `external_api_client`

职责：外部调用方稳定身份、HMAC secret、启停和机构授权模式。只停用，不物理删除。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 内部主键 |
| `client_id` | `varchar(100)` | NOT NULL UNIQUE | 对外稳定身份；大小写敏感、不可复用 |
| `client_name` | `varchar(200)` | NOT NULL | 展示名称 |
| `secret_enc` | `text` | NOT NULL | 当前 HMAC secret 密文 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 停用后立即拒绝请求 |
| `authorization_mode` | `varchar(16)` | NOT NULL DEFAULT `'SELECTED'` | `ALL/SELECTED` |
| `description` | `varchar(500)` | NULL | 说明 |
| `secret_updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建或重置 secret 的时间 |
| `last_used_at` | `timestamptz` | NULL | 最近一次认证成功时间；非安全审计依据 |
| 通用审计列 |  |  | `created_*/updated_*` |

约束和索引：

```text
CHECK (btrim(client_id) <> '')
CHECK authorization_mode IN (ALL, SELECTED)
UNIQUE (client_id)
```

服务规则：

### 5.4 `external_api_request`

职责：所有外部写操作的统一幂等、处理状态和长期结果摘要。

| 列 | 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |

| `error_code` | `varchar(100)` | NULL | 失败稳定错误码 |
| `error_message` | `varchar(1000)` | NULL | 脱敏错误摘要 |
| `attempt_count` | `integer` | NOT NULL DEFAULT `1` | 处理/恢复尝试数 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 首次接收时间 |

| `completed_at` | `timestamptz` | NULL | 首次终态时间 |
| `last_replayed_at` | `timestamptz` | NULL | 最近一次幂等命中返回时间 |

约束和索引：

```text
UNIQUE (client_id, request_id)
CHECK operation_code IN (TASK_ENSURE, TASK_RUN, TASK_DELETE, MESSAGE_RETRY)
CHECK status IN (PROCESSING, SUCCEEDED, FAILED)
CHECK request_hash ~ '^[0-9a-f]{64}$'
CHECK jsonb_typeof(normalized_request) = 'object'
CHECK response_body IS NULL OR jsonb_typeof(response_body) = 'object'
CHECK attempt_count >= 1
CHECK 终态时 completed_at IS NOT NULL
CHECK SUCCEEDED 时 response_body 非空且错误字段为空
CHECK FAILED 时 error_code 非空

INDEX idx_external_request_operation ON external_api_request (operation_code, created_at DESC)
INDEX idx_external_request_processing ON external_api_request (status, last_attempt_at) WHERE status='PROCESSING'
```

幂等事务：

1. 以 `(client_id, request_id)` 插入 `PROCESSING`；唯一冲突后锁定现有行。
2. Hash 或操作不同返回 `IDEMPOTENCY_CONFLICT`。
3. 已终态且相同请求直接返回原响应，并更新 `last_replayed_at`。
4. `PROCESSING` 超时后由操作专用恢复逻辑核对真实任务、执行或 Outbox 状态，再完成原记录；不得盲目重复副作用。
5. P0 不自动清理该表，也不允许复用历史 requestId。

## 7. Quartz JDBC JobStore

Quartz 表不设计自定义字段，直接采用项目锁定 Quartz 版本官方 PostgreSQL JDBC JobStore DDL，并统一使用小写物理表名：

```text
qrtz_job_details
qrtz_triggers
qrtz_simple_triggers
qrtz_cron_triggers
qrtz_simprop_triggers
qrtz_blob_triggers
qrtz_calendars
qrtz_paused_trigger_grps
qrtz_fired_triggers
qrtz_scheduler_state
qrtz_locks
```

固定规则：

1. 所有表位于 `df_etl` Schema，配置 `org.quartz.jobStore.tablePrefix=df_etl.qrtz_`。
2. DDL 必须与实际依赖的 Quartz 版本官方 PostgreSQL 脚本逐列一致，不能从老库手抄或自行删列。
3. `spring.quartz.jdbc.initialize-schema=never`；缺表时启动失败并明确报告，禁止退回 RAMJobStore。
4. 使用 `PostgreSQLDelegate`、`instanceId=AUTO`、`isClustered=true`、独立 HikariCP 连接池。
5. JobDataMap 只存简单 `taskId` 属性，`useProperties=true`；禁止 Java 序列化领域对象。
6. 任务暂停、无 Cron 或逻辑删除时删除 Job/Trigger，不依赖 `qrtz_paused_trigger_grps` 保存业务暂停状态。
7. 老系统任何 `qrtz_*` 行均不迁移；新投影由业务任务对账重建。
8. Quartz 官方主键、外键和索引完整保留；V1 生成时对 DDL 做版本校验和表数量校验。

## 8. Doris 删除快照技术表

### 8.1 `_dfetl_key_snapshot`

职责：保存各候选/有效基线快照的完整联合业务键集合。表由平台在每个逻辑 Doris 部署中幂等创建。

建议物理合同：

```sql
CREATE TABLE _dfetl_key_snapshot (
    snapshot_run_id        BIGINT       NOT NULL,
    task_id                BIGINT       NOT NULL,
    task_version_id        BIGINT       NOT NULL,
    institution_id         BIGINT       NOT NULL,
    institution_code       VARCHAR(64)  NOT NULL,
    dataset_id             BIGINT       NOT NULL,
    key_hash               CHAR(64)     NOT NULL,
    key_payload            STRING       NOT NULL,
    key_protocol_version   VARCHAR(64)  NOT NULL,
    captured_at            DATETIME(6)  NOT NULL
)
DUPLICATE KEY(snapshot_run_id, task_id, key_hash)
DISTRIBUTED BY HASH(task_id, key_hash) BUCKETS AUTO;
```

设计说明：

- 使用 `DUPLICATE KEY`，不在写入时自动覆盖重复业务键；快照完整性检查可以准确识别源端重复联合主键。
- `key_hash` 用于分布和 Join，anti join 同时比较 `key_payload`，不只依赖 Hash。
- 不使用按日期自动过期的动态分区，避免当前有效基线因年龄被错误删除。
- 表中只保留当前有效基线、活动候选及仍被活动比较引用的数据；清理由 `snapshot_run_id` 显式执行。
- 建表属性使用目标 Doris 配置的副本数；建议启用 `light_schema_change=true` 和 `compression=zstd`。
- 可按实际 Doris 版本为 `key_hash` 增加 Bloom Filter 属性；该优化不改变逻辑合同。

主要查询：

```text
WHERE snapshot_run_id = ? AND task_id = ?
GROUP BY key_hash, key_payload HAVING COUNT(*) > 1
baseline LEFT ANTI JOIN current ON task_id/key_hash/key_payload
DELETE WHERE snapshot_run_id = ?
```

### 8.2 `_dfetl_delete_diff`

职责：保存一次删除对账识别出的业务键明细，供分页、导出、dry-run 和人工应用。

建议物理合同：

```sql
CREATE TABLE _dfetl_delete_diff (
    validation_run_id          BIGINT       NOT NULL,
    baseline_snapshot_run_id   BIGINT       NOT NULL,
    current_snapshot_run_id    BIGINT       NOT NULL,
    task_id                    BIGINT       NOT NULL,
    task_version_id            BIGINT       NOT NULL,
    institution_id             BIGINT       NOT NULL,
    institution_code           VARCHAR(64)  NOT NULL,
    dataset_id                 BIGINT       NOT NULL,
    key_hash                   CHAR(64)     NOT NULL,
    key_payload                STRING       NOT NULL,
    detected_at                DATETIME(6)  NOT NULL
)
DUPLICATE KEY(validation_run_id, task_id, key_hash)
DISTRIBUTED BY HASH(task_id, key_hash) BUCKETS AUTO;
```

设计说明：

- 每次成功删除对账使用新的 `validation_run_id`，明细不可原地修改。
- 分页必须使用稳定键集游标 `(key_hash, key_payload)`，禁止大偏移量 `OFFSET`。
- 导出和删除应用均按 `validation_run_id + task_id + institution_id` 限定范围。
- 清理任务只删除已达到保留截止时间、没有活动 `delete_apply_run` 且不再需要审计下钻的 validation run 明细。
- 具体保留天数属于部署级治理参数，不进入表结构；PostgreSQL 运行摘要长期保留。
