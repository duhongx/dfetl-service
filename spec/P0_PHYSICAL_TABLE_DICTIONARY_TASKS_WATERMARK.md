## 1. 本文件范围

```text
sync_task
sync_task_version
task_validation_policy
task_watermark
```

同时明确以下边界：

- 任务身份固定为“一个医疗机构 + 一个标准数据集”；
- 采集链路属于任务版本，可以由用户显式更换；
- 预检只保存和展示事实，不存在全局、数据集或任务级预检策略；
- 校验允许“全局默认 → 数据集覆盖 → 任务覆盖”；
- 调度和读取参数属于不可变任务版本；
- 消息策略只存在于数据集级；
- 正式水位只有当前值，不建立水位历史表。

## 2. 旧扁平任务模型的目标拆分

旧 `sync_task` 同时保存任务身份、源目标配置、运行状态、调度、增量配置、正式水位、字段映射、执行摘要和大量历史功能开关。新模型拆分为：

```text
sync_task
  ├─ 长期业务身份
  ├─ 当前版本指针
  ├─ 自动调度开关
  └─ 逻辑删除

sync_task_version
  ├─ 不可变链路版本
  ├─ 不可变数据集版本
  ├─ 固定任务类型和写入合同
  ├─ 固定读取参数
  └─ 固定调度合同

task_validation_policy
  └─ 可在后续新执行生效的任务级校验覆盖

task_watermark
  └─ 当前正式时间水位
```

不继续在任务身份行保存：

```text
source_datasource_id
target_datasource_id
source_schema
source_object
source_mode
custom_sql
view_names
target_table_map
field_mappings
sync_type
sync_mode
data_scope
incremental_checkpoint
initial_full_sync_done
status
version_status
last_run_status
last_run_time
schedule_blocked
catch_up_pending
alert_status
reader_parallelism
retry/backoff/resume 字段
消息配置
预检策略
```

## 3. `sync_task`

职责：保存同步管道的长期业务身份、当前不可变版本指针、用户控制的自动调度开关及逻辑删除信息。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 任务主键 |
| `institution_id` | `bigint` | NOT NULL | 任务所属机构，FK `institution(id)`，`ON DELETE RESTRICT` |
| `dataset_id` | `bigint` | NOT NULL | 任务所属标准数据集，FK `standard_dataset(id)`，`ON DELETE RESTRICT` |
| `name` | `varchar(200)` | NOT NULL | 展示名称；不作为业务唯一身份 |
| `current_version_id` | `bigint` | NULL | 当前不可变任务版本；创建事务结束前必须非空 |
| `schedule_enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否允许后续自动调度；不影响人工运行 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 名称、当前指针和调度开关的乐观锁版本 |
| `deleted_at` | `timestamptz` | NULL | 逻辑删除时间 |
| `deleted_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

任务不保存生命周期状态。以下事实分别从对应对象查询：

- 最近运行结果和失败原因：`sync_execution`；
- 当前载入进度：`load_batch`；
- 当前正式水位：`task_watermark`；
- 当前校验策略：三级策略解析；
- 当前消息策略：`dataset_message_policy`；
- 当前采集链路：当前 `sync_task_version.route_version_id`。

### 3.2 约束

```text
CHECK (btrim(name) <> '')
CHECK (revision >= 0)
CHECK ((deleted_at IS NULL AND deleted_by IS NULL) OR deleted_at IS NOT NULL)
```

为任务版本复合外键提供支撑：

```text
UNIQUE (id, institution_id, dataset_id)
```

当前版本同父约束：

```text
FOREIGN KEY (id, current_version_id)
REFERENCES sync_task_version(task_id, id)
DEFERRABLE INITIALLY DEFERRED
```

创建任务时可以先插入身份行，再插入第一个版本、默认任务校验策略，最后切换 `current_version_id`；事务结束前未删除任务必须已经存在当前版本。

### 3.3 唯一和索引

未删除任务的最终业务唯一性：

```text
UNIQUE INDEX uk_sync_task_active_institution_dataset
    ON sync_task (institution_id, dataset_id)
    WHERE deleted_at IS NULL
```

任务名称不设置全局唯一约束。页面可以使用自动生成名称，但业务身份始终由机构和数据集确定。

查询索引：

```text
INDEX idx_sync_task_institution
    ON sync_task (institution_id, deleted_at, id)

INDEX idx_sync_task_dataset
    ON sync_task (dataset_id, deleted_at, id)

INDEX idx_sync_task_schedule_projection
    ON sync_task (schedule_enabled, current_version_id, id)
    WHERE deleted_at IS NULL AND schedule_enabled = true
```

`current_version_id` 的唯一引用查询由当前版本外键和主键完成，无需额外低选择度索引。

### 3.4 调度开关和逻辑删除

- 暂停任务只将 `schedule_enabled=false`，并在事务提交后删除对应 Quartz Job/Trigger。
- 恢复任务将其设为 `true`，Quartz 投影根据当前版本重新建立。
- 暂停任务仍允许人工运行。
- 任务失败、取消或校验失败不会自动修改 `schedule_enabled`。
- 逻辑删除前必须确认不存在活动执行；如有活动执行，等待结束或受控取消。
- 逻辑删除同时关闭后续调度，但不删除任务版本、水位、执行、批次、校验、消息和审计历史。
- 逻辑删除后释放“机构 + 数据集”的未删除唯一关系，允许重新创建新任务。

## 4. `sync_task_version`

职责：保存一次完整、不可变、可直接执行的任务合同。任务可以采用同一链路的新版本，也可以由用户显式改用另一条满足条件的采集链路。

### 4.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 任务版本主键 |
| `task_id` | `bigint` | NOT NULL | 父任务，FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `version_no` | `integer` | NOT NULL | 父任务内从 1 递增 |
| `institution_id` | `bigint` | NOT NULL | 任务机构约束辅助列和历史快照引用 |
| `institution_code` | `varchar(100)` | NOT NULL | 任务机构编码快照 |
| `dataset_id` | `bigint` | NOT NULL | 任务数据集约束辅助列 |
| `dataset_version_id` | `bigint` | NOT NULL | 不可变数据集版本 |
| `route_version_id` | `bigint` | NOT NULL | 不可变采集链路版本 |
| `task_kind` | `varchar(32)` | NOT NULL | `FULL_ONLY/FULL_THEN_INCREMENTAL` |
| `write_mode` | `varchar(40)` | NOT NULL | `REPLACE_INSTITUTION_SCOPE/UPSERT` |
| `doris_key_model` | `varchar(24)` | NOT NULL | `DUPLICATE_KEY/UNIQUE_KEY` |
| `incremental_field_code` | `varchar(100)` | NULL | 时间增量字段编码；仅增量任务有值 |
| `fetch_size` | `integer` | NOT NULL | JDBC Reader Fetch Size；Reader 并发固定为 1 |
| `upper_bound_delay_minutes` | `integer` | NOT NULL DEFAULT `0` | 增量上界延迟；非增量任务固定为 0 |
| `lookback_seconds` | `integer` | NOT NULL DEFAULT `0` | 增量回看窗口；默认 0 |
| `schedule_mode` | `varchar(24)` | NOT NULL | `MANUAL/EVERY_N_HOURS/CRON` |
| `schedule_interval_hours` | `integer` | NULL | `EVERY_N_HOURS` 时保存原间隔 |
| `schedule_cron` | `varchar(128)` | NULL | 实际交给 Quartz 的规范化 Cron；自动错峰后也保存最终值 |
| `schedule_timezone` | `varchar(64)` | NOT NULL | 调度时区，默认 `Asia/Shanghai` |
| `schedule_source` | `varchar(16)` | NOT NULL | `GLOBAL/DATASET/TASK` |
| `schedule_source_revision` | `bigint` | NULL | 来源策略 revision；用户直接配置时可以为空 |
| `contract_hash` | `char(64)` | NOT NULL | 完整任务执行合同 SHA-256 |
| `change_summary` | `varchar(1000)` | NULL | 小型差异摘要 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

不重复保存数据源地址、密码、完整 JDBC URL、FE 列表、字段解析 JSON、业务主键数组、ODS/RAW 自由表名或消息配置。它们分别由不可变数据集版本、链路版本、字段解析行和数据集消息策略提供。

### 4.2 基础约束

```text
CHECK (version_no > 0)
CHECK (btrim(institution_code) <> '')
CHECK (task_kind IN ('FULL_ONLY','FULL_THEN_INCREMENTAL'))
CHECK (write_mode IN ('REPLACE_INSTITUTION_SCOPE','UPSERT'))
CHECK (doris_key_model IN ('DUPLICATE_KEY','UNIQUE_KEY'))
CHECK (incremental_field_code IS NULL OR
       incremental_field_code = upper(btrim(incremental_field_code)))
CHECK (fetch_size BETWEEN 1 AND 1000000)
CHECK (upper_bound_delay_minutes BETWEEN 0 AND 1440)
CHECK (lookback_seconds BETWEEN 0 AND 2592000)
CHECK (schedule_mode IN ('MANUAL','EVERY_N_HOURS','CRON'))
CHECK (schedule_source IN ('GLOBAL','DATASET','TASK'))
CHECK (schedule_source_revision IS NULL OR schedule_source_revision >= 0)
CHECK (btrim(schedule_timezone) <> '')
CHECK (contract_hash ~ '^[0-9a-f]{64}$')
```

三种标准任务组合固定为：

```text
CHECK (
  (task_kind = 'FULL_ONLY'
    AND write_mode = 'REPLACE_INSTITUTION_SCOPE'
    AND doris_key_model = 'DUPLICATE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes = 0
    AND lookback_seconds = 0)
  OR
  (task_kind = 'FULL_THEN_INCREMENTAL'
    AND write_mode = 'UPSERT'
    AND doris_key_model = 'UNIQUE_KEY'
    AND incremental_field_code IS NOT NULL)
  OR
  (task_kind = 'FULL_ONLY'
    AND write_mode = 'UPSERT'
    AND doris_key_model = 'UNIQUE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes = 0
    AND lookback_seconds = 0)
)
```

调度组合：

```text
CHECK (
  (schedule_mode = 'MANUAL'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NULL)
  OR
  (schedule_mode = 'EVERY_N_HOURS'
    AND schedule_interval_hours BETWEEN 1 AND 8760
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
  OR
  (schedule_mode = 'CRON'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
)
```

`EVERY_N_HOURS` 的 `schedule_cron` 保存应用自动错峰后最终交给 Quartz 的表达式，保证调度投影可重建，不需要在 Quartz 表外再计算一次不同结果。

### 4.3 关系一致性

任务版本必须与任务长期身份一致：

```text
FOREIGN KEY (task_id, institution_id, dataset_id)
REFERENCES sync_task(id, institution_id, dataset_id)
ON DELETE RESTRICT
```

任务机构必须属于所选链路版本覆盖集合：

```text
FOREIGN KEY (route_version_id, institution_id)
REFERENCES collection_route_version_institution(route_version_id, institution_id)
ON DELETE RESTRICT
```

链路版本必须属于同一数据集及同一数据集版本：

```text
FOREIGN KEY (route_version_id, dataset_id)
REFERENCES collection_route_version(id, dataset_id)
ON DELETE RESTRICT

FOREIGN KEY (route_version_id, dataset_version_id)
REFERENCES collection_route_version(id, dataset_version_id)
ON DELETE RESTRICT
```

增量字段必须属于所选数据集版本：

```text
FOREIGN KEY (dataset_version_id, incremental_field_code)
REFERENCES standard_dataset_field(dataset_version_id, field_code)
ON DELETE RESTRICT
```

`incremental_field_code` 为空时该外键不触发。

保存服务还必须验证：

1. 无业务主键数据集只能生成 `FULL_ONLY + REPLACE_INSTITUTION_SCOPE + DUPLICATE_KEY`。
2. 有业务主键且数据集版本存在有效增量字段时生成 `FULL_THEN_INCREMENTAL + UPSERT + UNIQUE_KEY`。
3. 有业务主键但无增量字段时生成 `FULL_ONLY + UPSERT + UNIQUE_KEY`。
4. `incremental_field_code` 必须等于数据集版本确认的增量字段，不允许任务自行选择其他字段。
5. 所选链路不能已逻辑删除，且任务所属数据集和机构必须匹配。
6. 字段解析或源元数据问题可以保存到版本并展示风险，但正式执行前发现不可执行合同时明确失败。

### 4.4 唯一与索引

```text
UNIQUE (task_id, version_no)
UNIQUE (task_id, contract_hash)
UNIQUE (task_id, id)
UNIQUE (id, dataset_id)
UNIQUE (id, dataset_version_id)
UNIQUE (id, route_version_id)

INDEX idx_task_version_history
    ON sync_task_version (task_id, version_no DESC)

INDEX idx_task_version_route
    ON sync_task_version (route_version_id, task_id, id)

INDEX idx_task_version_dataset
    ON sync_task_version (dataset_version_id, task_id, id)
```

### 4.5 合同 Hash 和不可变性

`contract_hash` 至少覆盖：

```text
institution_id + institution_code
dataset_id + dataset_version_id
route_version_id
task_kind + write_mode + doris_key_model + incremental_field_code
fetch_size + upper_bound_delay_minutes + lookback_seconds
schedule_mode + schedule_interval_hours + schedule_cron + schedule_timezone
schedule_source + schedule_source_revision
```

- Hash 未变化时不生成重复任务版本。
- Hash 变化时插入新版本并在同一事务切换 `sync_task.current_version_id`。
- 存在活动执行时拒绝切换任务版本。
- 已提交版本禁止 UPDATE/DELETE，错误通过新版本修正。
- 更换链路、修改调度、Fetch Size、上界延迟或回看窗口都通过新版本表达。
- 创建新版本不会自动重置水位、执行重新采集、修改预检事实、改变消息策略或处理删除快照基线。

## 5. `task_validation_policy`

职责：保存任务级校验继承或明确覆盖。它替代含义过宽的 `task_governance_override`；P0 不建立预检策略、消息覆盖或调度覆盖字段。

### 5.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `bigint` | PK/FK | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `override_mode` | `varchar(16)` | NOT NULL DEFAULT `'INHERIT'` | `INHERIT/OVERRIDE` |
| `enabled` | `boolean` | NULL | 覆盖时必填；允许显式关闭 |
| `validation_method` | `varchar(32)` | NULL | 覆盖时必填，`ROW_COUNT/ROW_COUNT_CHECKSUM` |
| `row_tolerance` | `numeric(8,4)` | NULL | 覆盖时必填 |
| `lookback_hours` | `integer` | NULL | 覆盖时必填 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 5.2 约束

```text
CHECK (override_mode IN ('INHERIT','OVERRIDE'))
CHECK (validation_method IS NULL OR
       validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (row_tolerance IS NULL OR
       (row_tolerance >= 0 AND row_tolerance <= 100))
CHECK (lookback_hours IS NULL OR
       lookback_hours BETWEEN 0 AND 8760)
CHECK (revision >= 0)

CHECK (
  (override_mode = 'INHERIT'
    AND enabled IS NULL
    AND validation_method IS NULL
    AND row_tolerance IS NULL
    AND lookback_hours IS NULL)
  OR
  (override_mode = 'OVERRIDE'
    AND enabled IS NOT NULL
    AND validation_method IS NOT NULL
    AND row_tolerance IS NOT NULL
    AND lookback_hours IS NOT NULL)
)
```

### 5.3 生效边界

- 任务创建时同步创建一行，默认 `INHERIT`。
- 每次新执行启动前按“任务覆盖 → 数据集覆盖 → 全局默认”解析最终校验策略。
- 任务处于 `INHERIT` 时，上级校验策略变化从下一次新执行生效。
- 任务为 `OVERRIDE` 时继续使用任务值，直至用户修改或重置为继承。
- 运行中执行始终使用启动时保存的有效配置快照。
- 无业务主键数据集不能保存 `ROW_COUNT_CHECKSUM`；保存服务必须根据任务当前数据集版本拒绝该组合。
- 本表不保存 Checksum 算法、采样率、自动修复、失败重试、自动复检、失败动作、分段大小或目标表列表。
- 成功、失败、重置为继承和显式关闭均写操作审计。

## 6. 已确认：预检只保存事实，不建立策略表

P0 不建立：

```text
global_precheck_policy
dataset_precheck_policy
task_precheck_policy
task_validation_policy 中的 precheck 字段
sync_task_version 中的 precheck_policy 字段
```

任务创建和运行统一展示：

- 最近相关 `precheck_run`；
- `PASS/ISSUES`；
- 是否缺失；
- 是否因链路版本、源结构 Hash 或数据集合同 Hash 变化而过期。

这些事实永远不作为创建或运行门禁，也不需要用户选择“继承/覆盖”或确认风险级别。执行快照只保存当时观察到的预检事实引用和摘要，不保存不存在行为差异的策略值。

## 7. `task_watermark`

职责：只保存时间增量任务的当前正式水位。无增量字段的两类 `FULL_ONLY` 任务不创建水位行。

P0 增量字段固定为业务方指定的时间字段 `XIUGAISJ`，不支持 `ID_RANGE`，因此水位使用 `timestamptz`，不保存字符串或多类型 JSON。

### 7.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `bigint` | PK/FK | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `task_version_id` | `bigint` | NOT NULL | 当前水位最近一次提交或人工设置时对应的任务版本 |
| `watermark_value` | `timestamptz` | NOT NULL | 当前正式左边界 |
| `source_execution_id` | `bigint` | NULL | 自动推进本值的成功执行；人工设置时为空 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 并发提交和人工重置的乐观锁版本 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近更新时间 |
| `updated_by` | `bigint` | NULL | 人工设置时为管理员；系统推进时可为空，FK `app_user(id)` `ON DELETE SET NULL` |

### 7.2 约束和外键

```text
CHECK (revision >= 0)

FOREIGN KEY (task_id, task_version_id)
REFERENCES sync_task_version(task_id, id)
ON DELETE RESTRICT
```

`source_execution_id` 在 `sync_execution` 物理字典完成后增加普通 FK `ON DELETE RESTRICT`，并由服务保证该执行属于同一任务、使用 `task_version_id` 对应版本且状态为 `SUCCEEDED`。

### 7.3 创建、推进和人工重置

- 增量任务创建时不必预建空水位行。
- 不存在水位行时，`FULL_THEN_INCREMENTAL` 的下一次普通运行执行首次全量流程。
- 首次全量开始时间作为初始增量水位；全量完成后执行补充增量，最终完整成功并通过阻断校验后插入水位行。
- 日常增量启动时读取当前 `watermark_value`，计算固定上界，使用左闭右开 `[watermark, upper)`。
- 写入和阻断校验全部通过后，短事务更新到本次固定 `upper`；空窗口成功也推进。
- 失败、取消、校验不一致、数据补采和独立治理校验均不推进正式水位。
- 人工重置为明确时间时 upsert 当前行，设置当前任务版本并清空 `source_execution_id`。
- 用户明确选择“清除水位、下次重新执行首次全量”时删除当前水位行；删除前后值、原因和操作者写入 `audit_log`。
- 不建立 `task_watermark_history`。正常推进从成功执行固定窗口追溯，人工变化从审计追溯。

### 7.4 任务版本和链路变化

创建新任务版本或更换链路时，系统不自动修改水位行：

- 用户可以保留当前水位；
- 可以人工重置为指定时间；
- 可以清除水位并在下一次运行重新走首次全量；
- 可以独立发起重新采集或数据补采。

`task_watermark.task_version_id` 表示当前水位形成时的合同上下文。它与任务当前版本不同只作为事实展示，不自动阻断、迁移或回退。下一次成功推进后更新为实际执行使用的任务版本。

### 7.5 查询和并发

主键已经支持按任务查询。增加：

```text
INDEX idx_task_watermark_source_execution
    ON task_watermark (source_execution_id)
    WHERE source_execution_id IS NOT NULL
```

执行完成事务使用 `SELECT ... FOR UPDATE` 锁定任务和水位行，并通过 `revision` 或当前值比较防止人工重置与执行提交相互覆盖。

## 8. 任务创建和新版本事务

### 8.1 创建任务

```text
锁定机构和数据集身份
→ 检查未删除任务唯一关系
→ 选择链路当前版本并校验数据集、覆盖机构
→ 根据数据集合同解析三种标准任务组合
→ 解析数据集同步默认和用户输入，形成读取/调度合同
→ 计算 task contract_hash
→ 插入 sync_task
→ 插入第一个 sync_task_version
→ 插入 task_validation_policy(INHERIT)
→ 切换 current_version_id
→ 提交
→ 同步 Quartz 投影
```

数据库部分唯一索引是并发创建的最终保护。冲突时返回已有任务，不留下半成品任务或版本。

### 8.2 创建新任务版本

```text
锁定 sync_task
→ 拒绝已逻辑删除任务和存在活动执行的任务
→ 选择目标链路版本并校验数据集、机构覆盖
→ 形成完整执行和调度合同
→ Hash 未变化：不创建版本
→ Hash 变化：插入新版本并切换 current_version_id/revision
→ 提交
→ 重建 Quartz 投影
```

不在该事务中：

- 自动运行任务；
- 自动重置水位；
- 自动重新采集；
- 自动创建预检；
- 自动修改数据集消息策略；
- 自动重建 Doris 表；
- 自动处理删除快照基线。

## 9. 高频查询方向

### 9.1 任务列表

任务列表主查询：

```text
sync_task
JOIN institution
JOIN standard_dataset
JOIN sync_task_version current_version
JOIN collection_route_version
LEFT JOIN latest sync_execution projection
LEFT JOIN task_watermark
```

通过投影或批量查询取得最近执行，避免字段、版本、策略和执行历史形成笛卡尔积。

支持按以下条件分页：

- 机构编码或名称；
- 数据集编码或名称；
- 当前链路；
- `schedule_enabled`；
- 最近执行状态；
- 是否存在正式水位；
- 任务名称。

### 9.2 任务详情

详情分开查询：

1. 任务身份和当前版本；
2. 链路及字段解析快照；
3. 版本历史；
4. 最终生效校验策略和来源；
5. 数据集消息策略只读视图；
6. 当前正式水位；
7. 最近执行、批次、预检事实、校验和消息状态。

### 9.3 引用检查

删除链路、移除覆盖机构或逻辑删除任务时，引用检查只看未删除任务的当前版本；历史任务版本用于历史展示，不阻止当前配置调整。
