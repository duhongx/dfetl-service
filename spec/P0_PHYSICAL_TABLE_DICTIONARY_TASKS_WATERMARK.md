# P0 物理表字典：同步任务、校验覆盖与正式水位

> 状态：阶段 1 物理模型第四批 Review 已按可变任务模型重写  
> 日期：2026-08-15  
> 上游链路字典：`spec/P0_PHYSICAL_TABLE_DICTIONARY_ROUTES_TASKS.md`  
> 数据集及策略字典：`spec/P0_PHYSICAL_TABLE_DICTIONARY_DATASETS.md`

## 1. 本文件范围

```text
sync_task
task_validation_policy
task_watermark
```

明确不建立：

```text
sync_task_version
task_watermark_history
task_governance_override
任务草稿表
任务配置发布/回退表
待生效任务配置表
```

核心边界：

- 任务身份固定为“一个医疗机构 + 一个标准数据集”；
- `sync_task` 直接保存当前有效任务配置；
- 编辑任务直接覆盖当前配置，不生成任务版本；
- 存在活动执行时禁止修改任务配置和任务级校验覆盖；
- 已接受执行使用 `sync_execution` 启动快照，不受后续任务修改影响；
- 校验只允许继承或覆盖校验方法，正式同步最低为 `ROW_COUNT`；
- 消息策略只存在于数据集级；
- 正式水位只保存当前值。

## 2. `sync_task`

职责：保存长期任务身份、当前执行配置、自动调度开关和逻辑删除信息。

### 2.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 任务主键 |
| `institution_id` | `bigint` | NOT NULL | 所属机构，FK `institution(id)`，`ON DELETE RESTRICT` |
| `dataset_id` | `bigint` | NOT NULL | 所属标准数据集，FK `standard_dataset(id)`，`ON DELETE RESTRICT` |
| `dataset_version_id` | `bigint` | NOT NULL | 当前任务使用的数据集合同版本 |
| `route_version_id` | `bigint` | NOT NULL | 当前任务使用的采集链路版本 |
| `name` | `varchar(200)` | NOT NULL | 展示名称，不作为业务唯一身份 |
| `task_kind` | `varchar(32)` | NOT NULL | `FULL_ONLY/FULL_THEN_INCREMENTAL` |
| `write_mode` | `varchar(40)` | NOT NULL | `REPLACE_INSTITUTION_SCOPE/UPSERT` |
| `doris_key_model` | `varchar(24)` | NOT NULL | `DUPLICATE_KEY/UNIQUE_KEY` |
| `incremental_field_code` | `varchar(100)` | NULL | 时间增量字段；非增量任务为空 |
| `fetch_size` | `integer` | NOT NULL | JDBC Reader Fetch Size；Reader 并发固定为 1 |
| `upper_bound_delay_minutes` | `integer` | NOT NULL DEFAULT `0` | 增量上界延迟；非增量任务固定 0 |
| `lookback_seconds` | `integer` | NOT NULL DEFAULT `0` | 增量读取回看窗口；默认 0 |
| `schedule_mode` | `varchar(24)` | NOT NULL | `MANUAL/EVERY_N_HOURS/CRON` |
| `schedule_interval_hours` | `integer` | NULL | `EVERY_N_HOURS` 时保存原始周期 |
| `schedule_cron` | `varchar(128)` | NULL | 最终交给 Quartz 的规范化 Cron |
| `schedule_timezone` | `varchar(64)` | NOT NULL DEFAULT `'Asia/Shanghai'` | 调度时区 |
| `schedule_source` | `varchar(16)` | NOT NULL | `GLOBAL/DATASET/TASK` |
| `schedule_source_revision` | `bigint` | NULL | 来源策略 revision；用户直接配置时可为空 |
| `schedule_enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否允许后续自动调度；不影响人工运行 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `deleted_at` | `timestamptz` | NULL | 逻辑删除时间 |
| `deleted_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近修改时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

任务不保存：

```text
current_version_id
version_no
contract_hash
任务生命周期状态
最近执行状态和时间
正式水位
消息配置
预检策略
校验关闭开关
reader_parallelism
retry/backoff/resume 字段
custom_sql
字段重命名映射
```

对应事实分别从 `sync_execution`、`task_watermark`、数据集策略和链路字段解析中查询。

### 2.2 基础约束

```text
CHECK (btrim(name) <> '')
CHECK (task_kind IN ('FULL_ONLY','FULL_THEN_INCREMENTAL'))
CHECK (write_mode IN ('REPLACE_INSTITUTION_SCOPE','UPSERT'))
CHECK (doris_key_model IN ('DUPLICATE_KEY','UNIQUE_KEY'))
CHECK (incremental_field_code IS NULL OR
       incremental_field_code = upper(btrim(incremental_field_code)))
CHECK (fetch_size BETWEEN 1 AND 1000000)
CHECK (upper_bound_delay_minutes BETWEEN 0 AND 1440)
CHECK (lookback_seconds BETWEEN 0 AND 2592000)
CHECK (schedule_mode IN ('MANUAL','EVERY_N_HOURS','CRON'))
CHECK (schedule_source IN ('GLOBAL','DATASET','TASK'))
CHECK (schedule_source_revision IS NULL OR schedule_source_revision >= 0)
CHECK (btrim(schedule_timezone) <> '')
CHECK (revision >= 0)
CHECK ((deleted_at IS NULL AND deleted_by IS NULL) OR deleted_at IS NOT NULL)
```

### 2.3 三种标准任务组合

```text
CHECK (
  (task_kind = 'FULL_ONLY'
    AND write_mode = 'REPLACE_INSTITUTION_SCOPE'
    AND doris_key_model = 'DUPLICATE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes = 0
    AND lookback_seconds = 0)
  OR
  (task_kind = 'FULL_THEN_INCREMENTAL'
    AND write_mode = 'UPSERT'
    AND doris_key_model = 'UNIQUE_KEY'
    AND incremental_field_code IS NOT NULL)
  OR
  (task_kind = 'FULL_ONLY'
    AND write_mode = 'UPSERT'
    AND doris_key_model = 'UNIQUE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes = 0
    AND lookback_seconds = 0)
)
```

内部枚举统一使用：

```text
FULL_THEN_INCREMENTAL
REPLACE_INSTITUTION_SCOPE
```

不再使用 `FULL_THEN_INCREMENT`、`TRUNCATE` 等容易误解的同义值。

### 2.4 调度组合

```text
CHECK (
  (schedule_mode = 'MANUAL'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NULL)
  OR
  (schedule_mode = 'EVERY_N_HOURS'
    AND schedule_interval_hours BETWEEN 1 AND 8760
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
  OR
  (schedule_mode = 'CRON'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
)
```

`EVERY_N_HOURS.schedule_cron` 保存自动错峰后最终交给 Quartz 的表达式，确保调度投影可以直接重建。

### 2.5 关系一致性

任务当前链路版本必须属于同一数据集和数据集版本：

```text
FOREIGN KEY (route_version_id, dataset_id)
REFERENCES collection_route_version(id, dataset_id)
ON DELETE RESTRICT

FOREIGN KEY (route_version_id, dataset_version_id)
REFERENCES collection_route_version(id, dataset_version_id)
ON DELETE RESTRICT
```

任务机构必须属于所选链路版本覆盖集合：

```text
FOREIGN KEY (route_version_id, institution_id)
REFERENCES collection_route_version_institution(route_version_id, institution_id)
ON DELETE RESTRICT
```

增量字段必须属于当前数据集版本：

```text
FOREIGN KEY (dataset_version_id, incremental_field_code)
REFERENCES standard_dataset_field(dataset_version_id, field_code)
ON DELETE RESTRICT
```

`incremental_field_code` 为空时该外键不触发。

为执行身份一致性提供父唯一约束：

```text
UNIQUE (id, institution_id, dataset_id)
```

应用保存时继续验证：

1. 当前数据集和链路未逻辑删除或作废；
2. 任务组合由数据集合同确定，不允许用户构造不支持组合；
3. `incremental_field_code` 等于数据集版本确认的增量字段；
4. 字段解析问题允许保存和展示，但正式执行前真实不可执行时失败；
5. 消息策略不能由任务覆盖。

### 2.6 唯一和索引

未删除任务业务唯一性：

```text
UNIQUE INDEX uk_sync_task_active_institution_dataset
    ON sync_task (institution_id, dataset_id)
    WHERE deleted_at IS NULL
```

查询和调度索引：

```text
INDEX idx_sync_task_institution
    ON sync_task (institution_id, deleted_at, id)

INDEX idx_sync_task_dataset
    ON sync_task (dataset_id, deleted_at, id)

INDEX idx_sync_task_route_version
    ON sync_task (route_version_id, deleted_at, id)

INDEX idx_sync_task_dataset_version
    ON sync_task (dataset_version_id, deleted_at, id)

INDEX idx_sync_task_schedule_projection
    ON sync_task (schedule_enabled, schedule_mode, schedule_cron, id)
    WHERE deleted_at IS NULL AND schedule_enabled = true
```

任务名称不设置唯一约束。

### 2.7 创建、编辑、暂停和删除

创建任务：

```text
锁定机构和数据集
→ 检查未删除任务唯一关系
→ 选择链路版本并校验覆盖机构和数据集合同
→ 形成当前任务配置
→ 插入 sync_task
→ 插入 task_validation_policy(INHERIT)
→ 提交
→ 同步 Quartz 投影
```

编辑任务：

```text
锁定 sync_task
→ 查询是否存在 PENDING/RUNNING/LOADING/VALIDATING 执行
→ 存在则返回 TASK_EXECUTION_ACTIVE，不更新任何配置
→ 不存在则校验用户提交的新配置和 revision
→ UPDATE sync_task ... WHERE id=? AND revision=?
→ revision + 1
→ 写 audit_log 修改前后摘要
→ 提交
→ 同步 Quartz 投影
```

固定规则：

- 活动执行期间禁止修改 `sync_task` 当前配置；
- 活动执行期间禁止修改 `task_validation_policy`；
- 拒绝信息必须包含当前执行 ID、状态和“等待执行结束或先取消执行”的处理建议；
- 执行启动与任务编辑使用同一任务行锁或等效事务串行化，防止并发穿透；
- 不建立待生效配置、配置草稿或执行结束后自动应用；
- 不插入任务版本；
- 不自动运行任务；
- 不自动重置水位；
- 不自动重新采集；
- 不自动处理删除快照基线；
- 没有字段变化时可以返回无变化，不增加 revision。

暂停和恢复：

- 暂停只设置 `schedule_enabled=false`，提交后删除 Quartz Job/Trigger；
- 恢复设置为 `true`，根据当前任务配置重建 Quartz 投影；
- 暂停后仍允许人工运行；
- 暂停和取消是独立运行操作，不等同于编辑任务配置；
- 失败、取消或校验失败不自动修改调度开关。

逻辑删除：

- 存在活动执行时不得删除；
- 设置 `deleted_at/deleted_by` 并关闭后续调度；
- 不删除水位、执行、批次、校验、Outbox 和审计历史；
- 释放“机构 + 数据集”未删除唯一关系，允许以后重新创建。

## 3. `task_validation_policy`

职责：保存任务级校验方法继承或覆盖。P0 不保存预检策略、校验关闭、容差或校验回看窗口。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `bigint` | PK/FK | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `override_mode` | `varchar(16)` | NOT NULL DEFAULT `'INHERIT'` | `INHERIT/OVERRIDE` |
| `validation_method` | `varchar(32)` | NULL | 覆盖时必填，`ROW_COUNT/ROW_COUNT_CHECKSUM` |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 3.2 约束

```text
CHECK (override_mode IN ('INHERIT','OVERRIDE'))
CHECK (validation_method IS NULL OR
       validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (
  (override_mode = 'INHERIT' AND validation_method IS NULL)
  OR
  (override_mode = 'OVERRIDE' AND validation_method IS NOT NULL)
)
CHECK (revision >= 0)
```

保存服务必须拒绝无真实业务主键的数据集配置 `ROW_COUNT_CHECKSUM`。

任务级校验覆盖属于任务配置，修改时同样执行“无活动执行”检查。

不保存：

```text
enabled
row_tolerance
lookback_hours
auto_recheck
precheck_policy
message_policy
```

运行开始时解析：

```text
全局默认
→ 数据集覆盖
→ 任务覆盖
```

最终只得到一个不可关闭的 `validation_method`，并保存到 `sync_execution.validation_policy_snapshot`。

## 4. `task_watermark`

职责：只保存时间增量任务的当前正式水位。无增量字段的两类 `FULL_ONLY` 任务不创建水位行。

### 4.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `bigint` | PK/FK | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `watermark_value` | `timestamptz` | NOT NULL | 当前正式左边界 |
| `source_execution_id` | `bigint` | NULL | 最近自动推进该值的成功执行；人工设置时为空 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 并发推进和人工重置的乐观锁版本 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近更新时间 |
| `updated_by` | `bigint` | NULL | 人工设置时为管理员，系统推进时可为空；FK `app_user(id)` `ON DELETE SET NULL` |

删除：

```text
task_version_id
```

水位属于任务本身，不与已经删除的任务配置版本绑定。

### 4.2 约束和索引

```text
CHECK (revision >= 0)

FOREIGN KEY (source_execution_id)
REFERENCES sync_execution(id)
ON DELETE RESTRICT
```

应用必须保证 `source_execution_id`：

- 属于同一 `task_id`；
- 状态为 `SUCCEEDED`；
- 该执行按其启动快照允许推进水位。

索引：

```text
INDEX idx_task_watermark_source_execution
    ON task_watermark (source_execution_id)
    WHERE source_execution_id IS NOT NULL
```

### 4.3 创建和推进

- 增量任务创建时不预建空水位行；
- 不存在水位时，下一次普通运行创建独立 `INITIAL_FULL` 执行；
- 首次全量成功并通过门禁校验后，以首次全量开始时间 `T0` 插入水位；
- 下一次正常调度创建独立 `INCREMENTAL` 执行；
- 增量成功并通过门禁校验后推进到固定 `window_upper`；
- 空窗口成功也推进；
- 失败、取消、数据补采和独立治理校验不推进水位。

人工操作：

- 重置为指定时间：upsert 当前值，清空 `source_execution_id`；
- 清除水位：删除当前行，下一次普通运行重新执行首次全量；
- 修改前后值、原因和操作者写入 `audit_log`；
- 不建立 `task_watermark_history`。

任务配置或链路变化时，系统不自动修改水位。使用者可以保留、重置或清除水位，也可以独立发起重新采集或数据补采。

## 5. 执行快照要求

由于任务当前配置可以直接覆盖，`sync_execution` 创建时必须保存本次实际配置快照。

至少固定：

```text
institution_id / institution_code
dataset_id / dataset_version_id
route_version_id
task_kind / write_mode / doris_key_model
incremental_field_code
fetch_size / upper_bound_delay_minutes / lookback_seconds
本次固定时间或主键范围
校验策略快照
消息策略快照
```

之后任务修改不得热更新已有执行。由于活动执行期间禁止编辑任务，执行快照主要承担运行隔离、历史追溯和进程恢复，不承担并发配置切换。

相应删除：

```text
sync_execution.task_version_id
validation_run.task_version_id
message_outbox.task_version_id
task_watermark.task_version_id
```

执行、校验和 Outbox 物理字典中的旧字段在阶段 1 一致性清理中机械删除。

## 6. 高频查询

任务列表：

```text
sync_task
JOIN institution
JOIN standard_dataset
JOIN collection_route_version
LEFT JOIN task_watermark
LEFT JOIN 最近 sync_execution
```

任务详情：

```text
sync_task 当前配置
+ 当前链路版本和字段解析
+ 最终校验方法
+ 数据集消息策略
+ 当前水位
+ 最近预检事实
```

执行详情使用 `sync_execution` 快照，不回读当前任务配置替换历史值。

## 7. 被废止的旧模型

```text
sync_task_version

sync_execution.task_version_id

```

## 8. 验收

- `sync_task` 包含当前完整任务配置。
- 无活动执行时，编辑任务直接更新原行，并通过 revision 防止并发静默覆盖。
- 存在 `PENDING/RUNNING/LOADING/VALIDATING` 执行时，任务配置和任务级校验覆盖均不能修改。
- 编辑拒绝响应包含当前执行 ID、状态和明确处理建议。
- 执行启动与任务编辑不存在并发穿透。
- 未删除任务按机构 + 数据集唯一。
- 当前任务引用的数据集版本、链路版本和覆盖机构关系有效。
- 三种标准任务组合由数据库和服务共同保证。
- `task_validation_policy` 只处理校验方法继承或覆盖。
- `task_watermark` 不保存任务版本字段。
- 历史执行通过启动快照追溯，不依赖当前任务值。
- 不存在任务配置版本发布、迁移、回退、待生效或双配置状态机。
