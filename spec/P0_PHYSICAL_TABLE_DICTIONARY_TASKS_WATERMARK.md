## 1. 当前对象和边界

本文件只定义：

```text
sync_task
task_watermark
```

明确不建立：

```text
sync_task_version
sync_task.current_version_id
task_validation_policy
task_watermark_history
task_governance_override
任务草稿表
任务配置发布/回退表
任务身份迁移表
```

核心模型：

```text
Task 固定身份
= institution_id + dataset_id

Task 当前配置
= dataset_version_id + route_version_id
+ 读取/写入参数
+ 调度参数
+ validation_method_override
+ revision

历史不可变上下文
= sync_execution / validation_run 启动快照
```

固定规则：

- 一个 Task 只属于一家机构和一个标准 Dataset。
- 同一机构 + Dataset 只能存在一个未删除 Task。
- `institution_id/dataset_id` 创建后不可修改。
- `sync_task` 直接保存当前有效配置；普通编辑不生成 Task Version。
- 活动同步执行期间禁止编辑当前 Task 配置。
- 活动独立 Validation 不阻止 Task 普通配置编辑；当前 Validation 使用启动快照。
- Task 级校验覆盖是 `sync_task.validation_method_override` 可空字段。
- Message 配置只存在于 Dataset 级。
- `task_watermark` 只保存当前正式水位，不维护历史表。

## 2. `sync_task`

职责：保存稳定 Task 身份、当前执行配置、调度开关、Task 级校验方式覆盖和逻辑删除信息。

### 2.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | Task ID |
| `institution_id` | `bigint` | NOT NULL | 固定机构，创建后不可修改 |
| `dataset_id` | `bigint` | NOT NULL | 固定 Dataset，创建后不可修改 |
| `dataset_version_id` | `bigint` | NOT NULL | 当前使用的不可变 Dataset Version |
| `route_version_id` | `bigint` | NOT NULL | 当前使用的不可变 Route Version |
| `name` | `varchar(200)` | NOT NULL | 展示名，不承担业务身份 |
| `task_kind` | `varchar(32)` | NOT NULL | `FULL_ONLY/FULL_THEN_INCREMENTAL` |
| `write_mode` | `varchar(40)` | NOT NULL | `REPLACE_INSTITUTION_SCOPE/UPSERT` |
| `doris_key_model` | `varchar(24)` | NOT NULL | `DUPLICATE_KEY/UNIQUE_KEY` |
| `incremental_field_code` | `varchar(100)` | NULL | 增量时间字段；非增量任务为空 |
| `fetch_size` | `integer` | NOT NULL | JDBC Fetch Size；Reader 并发固定 1 |
| `upper_bound_delay_minutes` | `integer` | NOT NULL DEFAULT `0` | 增量上界延迟 |
| `lookback_seconds` | `integer` | NOT NULL DEFAULT `0` | 增量读取回看；不是校验回看 |
| `schedule_mode` | `varchar(24)` | NOT NULL | `MANUAL/EVERY_N_HOURS/CRON` |
| `schedule_interval_hours` | `integer` | NULL | EVERY_N_HOURS 时保存原周期 |
| `schedule_cron` | `varchar(128)` | NULL | Quartz 使用的最终规范化 Cron |
| `schedule_timezone` | `varchar(64)` | NOT NULL DEFAULT `'Asia/Shanghai'` | 调度时区 |
| `schedule_source` | `varchar(16)` | NOT NULL | `GLOBAL/DATASET/TASK` |
| `schedule_source_revision` | `bigint` | NULL | 创建/编辑当前配置时的来源 revision |
| `schedule_enabled` | `boolean` | NOT NULL DEFAULT `true` | 是否允许后续自动调度 |
| `validation_method_override` | `varchar(32)` | NULL | `NULL/ROW_COUNT/ROW_COUNT_CHECKSUM` |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 当前 Task 配置乐观锁 |
| `deleted_at` | `timestamptz` | NULL | 逻辑删除时间 |
| `deleted_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `created_at/created_by` |  |  | 创建审计 |
| `updated_at/updated_by` |  |  | 更新审计 |

Task 不保存：

```text
current_version_id
version_no
contract_hash
任务版本状态
任务生命周期状态
最近执行状态/时间
正式水位
Message 配置
Precheck 策略
Validation enabled/disabled
Validation 容差/校验回看
override_mode
reader_parallelism
retry/backoff/resume
custom_sql
字段重命名映射
```

### 2.2 基础约束

```text
CHECK (btrim(name) <> '')
CHECK (task_kind IN ('FULL_ONLY','FULL_THEN_INCREMENTAL'))
CHECK (write_mode IN ('REPLACE_INSTITUTION_SCOPE','UPSERT'))
CHECK (doris_key_model IN ('DUPLICATE_KEY','UNIQUE_KEY'))
CHECK (incremental_field_code IS NULL OR
       incremental_field_code = upper(btrim(incremental_field_code)))
CHECK (fetch_size BETWEEN 1 AND 1000000)
CHECK (upper_bound_delay_minutes BETWEEN 0 AND 1440)
CHECK (lookback_seconds BETWEEN 0 AND 2592000)
CHECK (schedule_mode IN ('MANUAL','EVERY_N_HOURS','CRON'))
CHECK (schedule_source IN ('GLOBAL','DATASET','TASK'))
CHECK (schedule_source_revision IS NULL OR schedule_source_revision >= 0)
CHECK (btrim(schedule_timezone) <> '')
CHECK (validation_method_override IS NULL OR
       validation_method_override IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (revision >= 0)
CHECK ((deleted_at IS NULL AND deleted_by IS NULL) OR deleted_at IS NOT NULL)
```

`validation_method_override=NULL` 直接表示继承，不建立 `override_mode`。

### 2.3 三种标准 Task 组合

```text
CHECK (
  (task_kind='FULL_ONLY'
    AND write_mode='REPLACE_INSTITUTION_SCOPE'
    AND doris_key_model='DUPLICATE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes=0
    AND lookback_seconds=0)
  OR
  (task_kind='FULL_THEN_INCREMENTAL'
    AND write_mode='UPSERT'
    AND doris_key_model='UNIQUE_KEY'
    AND incremental_field_code IS NOT NULL)
  OR
  (task_kind='FULL_ONLY'
    AND write_mode='UPSERT'
    AND doris_key_model='UNIQUE_KEY'
    AND incremental_field_code IS NULL
    AND upper_bound_delay_minutes=0
    AND lookback_seconds=0)
)
```

内部唯一枚举：

```text
FULL_ONLY
FULL_THEN_INCREMENTAL
REPLACE_INSTITUTION_SCOPE
UPSERT
DUPLICATE_KEY
UNIQUE_KEY
```

不再使用 `FULL_THEN_INCREMENT`、`TRUNCATE` 等同义值。

### 2.4 调度组合

```text
CHECK (
  (schedule_mode='MANUAL'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NULL)
  OR
  (schedule_mode='EVERY_N_HOURS'
    AND schedule_interval_hours BETWEEN 1 AND 8760
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
  OR
  (schedule_mode='CRON'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NOT NULL
    AND btrim(schedule_cron) <> '')
)
```

`EVERY_N_HOURS.schedule_cron` 保存自动错峰后最终交给 Quartz 的表达式；Quartz 直接从当前 `sync_task` 重建投影。

## 3. Task 与 Route/Dataset 的关系一致性

### 3.1 基础 FK

```text
FK institution_id → institution(id) ON DELETE RESTRICT
FK dataset_id → standard_dataset(id) ON DELETE RESTRICT
FK dataset_version_id → standard_dataset_version(id) ON DELETE RESTRICT
FK route_version_id → collection_route_version(id) ON DELETE RESTRICT
```

### 3.2 Dataset Version 必须属于 Task Dataset

```text
FOREIGN KEY (dataset_id,dataset_version_id)
REFERENCES standard_dataset_version(dataset_id,id)
ON DELETE RESTRICT
```

### 3.3 Route Version 必须属于同一机构和 Dataset

单机构 Route 模型不再存在：

```text
collection_route_version_institution
```

因此旧外键：

```text
(route_version_id,institution_id)
→ collection_route_version_institution(...)
```

**明确删除。**

当前使用 Route Version 自身的身份快照：

```text
FOREIGN KEY (route_version_id,institution_id,dataset_id)
REFERENCES collection_route_version(id,institution_id,dataset_id)
ON DELETE RESTRICT
```

`collection_route_version` 必须保留父唯一约束：

```text
UNIQUE (id,institution_id,dataset_id)
```

### 3.4 Route Version 与 Dataset Version 必须一致

最终物理模型建议由数据库直接保证：

```text
FOREIGN KEY (
  route_version_id,
  institution_id,
  dataset_id,
  dataset_version_id
)
REFERENCES collection_route_version(
  id,
  institution_id,
  dataset_id,
  dataset_version_id
)
ON DELETE RESTRICT
```

对应父表增加：

```text
UNIQUE (id,institution_id,dataset_id,dataset_version_id)
```

该四列复合 FK 可以替代前述三列 Route 身份 FK；Flyway V1 最终只保留一套不重复约束。`P0_PHYSICAL_TABLE_DICTIONARY_ROUTES_TASKS.md` 在最终全 spec 一致性扫描中同步补齐该父唯一键。

### 3.5 增量字段

```text
FOREIGN KEY (dataset_version_id,incremental_field_code)
REFERENCES standard_dataset_field(dataset_version_id,field_code)
ON DELETE RESTRICT
```

增量字段为空时不触发。

应用保存还必须验证：

1. Institution、Dataset、Route 未停用/VOID/逻辑删除。
2. Task 三种组合由 Dataset 合同确定。
3. `incremental_field_code` 等于当前 Dataset Version 确认的增量字段。
4. 无真实业务主键时拒绝 `ROW_COUNT_CHECKSUM`。
5. Message 策略不能由 Task 覆盖。

## 4. 唯一和索引

未删除 Task 唯一：

```text
UNIQUE INDEX uk_sync_task_active_institution_dataset
    ON sync_task(institution_id,dataset_id)
    WHERE deleted_at IS NULL
```

查询/调度索引：

```text
INDEX idx_sync_task_institution
    ON sync_task(institution_id,deleted_at,id)

INDEX idx_sync_task_dataset
    ON sync_task(dataset_id,deleted_at,id)

INDEX idx_sync_task_route_version
    ON sync_task(route_version_id,deleted_at,id)

INDEX idx_sync_task_dataset_version
    ON sync_task(dataset_version_id,deleted_at,id)

INDEX idx_sync_task_schedule_projection
    ON sync_task(schedule_enabled,schedule_mode,schedule_cron,id)
    WHERE deleted_at IS NULL AND schedule_enabled=true
```

为 Execution 身份快照支撑：

```text
UNIQUE (id,institution_id,dataset_id)
```

Task 名称不唯一；Validation Override 不单独索引。

## 5. Task 创建与编辑

### 5.1 创建

```text
锁定 Institution + Dataset
→ 检查未删除 Task 唯一关系
→ 找到/确认当前单机构 Route Version
→ 校验 Dataset Version/Route Version/Task 身份一致
→ 从 Dataset/Global 默认解析初始读取与调度参数
→ 生成确定 Task 组合
→ 插入 sync_task 当前配置
→ 提交
→ 重建/同步 Quartz 投影
```

不插入：

```text
sync_task_version
task_validation_policy(INHERIT)
```

Task 校验覆盖初始值直接为：

```text
validation_method_override = NULL
```

### 5.2 编辑

```text
锁定 sync_task
→ 检查活动 sync_execution
→ 活动则返回 TASK_EXECUTION_ACTIVE
→ 拒绝 institution_id/dataset_id 变化
→ 校验 Route/Dataset Version 和其余配置
→ 按 revision UPDATE sync_task
→ revision + 1
→ 写 audit_log before/after 摘要
→ 提交
→ 同步 Quartz 投影
```

固定规则：

- 编辑 DTO 原则上不提供 Institution/Dataset 修改入口；旧调用若传入变化值返回 `TASK_IDENTITY_IMMUTABLE`。
- 不建立“创建新 Task Version”“发布新版本”“切换 current_version_id”等流程。
- 更换 Route、Dataset Version、Fetch Size、调度或 Validation Override 都是当前 Task 配置编辑。
- 活动同步 Execution 期间全部当前配置不可修改。
- 活动独立 Validation 不阻止普通编辑；Validation 保持启动快照。
- Task 编辑不自动重置 Watermark、不自动首次全量、不自动补采、不自动处理删除 Snapshot 基线。

### 5.3 暂停/恢复

- 暂停：`schedule_enabled=false`；提交后删除 Quartz Job/Trigger。
- 恢复：`schedule_enabled=true`；按当前 `sync_task` 重建 Quartz 投影。
- 暂停不阻止人工运行。
- 暂停与取消当前 Execution 是两个独立动作。
- Execution 失败/取消/Validation 失败不自动修改调度开关。

### 5.4 删除和改变业务身份

逻辑删除：

- 存在活动同步 Execution 时拒绝。
- 设置 `deleted_at/deleted_by` 并关闭调度。
- Execution、Batch、Validation、Outbox、Watermark、Audit 历史全部保留。
- 释放“机构 + Dataset”未删除唯一关系。

改变 Institution 或 Dataset：

```text
确认无活动同步 Execution
→ 逻辑删除旧 Task
→ 创建新 Task
```

历史和 Watermark 不自动迁移。

## 6. Validation 方式解析

Task 覆盖：

```text
sync_task.validation_method_override
```

最终解析：

```text
Task override
→ standard_dataset.validation_method_override
→ system_setting[validation.default_method]
→ 注册默认 ROW_COUNT
→ Dataset 合同能力强制
```

结果固定到 `sync_execution`：

```text
validation_method
validation_source
validation_source_revision
validation_contract_forced
```

来源为 TASK 时，`validation_source_revision=sync_task.revision`；不维护独立 Task Validation Policy revision。

## 7. `task_watermark`

职责：只保存时间增量 Task 的**当前**正式 Watermark。两种无增量 `FULL_ONLY` Task 不创建 Watermark 行。

### 7.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `bigint` | PK/FK | FK `sync_task(id)`，`ON DELETE RESTRICT` |
| `watermark_value` | `timestamptz` | NOT NULL | 当前正式左边界 |
| `source_execution_id` | `bigint` | NULL | 最近自动推进该值的成功 Execution；人工设置为空 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 并发推进/人工重置乐观锁 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | 人工操作用户；系统推进可为空 |

明确不保存：

```text
task_version_id
watermark history
跨 Execution checkpoint
```

### 7.2 约束和索引

```text
CHECK (revision >= 0)

FOREIGN KEY (source_execution_id)
REFERENCES sync_execution(id)
ON DELETE RESTRICT

INDEX idx_task_watermark_source_execution
    ON task_watermark(source_execution_id)
    WHERE source_execution_id IS NOT NULL
```

应用保证 `source_execution_id` 属于同一 Task、状态为 SUCCEEDED，并且该 Execution 按启动快照允许推进水位。

### 7.3 首次全量和推进

- 增量 Task 创建时不预建空 Watermark。
- 没有 Watermark 的下一次普通运行创建独立 `INITIAL_FULL` Execution。
- `INITIAL_FULL` 开始时捕获 `T0`。
- 全量成功 + SYNC_GATE PASS 后插入 Watermark=`T0`。
- **不在同一 INITIAL_FULL 内立即追加补充增量。**
- 下一次正常调度/人工运行创建独立 `INCREMENTAL` Execution。
- INCREMENTAL 成功 + Gate PASS 后推进到本次固定 `window_upper`；空窗口成功也推进。
- 失败、取消、Backfill、独立 Validation 不推进正式水位。

人工操作：

- 重置：upsert 指定时间并清空 `source_execution_id`。
- 清除：删除当前 Watermark，下一次普通运行重新 INITIAL_FULL。
- 前后值、原因、操作者写入 `audit_log`。
- 不建立 `task_watermark_history`。

Task/Route 配置变化不自动修改 Watermark。

## 8. Execution / Validation 快照

`sync_execution` 创建时至少固定：

```text
task_id + task_revision
institution_id / institution_code
dataset_id / dataset_version_id
route_version_id
task_kind / write_mode / doris_key_model
incremental_field_code
fetch_size / upper_bound_delay_minutes / lookback_seconds
本次固定时间/Key范围
最终 validation method/source/revision
Message 策略快照
必要的 Source/Target/字段合同上下文
```

历史执行详情读取 Execution Snapshot，不拿当前 Task 覆盖历史。

独立 `validation_run` 启动时保存本次：

```text
task_id
institution/dataset/route 上下文
range_snapshot
validation method/source
必要 Source/Target/字段合同快照
```

相应目标模型不存在：

```text
sync_execution.task_version_id
validation_run.task_version_id
message_outbox.task_version_id
task_watermark.task_version_id
```

## 9. 高频查询

Task 列表：

```text
sync_task
JOIN institution
JOIN standard_dataset
JOIN collection_route_version
LEFT JOIN task_watermark
LEFT JOIN 最近 sync_execution
```

Task 详情：

```text
sync_task 当前配置
+ 当前 Route Version / field resolution
+ 最终 Validation 方式与来源
+ Dataset Message Policy
+ 当前 Watermark
+ 最近 Execution / Precheck 摘要
```

Execution/Validation 历史必须读各自启动快照。

## 10. 旧模型机械清理映射

| 旧对象/文案 | 当前处理 |
| --- | --- |
| `sync_task_version` | 删除 |
| `sync_task.current_version_id` | 删除 |
| `task_version_id` | 从 Execution/Validation/Outbox/Watermark 删除 |
| “创建第一个不可变 Task Version” | 改为直接创建 `sync_task` 当前配置 |
| “修改 Task 时创建新 Version” | 改为无活动同步时更新 `sync_task` + revision |
| “当前 Version Cron” | 改为 `sync_task.schedule_cron` |
| “Task Version 快照” | 改为 Execution/Validation 启动快照 |
| “发布/切换/回退 Task Version” | 不建设；用户显式编辑当前配置 |
| `task_validation_policy` | 删除；合并为 `sync_task.validation_method_override` |
| validation `override_mode` | 删除；NULL 表示继承 |
| `collection_route_version_institution` | 删除；Route Version 自身携带单机构身份 |

## 11. 验收

- P0 表清单不存在 `sync_task_version`、`task_validation_policy`、`collection_route_version_institution`。
- `sync_task` 包含固定 Institution/Dataset 身份和当前完整配置。
- `validation_method_override=NULL` 明确表示继承。
- Task 普通编辑直接更新原行并增加 `revision`。
- Institution/Dataset 创建后不可修改。
- 更换业务身份必须逻辑删除旧 Task 后创建新 Task。
- 活动同步 Execution 期间全部当前 Task 配置不可修改。
- Route Version 通过自身 Institution/Dataset 快照与 Task 建立复合 FK，不再依赖覆盖机构关系表。
- Route Version/Dataset Version/Task 四元一致性在最终 Flyway V1 通过复合唯一键/FK 收敛。
- 未删除 Task 按 Institution + Dataset 唯一。
- `task_watermark` 不保存 Task Version 字段。
- 历史运行通过 Execution/Validation 启动快照追溯。
- 不存在 Task 配置版本、独立 Task Validation Policy、待生效配置、版本发布或版本回退状态机。
