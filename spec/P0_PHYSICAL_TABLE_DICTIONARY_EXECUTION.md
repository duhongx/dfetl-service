### 2.2 基础约束

```text
CHECK (task_revision >= 0)
CHECK (btrim(institution_code) <> '')
CHECK (task_kind IN ('FULL_ONLY','FULL_THEN_INCREMENTAL'))
CHECK (write_mode IN ('REPLACE_INSTITUTION_SCOPE','UPSERT'))
CHECK (doris_key_model IN ('DUPLICATE_KEY','UNIQUE_KEY'))
CHECK (incremental_field_code IS NULL OR incremental_field_code=upper(btrim(incremental_field_code)))
CHECK (fetch_size BETWEEN 1 AND 1000000)
CHECK (upper_bound_delay_minutes BETWEEN 0 AND 1440)
CHECK (lookback_seconds BETWEEN 0 AND 2592000)
CHECK (operation_type IN ('NORMAL','RECOLLECT','BACKFILL'))
CHECK (trigger_type IN ('SCHEDULED','MANUAL','EXTERNAL_API'))
CHECK (status IN ('PENDING','RUNNING','LOADING','VALIDATING','SUCCEEDED','FAILED','CANCELLED'))
CHECK (execution_scope IN ('FULL','INITIAL_FULL','INCREMENTAL','BACKFILL_TIME','BACKFILL_KEY'))
CHECK (target_prepare_mode IN ('NONE','REPLACE_INSTITUTION_SCOPE'))
CHECK (validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (validation_source IN ('GLOBAL','DATASET','TASK','CONTRACT'))
CHECK (validation_source_revision IS NULL OR validation_source_revision >= 0)
CHECK (btrim(checksum_protocol_version) <> '')
CHECK (source_row_count >= 0 AND loaded_row_count >= 0 AND rejected_row_count >= 0)
CHECK (batch_count >= 0 AND revision >= 0)
CHECK (jsonb_typeof(precheck_fact_snapshot)='object')
CHECK (jsonb_typeof(message_policy_snapshot)='object')
CHECK (key_lower IS NULL OR jsonb_typeof(key_lower)='object')
CHECK (key_upper IS NULL OR jsonb_typeof(key_upper)='object')
```

Validation 来源：

```text
CHECK (
  (validation_source='CONTRACT'
    AND validation_contract_forced=true
    AND validation_source_revision IS NULL)
  OR
  (validation_source<>'CONTRACT'
    AND validation_contract_forced=false)
)
```

三种 Task 组合必须与 `sync_task` 完全一致。

Target Prepare：

```text
CHECK (
  (write_mode='REPLACE_INSTITUTION_SCOPE' AND target_prepare_mode='REPLACE_INSTITUTION_SCOPE')
  OR
  (write_mode='UPSERT' AND target_prepare_mode='NONE')
)
```

### 2.3 范围/触发/终态约束

```text
CHECK (window_lower IS NULL OR window_upper IS NULL OR window_lower < window_upper)
```

- `INCREMENTAL/BACKFILL_TIME` 使用时间范围，不使用 Key-only 范围。
- `BACKFILL_KEY` 使用 `key_lower/key_upper`，不使用时间范围。
- `FULL/INITIAL_FULL` 不要求业务窗口边界。
- `BACKFILL` 只允许 `BACKFILL_TIME/BACKFILL_KEY` 且 `watermark_commit_expected=false`。
- `SCHEDULED` 必须有 `schedule_fire_time`；`EXTERNAL_API` 必须有 Client + Request ID。
- 活动态 `finished_at IS NULL`；终态 `finished_at IS NOT NULL`。
- `SUCCEEDED` 必须 `rejected_row_count=0`；`FAILED` 必须有 `error_code`。

取消请求不增加 `CANCELLING` 状态；工作线程停止后先确认在途 Doris Label，再进入 `CANCELLED`。


`incremental_field_code` 为空时不触发。

**不再引用 `collection_route_version_institution`。**

### 2.6 状态流转

```text
PENDING → RUNNING → LOADING → VALIDATING → SUCCEEDED
PENDING/RUNNING/LOADING/VALIDATING → FAILED/CANCELLED
```

- Failed/Cancelled 不推进 Watermark，不改 Task 调度开关。
- 无 `RETRY` 状态；人工重新采集创建新 `RECOLLECT` Execution。
- 不保存 `retry_of_execution_id/recollect_of_execution_id/resume_from_batch_id`。
- Schedule 冲突只跳过本次触发，不创建 SKIPPED Execution，不追赶。

## 3. `load_batch`

职责：保存一次 Execution 内的实际分页游标、确定性 Doris Label、Label 状态探测和最终载入结果；不是跨 Execution 恢复检查点。

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | Batch ID |
| `execution_id` | `bigint` | NOT NULL | 父 Execution |
| `batch_no` | `integer` | NOT NULL | Execution 内从 1 递增 |
| `status` | `varchar(20)` | NOT NULL DEFAULT `'PENDING'` | `PENDING/LOADING/PROBING/SUCCEEDED/FAILED/CANCELLED` |
| `cursor_lower` | `jsonb` | NULL | 实际 Keyset 下界 |
| `cursor_upper` | `jsonb` | NULL | 实际 Keyset 上界 |
| `source_row_count` | `bigint` | NOT NULL DEFAULT `0` | Source 行数 |
| `loaded_row_count` | `bigint` | NOT NULL DEFAULT `0` | Doris 可见行数 |
| `rejected_row_count` | `bigint` | NOT NULL DEFAULT `0` | 拒绝行数 |
| `payload_checksum` | `varchar(128)` | NULL | Batch Payload 摘要；协议版本从父 Execution 取得 |
| `doris_label` | `varchar(128)` | NOT NULL | 确定性 Label |
| `doris_txn_id` | `bigint` | NULL | Doris Txn ID |

| `error_code/error_message` |  | NULL | 错误摘要 |
| `created_at/updated_at` |  | NOT NULL | 时间 |

明确不保存：

```text

probe_result
institution_code
checksum_protocol_version
batch_type/stage

```

### 3.2 约束/索引

```text
CHECK (batch_no > 0)
CHECK (status IN ('PENDING','LOADING','PROBING','SUCCEEDED','FAILED','CANCELLED'))
CHECK (source_row_count >= 0 AND loaded_row_count >= 0 AND rejected_row_count >= 0)
CHECK (probe_count >= 0)
CHECK (btrim(doris_label) <> '')
CHECK (cursor_lower IS NULL OR jsonb_typeof(cursor_lower)='object')
CHECK (cursor_upper IS NULL OR jsonb_typeof(cursor_upper)='object')
CHECK (doris_state IS NULL OR doris_state IN ('UNKNOWN','PREPARE','COMMITTED','VISIBLE','ABORTED'))
CHECK (status <> 'SUCCEEDED' OR (doris_state='VISIBLE' AND visible_at IS NOT NULL AND rejected_row_count=0))
CHECK (status <> 'FAILED' OR error_code IS NOT NULL)

UNIQUE(execution_id,batch_no)
UNIQUE(doris_label)
INDEX idx_load_batch_execution_status ON load_batch(execution_id,status,batch_no)
INDEX idx_load_batch_probe ON load_batch(status,updated_at,id)
  WHERE status IN ('LOADING','PROBING')
```

### 3.3 运行边界

- 第一阶段单 Reader、单在途 Batch。
- 整次范围和机构身份从父 Execution 获取。
- 有业务主键全量使用联合业务主键游标；时间增量使用时间 + 联合主键复合游标。
- Publish Timeout/客户端超时/空响应/解析失败只探测原 Label，不盲目重投。
- `PREPARE/COMMITTED` 继续 PROBING，`VISIBLE` 成功，`ABORTED` 失败。
- Label 长期 UNKNOWN/不可查询超时则 Batch 和 Execution 失败。
- Batch 游标只用于诊断，不成为下次 Execution 恢复位置。

| `issue_row_count` | `bigint` | NOT NULL DEFAULT `0` | 至少命中一个问题的行数统计 |
| `issue_summary_count` | `integer` | NOT NULL DEFAULT `0` | 汇总规则数 |
| `raw_retention_deadline` | `timestamptz` | NULL | 终态后 1 天清理截止 |

| `started_at/finished_at/created_at/updated_at` |  |  | 时间 |

### 4.2 约束和 FK

```text
CHECK (execution_status IN ('PENDING','EXTRACTING','VALIDATING','COMPLETED','FAILED','CANCELLED'))
CHECK (result_status IS NULL OR result_status IN ('PASS','ISSUES'))
CHECK (current_phase IN ('STRUCTURE','EXTRACT','VALIDATE','COMPLETE'))
CHECK (raw_cleanup_status IN ('NOT_READY','PENDING','CLEANED','FAILED'))
CHECK (extracted_row_count >= 0 AND checked_row_count >= 0 AND issue_row_count >= 0)
CHECK (issue_summary_count >= 0)
```

Route/Version：

```text
FOREIGN KEY (route_id,route_version_id)
REFERENCES collection_route_version(route_id,id)
ON DELETE RESTRICT

FOREIGN KEY (
  route_version_id,
  institution_id,
  dataset_id,
  dataset_version_id
)
REFERENCES collection_route_version(
  id,
  institution_id,
  dataset_id,
  dataset_version_id
)
ON DELETE RESTRICT
```

因此 Precheck 不能跨机构、跨 Dataset 或跨 Dataset Version 解释 Route。

### 4.3 唯一/索引和语义

```text
UNIQUE(run_uuid)
UNIQUE INDEX uk_precheck_run_active_route
  ON precheck_run(route_id)
  WHERE execution_status IN ('PENDING','EXTRACTING','VALIDATING')
INDEX idx_precheck_run_route_history
  ON precheck_run(route_id,created_at DESC,id DESC)
INDEX idx_precheck_run_cleanup
  ON precheck_run(raw_cleanup_status,raw_retention_deadline,id)
  WHERE raw_cleanup_status IN ('PENDING','FAILED')
```

- 只能人工发起。
- 每次扫描当前单机构 Route 对应 Source Object 全部目标范围。
- `COMPLETED + ISSUES` 是技术成功 + 数据有问题，不是 FAILED。
- Precheck 事实不成为正式同步数据源，也不作为 Task 硬门禁。
- 重新 Precheck 始终新建 Run。
- RAW 终态保留 1 天并按 Run/Route 精确清理。

## 5. `precheck_issue_summary`

职责：保存字段级和组合规则级**汇总**；不保存逐行问题、业务键、原值、样例或修复状态。

所有 Issue Summary 的机构由父 `precheck_run.institution_id` 唯一确定，因此不再重复保存 `institution_id/institution_code`，也不存在 `INSTITUTION` Rule Scope。

### 5.1 字段

```text
id bigint identity PK
run_id bigint NOT NULL
rule_scope varchar(20) NOT NULL              # STRUCTURE/FIELD/COMPOSITE
standard_field_code varchar(100) NULL
rule_code varchar(100) NOT NULL
rule_definition_version varchar(64) NOT NULL
checked_rows bigint NOT NULL DEFAULT 0
affected_rows bigint NOT NULL DEFAULT 0
observed_metrics jsonb NOT NULL DEFAULT '{}'
summary varchar(2000) NOT NULL
created_at timestamptz NOT NULL
```

约束：

```text
CHECK (rule_scope IN ('STRUCTURE','FIELD','COMPOSITE'))
CHECK (standard_field_code IS NULL OR standard_field_code=upper(btrim(standard_field_code)))
CHECK (checked_rows >= 0 AND affected_rows >= 0)
CHECK (affected_rows <= checked_rows OR checked_rows=0)
CHECK (jsonb_typeof(observed_metrics)='object')
CHECK ((rule_scope='FIELD' AND standard_field_code IS NOT NULL) OR rule_scope<>'FIELD')

UNIQUE INDEX uk_precheck_issue_summary_scope
ON precheck_issue_summary(
  run_id,
  rule_scope,
  coalesce(standard_field_code,''),
  rule_code
)
```

明确不保存：

```text
severity
issue status
row number
business_key
original_value/fixed_value
sample payload
```

### 6.2 核心约束

```text
CHECK (task_revision >= 0)
CHECK (validation_scope IN ('SYNC_WINDOW','FULL_DATASET','CHANGE_WINDOW','DELETE_RECONCILIATION'))
CHECK (trigger_type IN ('SYNC_GATE','MANUAL','MANUAL_RECHECK','SCHEDULED'))
CHECK (validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM','DELETE_KEY_DIFF'))
CHECK (validation_source IN ('GLOBAL','DATASET','TASK','CONTRACT'))
CHECK (validation_source_revision IS NULL OR validation_source_revision >= 0)
CHECK (status IN ('PENDING','RUNNING','COMPLETED','FAILED','CANCELLED'))
CHECK (result IS NULL OR result IN ('PASS','MISMATCH'))
CHECK (difference_count IS NULL OR difference_count >= 0)
CHECK (difference_ratio IS NULL OR (difference_ratio >= 0 AND difference_ratio <= 1))
CHECK (jsonb_typeof(context_snapshot)='object')
CHECK (jsonb_typeof(range_snapshot)='object')
CHECK (jsonb_typeof(difference_summary)='object')
```

组合规则：

- `SYNC_GATE/MANUAL_RECHECK` 必须关联 Execution；独立 `MANUAL/SCHEDULED` 不关联 Execution。
- `ROW_COUNT_CHECKSUM` 必须有 Checksum Protocol。
- `DELETE_RECONCILIATION` 必须使用 `DELETE_KEY_DIFF` 且两侧 Snapshot ID 非空，`difference_count/difference_ratio` 非空。
- 非 DELETE_RECONCILIATION 的 Snapshot ID 和 `difference_ratio` 必须为空。
- `SYNC_GATE` 固定 `validation_scope=SYNC_WINDOW`。
- COMPLETED 必须有 PASS/MISMATCH；FAILED 必须有 error_code。
- 整体 Checksum 不一致但无法精确计算差异行数时，`difference_count` 允许 NULL。

### 6.3 外键/唯一/并发

```text
FK task_id → sync_task(id) ON DELETE RESTRICT
FK execution_id → sync_execution(id) ON DELETE RESTRICT
UNIQUE(id,task_id)
UNIQUE(run_uuid)

UNIQUE INDEX uk_validation_sync_gate_execution
  ON validation_run(execution_id)
  WHERE trigger_type='SYNC_GATE'

UNIQUE INDEX uk_validation_run_active_independent_task
  ON validation_run(task_id)
  WHERE trigger_type IN ('MANUAL','MANUAL_RECHECK','SCHEDULED')
    AND status IN ('PENDING','RUNNING')
```

- SYNC_GATE/MANUAL_RECHECK 从父 Execution 复制上下文，不依赖 Task Version。
- 同步 Execution 与独立 Validation 通过锁定同一 Task 实现跨表互斥。
- 独立 Validation 启动后允许普通 Task 编辑，本次继续使用启动快照。

职责：在 Execution 成功收尾事务中保存一条小型 RabbitMQ 发布指令；每次 Execution 最多一条。

### 7.2 约束/FK/索引

```text

  ON message_outbox(status,last_attempt_at,id) WHERE status='PUBLISHING'
```

成功收尾从父 Execution Snapshot 复制 Task/Dataset/Institution/Message Policy，不回读当前 Task 改写历史身份。

### 7.3 发布/重试

- 发布器使用 `FOR UPDATE SKIP LOCKED` 抢占 PENDING。
- 临时失败增加 attempt_count，未耗尽回 PENDING 并更新 available_at；耗尽 DEAD_LETTER。
- 超时 PUBLISHING 恢复不新增租约/worker 状态表。
- 人工重发沿用 event_id、重置 attempt_count 并写 Audit。
- 每次真实发送生成新的 27 位 messageId。
- 不保存分页进度；失败后从范围起点重新读当前 Doris。
- Outbox 失败不回滚已经成功的 Execution/Watermark。

## 8. 成功收尾原子事务

```text
锁定 sync_execution
→ 准备/锁定 task_watermark
→ 全部 load_batch=SUCCEEDED 且 doris_state=VISIBLE
→ 唯一 SYNC_GATE validation_run=COMPLETED+PASS
→ rejected_row_count=0
→ sync_execution=SUCCEEDED
→ 按 Execution 固定范围创建/推进 Watermark（适用时）
→ Dataset Message Policy 启用则插入唯一 Outbox
→ commit
```

事务内不调用 Doris/RabbitMQ 等远程服务。

## 9. 运行前技术检查失败边界

在创建 Execution 前拒绝：

```text
Task 不存在/已删除
无权限
请求参数非法
External requestId 幂等冲突
已有活动同步 Execution
已有活动独立 Validation
```

通过身份/权限/互斥检查后：

```text
锁定 sync_task
→ 读取当前 Task/Route/Dataset/Validation/Message
→ 创建 PENDING sync_execution 并固定快照
→ 执行 Source/Doris/合同技术前检
→ 通过进入 RUNNING
→ 失败更新为 FAILED
```

已接受请求的技术前检失败仍保留 Execution 历史；不增加 PRECHECKING 状态。
