## 2. `sync_execution`

职责：保存一次真实同步执行的固定任务版本、触发来源、数据范围、运行状态、最终统计和错误摘要。

### 2.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 执行主键 |
| `execution_uuid` | `uuid` | NOT NULL | 应用生成的全局稳定执行标识 |
| `task_id` | `bigint` | NOT NULL | 父任务 |
| `task_version_id` | `bigint` | NOT NULL | 本次固定不可变任务版本 |
| `operation_type` | `varchar(20)` | NOT NULL | `NORMAL/RECOLLECT/BACKFILL` |
| `trigger_type` | `varchar(24)` | NOT NULL | `SCHEDULED/MANUAL/EXTERNAL_API` |
| `status` | `varchar(20)` | NOT NULL DEFAULT `'PENDING'` | 执行状态 |
| `execution_scope` | `varchar(24)` | NOT NULL | `FULL/INITIAL_FULL/INCREMENTAL/BACKFILL_TIME/BACKFILL_KEY` |
| `target_prepare_mode` | `varchar(40)` | NOT NULL DEFAULT `'NONE'` | `NONE/REPLACE_INSTITUTION_SCOPE` |
| `window_lower` | `timestamptz` | NULL | 时间窗口左边界，左闭 |
| `window_upper` | `timestamptz` | NULL | 时间窗口右边界，右开 |
| `key_lower` | `jsonb` | NULL | 补采主键范围左边界，联合键规范结构 |
| `key_upper` | `jsonb` | NULL | 补采主键范围右边界 |
| `watermark_before` | `timestamptz` | NULL | 启动时观察到的正式水位 |
| `watermark_commit_expected` | `boolean` | NOT NULL DEFAULT `false` | 成功时是否应推进正式水位 |
| `schedule_fire_time` | `timestamptz` | NULL | 计划触发时间；非计划运行为空 |
| `external_request_id` | `varchar(128)` | NULL | 外部 API 写操作请求号快照 |

| `message_policy_snapshot` | `jsonb` | NOT NULL DEFAULT `'{}'::jsonb` | 数据集消息策略快照；未启用时记录关闭事实 |
| `execution_contract_hash` | `char(64)` | NOT NULL | 本次执行合同 SHA-256 |
| `checksum_protocol_version` | `varchar(64)` | NOT NULL | 本次校验规范化协议版本 |
| `source_row_count` | `bigint` | NOT NULL DEFAULT `0` | 本次读取总行数 |
| `loaded_row_count` | `bigint` | NOT NULL DEFAULT `0` | Doris 最终确认写入总行数 |
| `rejected_row_count` | `bigint` | NOT NULL DEFAULT `0` | 正式合同拒绝行数；大于 0 时不能成功 |
| `batch_count` | `integer` | NOT NULL DEFAULT `0` | 实际载入批次数 |

### 2.2 枚举和组合约束

```text
CHECK (operation_type IN ('NORMAL','RECOLLECT','BACKFILL'))
CHECK (trigger_type IN ('SCHEDULED','MANUAL','EXTERNAL_API'))
CHECK (status IN
       ('PENDING','RUNNING','LOADING','VALIDATING','SUCCEEDED','FAILED','CANCELLED'))
CHECK (execution_scope IN
       ('FULL','INITIAL_FULL','INCREMENTAL','BACKFILL_TIME','BACKFILL_KEY'))
CHECK (target_prepare_mode IN ('NONE','REPLACE_INSTITUTION_SCOPE'))
CHECK (execution_contract_hash ~ '^[0-9a-f]{64}$')
CHECK (btrim(checksum_protocol_version) <> '')
CHECK (source_row_count >= 0)
CHECK (loaded_row_count >= 0)
CHECK (rejected_row_count >= 0)
CHECK (batch_count >= 0)
CHECK (revision >= 0)
CHECK (jsonb_typeof(precheck_fact_snapshot) = 'object')
CHECK (jsonb_typeof(validation_policy_snapshot) = 'object')
CHECK (jsonb_typeof(message_policy_snapshot) = 'object')
CHECK (key_lower IS NULL OR jsonb_typeof(key_lower) = 'object')
CHECK (key_upper IS NULL OR jsonb_typeof(key_upper) = 'object')
```

时间和主键范围：

```text
CHECK (window_lower IS NULL OR window_upper IS NULL OR window_lower < window_upper)
CHECK (
  (execution_scope IN ('INCREMENTAL','BACKFILL_TIME')
    AND window_upper IS NOT NULL
    AND key_lower IS NULL
    AND key_upper IS NULL)
  OR
  (execution_scope = 'BACKFILL_KEY'
    AND window_lower IS NULL
    AND window_upper IS NULL
    AND key_lower IS NOT NULL
    AND key_upper IS NOT NULL)
  OR
  (execution_scope IN ('FULL','INITIAL_FULL')
    AND key_lower IS NULL
    AND key_upper IS NULL)
)
```

操作类型：

```text
CHECK (
  (operation_type = 'BACKFILL'
    AND execution_scope IN ('BACKFILL_TIME','BACKFILL_KEY')
    AND watermark_commit_expected = false)
  OR
  (operation_type IN ('NORMAL','RECOLLECT')
    AND execution_scope IN ('FULL','INITIAL_FULL','INCREMENTAL'))
)
```

触发来源：

```text
CHECK (
  (trigger_type = 'SCHEDULED'
    AND schedule_fire_time IS NOT NULL
    AND requested_by_user_id IS NULL
    AND external_client_id IS NULL)
  OR
  (trigger_type = 'MANUAL'
    AND schedule_fire_time IS NULL
    AND external_client_id IS NULL)
  OR
  (trigger_type = 'EXTERNAL_API'
    AND schedule_fire_time IS NULL
    AND external_client_id IS NOT NULL
    AND external_request_id IS NOT NULL)
)
```

状态时间：

```text
CHECK (
  (status IN ('PENDING','RUNNING','LOADING','VALIDATING') AND finished_at IS NULL)
  OR
  (status IN ('SUCCEEDED','FAILED','CANCELLED') AND finished_at IS NOT NULL)
)
CHECK (status <> 'SUCCEEDED' OR rejected_row_count = 0)
CHECK (status <> 'FAILED' OR error_code IS NOT NULL)
```

取消请求不增加 `CANCELLING` 状态。工作线程发现 `cancel_requested_at` 后停止后续读取，核实在途 Doris Label，最终写入 `CANCELLED`。

### 2.3 外键和身份一致性

```text
FOREIGN KEY (task_id, task_version_id)
REFERENCES sync_task_version(task_id, id)
ON DELETE RESTRICT
```

执行只引用不可变任务版本，不在运行时把当前任务新版本热更新进已有执行。

### 2.4 唯一和索引

```text
UNIQUE (execution_uuid)

UNIQUE INDEX uk_sync_execution_active_task
    ON sync_execution (task_id)
    WHERE status IN ('PENDING','RUNNING','LOADING','VALIDATING')

INDEX idx_sync_execution_task_history
    ON sync_execution (task_id, created_at DESC, id DESC)

INDEX idx_sync_execution_status
    ON sync_execution (status, created_at, id)

INDEX idx_sync_execution_task_version
    ON sync_execution (task_version_id, created_at DESC, id)

INDEX idx_sync_execution_engine_job
    ON sync_execution (engine_job_id)
    WHERE engine_job_id IS NOT NULL
```

同一任务活动执行唯一约束是计划触发、管理端运行、外部 API 运行和人工重新采集的最终并发保护。重复请求不能依靠内存锁。

### 2.5 状态流转

```text
PENDING
  → RUNNING
  → LOADING
  → VALIDATING
  → SUCCEEDED

PENDING/RUNNING/LOADING/VALIDATING
  → FAILED
  → CANCELLED
```

- 失败和取消不推进水位，不改变任务调度开关。
- 普通失败后没有独立 `RETRY` 状态；人工重新采集创建新的 `RECOLLECT` 执行。
- 不保存 `retry_of_execution_id`、`recollect_of_execution_id` 或 `resume_from_batch_id`。
- 计划调度遇到活动执行时只写应用日志和必要指标，不创建 `SKIPPED` 执行，不建立待追赶状态。

## 3. `load_batch`

职责：保存一次执行中的实际分页游标、Doris Label、事务状态探测和最终载入结果。整次业务时间或主键范围由父 `sync_execution` 保存；本表不是跨执行恢复检查点。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 批次主键 |
| `execution_id` | `bigint` | NOT NULL | FK `sync_execution(id)`，`ON DELETE RESTRICT` |
| `batch_no` | `integer` | NOT NULL | 执行内从 1 递增 |
| `status` | `varchar(20)` | NOT NULL DEFAULT `'PENDING'` | `PENDING/LOADING/PROBING/SUCCEEDED/FAILED/CANCELLED` |
| `cursor_lower` | `jsonb` | NULL | 本批实际 Keyset 游标左边界；增量时为“时间值 + 联合业务主键”规范元组 |
| `cursor_upper` | `jsonb` | NULL | 本批实际 Keyset 游标右边界；通常为本批最后一条规范游标 |
| `institution_code` | `varchar(100)` | NOT NULL | 任务机构编码快照 |
| `source_row_count` | `bigint` | NOT NULL DEFAULT `0` | 本批源端读取行数 |
| `loaded_row_count` | `bigint` | NOT NULL DEFAULT `0` | Doris 最终确认写入行数 |
| `rejected_row_count` | `bigint` | NOT NULL DEFAULT `0` | 本批正式合同拒绝行数 |
| `payload_checksum` | `varchar(128)` | NULL | 本批同步载荷摘要 |
| `checksum_protocol_version` | `varchar(64)` | NOT NULL | 载荷摘要协议版本 |
| `doris_label` | `varchar(128)` | NOT NULL | 确定性 Stream Load Label |
| `doris_txn_id` | `bigint` | NULL | Doris 事务 ID |
| `doris_state` | `varchar(32)` | NULL | `UNKNOWN/PREPARE/COMMITTED/VISIBLE/ABORTED`；尚未取得有效状态时为空 |
| `probe_count` | `integer` | NOT NULL DEFAULT `0` | 本批执行过的 Label 探测次数汇总 |
| `last_probed_at` | `timestamptz` | NULL | 最近探测时间 |
| `submitted_at` | `timestamptz` | NULL | 向 Doris 提交时间 |
| `committed_at` | `timestamptz` | NULL | DFETL 最终确认该 Label 达到 `VISIBLE` 的时间 |
| `error_code` | `varchar(100)` | NULL | 稳定错误码 |
| `error_message` | `varchar(2000)` | NULL | 可直接用于排查的脱敏错误摘要 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |

明确不保存：

```text
phase
time_lower
time_upper
probe_result
batch_type
stage
resume_from_batch_id
next_cursor
```

批次属于哪类执行以及整次固定范围，统一通过：

```text
load_batch.execution_id
→ sync_execution.execution_scope/window_lower/window_upper/key_lower/key_upper
```

取得。

### 3.2 约束

```text
CHECK (batch_no > 0)
CHECK (status IN
       ('PENDING','LOADING','PROBING','SUCCEEDED','FAILED','CANCELLED'))
CHECK (source_row_count >= 0)
CHECK (loaded_row_count >= 0)
CHECK (rejected_row_count >= 0)
CHECK (probe_count >= 0)
CHECK (btrim(institution_code) <> '')
CHECK (btrim(doris_label) <> '')
CHECK (btrim(checksum_protocol_version) <> '')
CHECK (cursor_lower IS NULL OR jsonb_typeof(cursor_lower) = 'object')
CHECK (cursor_upper IS NULL OR jsonb_typeof(cursor_upper) = 'object')
CHECK (doris_state IS NULL OR
       doris_state IN ('UNKNOWN','PREPARE','COMMITTED','VISIBLE','ABORTED'))
CHECK (status <> 'SUCCEEDED' OR doris_state = 'VISIBLE')
CHECK (status <> 'SUCCEEDED' OR committed_at IS NOT NULL)
CHECK (status <> 'SUCCEEDED' OR rejected_row_count = 0)
CHECK (status <> 'FAILED' OR error_code IS NOT NULL)
CHECK (doris_state <> 'ABORTED' OR status = 'FAILED')
```

批次不再拥有时间范围约束。父执行负责约束整次时间或主键范围；应用生成游标时按任务版本中的 Keyset 合同验证结构和字段顺序。

`PROBING` 允许最后 `doris_state` 为 `NULL/UNKNOWN/PREPARE/COMMITTED`；查询到 `VISIBLE` 后必须立即收敛为 `SUCCEEDED`，查询到 `ABORTED` 后必须立即收敛为 `FAILED`。

### 3.3 唯一和索引

```text
UNIQUE (execution_id, batch_no)
UNIQUE (doris_label)

INDEX idx_load_batch_execution_status
    ON load_batch (execution_id, status, batch_no)

INDEX idx_load_batch_probe
    ON load_batch (status, updated_at, id)
    WHERE status IN ('LOADING','PROBING')
```

### 3.4 Doris Label 处理边界

- 第一阶段单 Reader、单个在途写入批次；当前批次确认后才提交下一批。
- 批次类型从父执行 `execution_scope` 推导，不保存重复 `phase`。
- 整次业务时间或主键范围只保存在父执行，不保存批次级 `time_lower/time_upper`。
- 有业务主键的全量和首次全量使用联合业务主键游标。
- 增量和按时间补采使用“增量时间值 + 联合业务主键”的完整有序元组游标。
- 按主键范围补采的整次范围保存在父执行，批次游标保存该范围内实际联合业务键边界。
- 无业务主键流式全量时游标可以为空，不生成假主键。
- Stream Load 明确成功并确认可见时写入 `SUCCEEDED + VISIBLE`。
- `Publish Timeout` 写入 `PROBING + COMMITTED`，继续查询原 Label，不重新提交请求体。
- 客户端超时、连接中断、空响应或响应解析失败均进入 `PROBING`，查询原 Label。
- `PREPARE/COMMITTED` 保持 `PROBING`；`VISIBLE` 收敛为 `SUCCEEDED`；`ABORTED` 收敛为 `FAILED`。
- Label 在限定探测时间内始终为 `UNKNOWN` 时，批次和执行失败，不自动重新提交该批数据。
- Label 查询接口在限定时间内始终无法给出可信结果时，批次和执行失败。
- 失败不推进水位、不进入正式同步校验、不创建消息 Outbox。
- 人工重新采集前必须再次核实旧 Label；旧 Label 仍为 `PREPARE/COMMITTED` 时拒绝盲目重放。
- `load_batch` 不保存下一次执行恢复位置，不提供“从第 N 批继续”。
- 重新采集创建新执行，从该新执行的数据范围起点和第 1 批重新读取。
- 已成功批次不因执行失败、取消或重新采集而删除。

详细规则见：

```text
spec/P0_DORIS_LABEL_PROBE_REVIEW.md
```

### 3.5 清晰错误信息

至少使用以下稳定错误码：

```text
DORIS_STREAM_LOAD_FAILED
DORIS_FILTERED_ROWS
DORIS_LABEL_ABORTED
DORIS_LABEL_UNKNOWN_TIMEOUT
DORIS_LABEL_QUERY_TIMEOUT
DORIS_VISIBILITY_TIMEOUT
```

`load_batch.error_message` 至少包含：

```text
batch_no
doris_label
最后 doris_state
probe_count
submitted_at
last_probed_at
Doris 脱敏错误摘要或最后一次查询异常
系统未自动重投的处理说明
核实旧 Label 后再重新采集的建议动作
```

批次失败导致执行失败时，`sync_execution` 沿用底层稳定错误码，并在错误摘要中增加失败批次号和 Label。

不得写入 Doris 密码、完整 Authorization Header、业务数据或未经脱敏的完整响应体。

### 4.2 约束和外键

### 4.4 固定运行语义

- 只能人工发起，不进入任务 Cron。
- 每次扫描整条链路，不保存单机构运行范围。

### 6.4 结果语义

- 数据一致：`COMPLETED + PASS`。
- 数据不一致：`COMPLETED + MISMATCH`。
- 查询、计算、连接或协议失败：`FAILED`，`result` 为空。
- 同步门禁出现 `MISMATCH` 或 `FAILED` 都使对应 `sync_execution` 失败且不推进水位。
- 独立治理校验失败只记录校验和告警，不回滚历史成功水位。
- 校验内部可以分批计算，但 PostgreSQL 只保存整次最终结果；失败后整次重新校验。
- `difference_summary` 只保存可控的小型汇总，删除键明细保存在 Doris `_dfetl_delete_diff`。
- 汇总直接导出 XLSX/CSV，不建立异步导出任务。

### 7.4 重试和人工重发

- 临时失败增加 `attempt_count`，写最后错误，未耗尽时回 `PENDING` 并覆盖 `available_at`。
- 耗尽 `max_attempts` 后进入 `DEAD_LETTER`。
- 超时 `PUBLISHING` 恢复同样增加 `attempt_count`，不增加租约或工作节点字段。
- 人工重发将 `DEAD_LETTER` 改回 `PENDING`，沿用 `event_id`，设置 `available_at=当前时间`，把 `attempt_count` 重置为 0；人工操作及重置前次数进入 `audit_log`。
- 每次真实发送重新生成 27 位 `messageId`。
- 整段中途失败后不保存分页进度，下次从该发布范围开头重新读取当前 Doris 并重新发布。
- Outbox 失败不改变已经成功的同步执行、水位或任务调度。

### 7.5 数据读取和保留

- 增量优先按原执行/批次标识查询当前 Doris，必要时使用原固定窗口。
- 全量读取原执行任务版本对应目标、任务机构范围内的当前 Doris 全量。
- 后续 UPSERT 可能使重发内容与原执行时不同或减少，这是已确认取舍。
- `PUBLISHED/DEAD_LETTER` 长期保留，不建立自动清理和归档任务。

## 8. 成功收尾原子事务

普通执行、首次全量流程和重新采集完成时使用短 PostgreSQL 事务：

```text
锁定 sync_execution
→ 锁定/准备 task_watermark
→ 确认全部 load_batch 已 SUCCEEDED 且 doris_state=VISIBLE
→ 确认唯一 SYNC_GATE validation_run 为 COMPLETED + PASS
→ 确认 rejected_row_count = 0
→ 更新 sync_execution = SUCCEEDED
→ 按执行固定上界推进或创建 task_watermark（如适用）
→ 如消息策略启用，插入唯一 message_outbox
→ 提交
```

该事务不调用 Doris、RabbitMQ 或其他远程服务。唯一约束负责收敛重复完成请求和重复 Outbox 创建。

## 9. 日志中心边界

P0 不建立 `execution_log_line`、`task_log` 或其他完整日志行表：

- `sync_execution` 保存 `engine_job_id`、错误码和脱敏摘要；
- `load_batch` 保存 DFETL 批次状态、Doris 原始状态、Label、探测次数和错误摘要；
- DFETL 应用日志和 SeaTunnel 引擎日志继续由日志文件或后续日志聚合系统保存；
- 日志中心按 task/execution/engine job 和时间范围查询、合并和下载；
- 日志保留、共享目录和多节点聚合属于部署运维设计，不把日志全文灌入元数据库。

## 10. 已确认：运行前技术检查失败的执行记录边界

固定区分“运行请求尚未被接受”和“运行请求已被接受但技术前检失败”。

### 10.1 无效运行请求不创建执行记录

以下情况在创建 `sync_execution` 前直接拒绝：

```text
任务不存在或已逻辑删除
调用方无权限
请求参数不合法
外部 API requestId 幂等冲突
同一任务已有活动执行
```

此类请求只返回稳定错误码，并按来源写入接口结果、成功/失败操作审计或安全日志；不创建没有实际执行含义的 `sync_execution`。

### 10.2 已接受的运行请求始终保留执行历史

请求身份、权限、参数和活动执行检查通过后，固定流程为：

```text
创建 PENDING sync_execution
→ 固定 task_version_id、执行范围和运行快照
→ 执行源数据源、链路合同、目标 Doris 和必要配置技术前检
→ 前检通过后进入 RUNNING/LOADING
→ 前检失败时更新为 FAILED
```

技术前检失败包括但不限于：

```text
源或目标数据源已停用
源数据库连接失败
目标 Doris 连接失败
源对象不存在
链路字段解析合同不可执行
Doris 实际结构与任务合同不一致
必要部署配置缺失
```

失败执行必须保存：

- 固定任务版本；
- 触发来源和发起人/client；
- 失败时间；
- 稳定 `error_code`；
- 脱敏 `error_message`；
- 已固化的小型执行快照。

不增加 `PRECHECKING` 等额外状态。技术前检期间保持 `PENDING`，开始实际执行后进入 `RUNNING`；前检失败直接从 `PENDING` 转为 `FAILED`。

预检事实不属于技术门禁：`MISSING/ISSUES/STALE` 只写入 `precheck_fact_snapshot` 并展示，不导致本次技术前检失败。

该规则保证任务监控能够看到每一次真正被系统接受的运行请求及其失败原因，同时避免为无效或并发冲突请求制造执行记录。
