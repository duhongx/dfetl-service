## 2. `sync_execution`

职责：保存一次真实同步运行的任务身份、启动时执行配置快照、触发来源、固定数据范围、运行状态、统计和错误摘要。

`sync_task` 可以在没有活动同步执行时直接修改，因此历史运行不能回读当前任务值解释；本表必须保存本次真正使用的配置。

状态时间：

```text
CHECK (
  (status IN ('PENDING','RUNNING','LOADING','VALIDATING') AND finished_at IS NULL)
  OR
  (status IN ('SUCCEEDED','FAILED','CANCELLED') AND finished_at IS NOT NULL)
)
CHECK (status <> 'SUCCEEDED' OR rejected_row_count = 0)
CHECK (status <> 'FAILED' OR error_code IS NOT NULL)
CHECK (finished_at IS NULL OR started_at IS NULL OR finished_at >= started_at)
```

取消请求不增加 `CANCELLING` 状态。工作线程发现取消请求后停止后续读取，先确认在途 Doris Label，再进入 `CANCELLED`。

### 2.4 外键和身份一致性

```text
FOREIGN KEY (task_id, institution_id, dataset_id)
REFERENCES sync_task(id, institution_id, dataset_id)
ON DELETE RESTRICT

FOREIGN KEY (route_version_id, institution_id)

ON DELETE RESTRICT

REFERENCES collection_route_version(id, dataset_id)
ON DELETE RESTRICT

FOREIGN KEY (route_version_id, dataset_version_id)
REFERENCES collection_route_version(id, dataset_version_id)
```

`incremental_field_code` 为空时最后一条外键不触发。

执行记录保存后只读取自身快照和不可变版本，不回读当前 `sync_task` 替换历史配置。

### 2.5 唯一和索引

```text
UNIQUE (execution_uuid)

UNIQUE INDEX uk_sync_execution_active_task
    ON sync_execution (task_id)
    WHERE status IN ('PENDING','RUNNING','LOADING','VALIDATING')

INDEX idx_sync_execution_task_history
    ON sync_execution (task_id, created_at DESC, id DESC)

INDEX idx_sync_execution_status
    ON sync_execution (status, created_at, id)

INDEX idx_sync_execution_dataset_history
    ON sync_execution (dataset_id, institution_id, created_at DESC, id DESC)

INDEX idx_sync_execution_engine_job
    ON sync_execution (engine_job_id)
    WHERE engine_job_id IS NOT NULL

INDEX idx_sync_execution_external_request
    ON sync_execution (external_client_id, external_request_id)
    WHERE external_client_id IS NOT NULL
      AND external_request_id IS NOT NULL
```

同任务活动执行部分唯一索引是所有触发来源的最终并发兜底。同步启动还要在锁定 `sync_task` 后检查活动独立校验。

### 2.6 状态流转

```text
PENDING
  → RUNNING
  → LOADING
  → VALIDATING
  → SUCCEEDED

PENDING/RUNNING/LOADING/VALIDATING
  → FAILED
  → CANCELLED
```

- 失败和取消不推进水位，不改变任务调度开关。
- 普通失败后没有 `RETRY` 状态；人工重新采集创建新的 `RECOLLECT` 执行。
- 不保存 `retry_of_execution_id`、`recollect_of_execution_id` 或 `resume_from_batch_id`。
- 计划调度遇到活动同步或活动独立校验时只写应用日志和指标，不创建 `SKIPPED` 执行，不建立追赶状态。

## 3. `load_batch`

职责：保存一次执行中的实际分页游标、Doris Label、事务状态探测和最终载入结果。整次业务范围和机构身份从父执行取得；本表不是跨执行恢复检查点。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 批次主键 |
| `execution_id` | `bigint` | NOT NULL | FK `sync_execution(id)`，`ON DELETE RESTRICT` |
| `batch_no` | `integer` | NOT NULL | 执行内从 1 递增 |
| `status` | `varchar(20)` | NOT NULL DEFAULT `'PENDING'` | `PENDING/LOADING/PROBING/SUCCEEDED/FAILED/CANCELLED` |
| `cursor_lower` | `jsonb` | NULL | 本批实际 Keyset 游标左边界 |
| `cursor_upper` | `jsonb` | NULL | 本批实际 Keyset 游标右边界 |
| `source_row_count` | `bigint` | NOT NULL DEFAULT `0` | 本批源端读取行数 |
| `loaded_row_count` | `bigint` | NOT NULL DEFAULT `0` | Doris 最终确认可见行数 |
| `rejected_row_count` | `bigint` | NOT NULL DEFAULT `0` | 本批正式合同拒绝行数 |
| `payload_checksum` | `varchar(128)` | NULL | 本批载荷摘要；协议版本从父执行取得 |
| `doris_label` | `varchar(128)` | NOT NULL | 确定性 Stream Load Label |
| `doris_txn_id` | `bigint` | NULL | Doris 事务 ID |
| `doris_state` | `varchar(32)` | NULL | `UNKNOWN/PREPARE/COMMITTED/VISIBLE/ABORTED` |
| `probe_count` | `integer` | NOT NULL DEFAULT `0` | Label 探测次数 |
| `last_probed_at` | `timestamptz` | NULL | 最近探测时间 |
| `submitted_at` | `timestamptz` | NULL | 向 Doris 提交时间 |
| `visible_at` | `timestamptz` | NULL | DFETL 最终确认 Label 达到 `VISIBLE` 的时间 |
| `error_code` | `varchar(100)` | NULL | 稳定错误码 |
| `error_message` | `varchar(2000)` | NULL | 可直接排查的脱敏错误摘要 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |

明确不保存：

```text
phase
time_lower
time_upper
probe_result
institution_code
checksum_protocol_version
batch_type
stage
resume_from_batch_id
next_cursor
```

这些值均可从父 `sync_execution` 或批次当前事实取得，不重复保存。

### 3.2 约束

```text
CHECK (batch_no > 0)
CHECK (status IN
       ('PENDING','LOADING','PROBING','SUCCEEDED','FAILED','CANCELLED'))
CHECK (source_row_count >= 0)
CHECK (loaded_row_count >= 0)
CHECK (rejected_row_count >= 0)
CHECK (probe_count >= 0)
CHECK (btrim(doris_label) <> '')
CHECK (cursor_lower IS NULL OR jsonb_typeof(cursor_lower) = 'object')
CHECK (cursor_upper IS NULL OR jsonb_typeof(cursor_upper) = 'object')
CHECK (doris_state IS NULL OR
       doris_state IN ('UNKNOWN','PREPARE','COMMITTED','VISIBLE','ABORTED'))
CHECK (status <> 'SUCCEEDED' OR doris_state = 'VISIBLE')
CHECK (status <> 'SUCCEEDED' OR visible_at IS NOT NULL)
CHECK (status <> 'SUCCEEDED' OR rejected_row_count = 0)
CHECK (status <> 'FAILED' OR error_code IS NOT NULL)
CHECK (doris_state <> 'ABORTED' OR status = 'FAILED')
```

`PROBING` 允许 `doris_state` 为 `NULL/UNKNOWN/PREPARE/COMMITTED`。查询到 `VISIBLE` 后立即收敛为 `SUCCEEDED`；查询到 `ABORTED` 后立即收敛为 `FAILED`。

### 3.3 唯一和索引

```text
UNIQUE (execution_id, batch_no)
UNIQUE (doris_label)

INDEX idx_load_batch_execution_status
    ON load_batch (execution_id, status, batch_no)

INDEX idx_load_batch_probe
    ON load_batch (status, updated_at, id)
    WHERE status IN ('LOADING','PROBING')
```

### 3.4 固定运行边界

- 第一阶段单 Reader、单个在途写入批次；当前批次确认后才提交下一批。
- 批次类型和整次范围从父执行取得。
- 有业务主键的全量使用联合业务主键游标。
- 增量和按时间补采使用“增量时间值 + 联合业务主键”复合游标。
- 无业务主键流式全量允许游标为空。
- `Publish Timeout`、客户端超时、空响应或响应解析失败只探测原 Label，不重新提交。
- `PREPARE/COMMITTED` 保持 `PROBING`；`VISIBLE` 才成功；`ABORTED` 失败。
- Label 在限定时间内始终 `UNKNOWN` 或持续不可查询时，批次和执行失败。
- 失败不推进水位、不进入正式校验、不创建 Outbox。
- 人工重新采集前再次核实旧 Label。
- 批次游标只用于诊断和追溯，不作为下一次执行恢复位置。

### 3.5 清晰错误信息

至少使用：

```text
DORIS_STREAM_LOAD_FAILED
DORIS_FILTERED_ROWS
DORIS_LABEL_ABORTED
DORIS_LABEL_UNKNOWN_TIMEOUT
DORIS_LABEL_QUERY_TIMEOUT
DORIS_VISIBILITY_TIMEOUT
```

错误摘要至少包含批次号、Label、最后 Doris 状态、探测次数、提交和最近探测时间、脱敏异常、未自动重投说明及人工处理建议。

### 6.4 运行和编辑边界

- 同步启动与独立校验启动锁定同一 `sync_task`，两类运行互斥。
- 同一任务最多一条活动独立校验。
- 独立校验启动时形成完整 `context_snapshot/range_snapshot`。
- 独立校验启动后允许用户修改任务普通配置；当前校验不热更新。
- 任务编辑与校验启动并发时，本次校验只采用完整的编辑前或编辑后配置。
- `SYNC_GATE` 是父同步执行内部步骤，不受独立校验唯一索引阻止。
- 定期治理冲突只跳过，不创建运行记录，不补跑。

### 6.5 结果语义

- 数据一致：`COMPLETED + PASS`。
- 数据不一致：`COMPLETED + MISMATCH`。
- 查询、计算、连接或协议失败：`FAILED`，`result` 为空。
- 同步门禁 `MISMATCH/FAILED` 都使父执行失败且不推进水位。
- 独立治理校验结果不回写历史执行，不改变已提交水位。
- 校验内部可以分批计算，但 PostgreSQL 只保存整次最终结果。
- 差异汇总直接导出，不建立异步导出任务。

### 7.4 重试和人工重发

- 临时失败增加 `attempt_count`，未耗尽时回 `PENDING` 并覆盖 `available_at`。
- 耗尽后进入 `DEAD_LETTER`。
- 超时 `PUBLISHING` 恢复同样增加次数，不增加租约或工作节点字段。
- 人工重发沿用 `event_id`、重置 `attempt_count=0`，操作进入 `audit_log`。
- 每次真实发送重新生成 27 位 `messageId`。
- 整段中途失败后不保存分页进度，下次从发布范围开头重新读取当前 Doris。
- Outbox 失败不改变已成功执行、水位或任务调度。

### 7.5 数据读取和保留

- 增量优先按原执行/批次标识查询当前 Doris，必要时使用原固定窗口。
- 全量根据原执行快照中的数据集、链路目标和机构范围读取当前 Doris 全量。
- 后续 UPSERT 可能使重发内容发生变化，这是已确认取舍。
- `PUBLISHED/DEAD_LETTER` 长期保留，不自动清理或归档。

## 8. 成功收尾原子事务

普通执行、首次全量和重新采集完成时使用短 PostgreSQL 事务：

```text
锁定 sync_execution
→ 锁定/准备 task_watermark
→ 确认全部 load_batch = SUCCEEDED 且 doris_state = VISIBLE
→ 确认唯一 SYNC_GATE validation_run = COMPLETED + PASS
→ 确认 rejected_row_count = 0
→ 更新 sync_execution = SUCCEEDED
→ 按执行固定范围创建或推进 task_watermark（如适用）
→ 如消息策略启用，按执行快照插入唯一 message_outbox
→ 提交
```

该事务不调用 Doris、RabbitMQ 或其他远程服务。唯一约束负责收敛重复完成请求和重复 Outbox 创建。

## 9. 日志中心边界

P0 不建立 `execution_log_line`、`task_log` 或完整日志行表：

- `sync_execution` 保存 `engine_job_id`、错误码和脱敏摘要；
- `load_batch` 保存批次状态、Doris 状态、Label、探测次数和错误摘要；
- 应用日志和 SeaTunnel 日志由文件或日志聚合系统保存；
- 日志中心按 task/execution/engine job 和时间范围查询、合并和下载；
- 不把日志全文灌入元数据库。

## 10. 运行前技术检查失败的执行记录边界

### 10.1 无效请求不创建执行

以下情况在创建 `sync_execution` 前直接拒绝：

```text
任务不存在或已逻辑删除
调用方无权限
请求参数不合法
外部 API requestId 幂等冲突
同一任务已有活动同步执行
同一任务已有活动独立校验
```

此类请求返回稳定错误码并写对应审计或日志，不制造执行记录。

### 10.2 已接受请求保留执行历史

请求身份、权限、参数和运行互斥检查通过后：

```text
锁定 sync_task
→ 读取当前任务、数据集、链路、校验和消息配置
→ 创建 PENDING sync_execution 并固定完整启动快照
→ 执行源连接、链路合同、Doris 结构和必要配置技术前检
→ 前检通过后进入 RUNNING/LOADING
→ 前检失败时更新为 FAILED
```

技术前检失败执行仍保存：

- 任务 ID 和启动时 task revision；
- 机构、数据集版本和链路版本；
- 任务类型、读取和写入合同；
- 触发来源和发起人/client；
- 校验和消息策略快照；
- 失败时间、稳定错误码和脱敏摘要。

不增加 `PRECHECKING` 状态。预检 `MISSING/ISSUES/STALE` 只是事实展示，不导致技术前检失败。
