## 1. 本批次范围

本批次完成以下目标对象的字段、关系、状态、默认值、外键、唯一约束和索引设计：

```text
standard_dataset
standard_dataset_version
standard_dataset_field
field_conversion_contract
field_conversion_rule
generic_jdbc_type_mapping
dataset_sync_policy
global_validation_policy
dataset_validation_policy
dataset_message_policy
```

其中 `field_conversion_contract` 是版本头，`field_conversion_rule` 是该版本下的不可变规则集合。逻辑模型中的“字段转换合同”在物理层拆成两张表，以便数据集版本可以对一个完整合同版本建立真实外键，而不是引用一组无法约束的自由规则行。

本批次固定结论：

1. 标准数据集只能从医共体规范库人工同步，不提供手工新增或删除。
2. 数据集身份与不可变定义版本分离；只有规范化定义 Hash 变化时才新增版本。
3. 数据集从权威来源消失时标记为 `VOID`，不删除历史版本、链路、任务和运行记录。
4. 字段版本行只插入不更新；不保留“当前字段行 + VOID 字段”的旧模型。
5. 标准字段编码保存为大写，Doris 业务列名由其小写形式确定；不提供人工重命名字段。
6. 未知或无法解析的医疗字段类型可以被如实保存为 `UNSUPPORTED`，不得回退为 `VARCHAR(256)`；正式执行在写入前失败。
7. 数据集同步策略不再保存可由合同确定的 `write_mode`、`sync_template`、业务主键或增量字段。
8. Reader 并发固定为 1，不进入策略表。
9. 正式同步校验默认启用、方法为 `ROW_COUNT`、容差和回看均为 0；自动复检和可配置 `fail_block` 字段删除。
10. 消息策略只保存在数据集级，默认关闭；不保存 transport、Exchange、全量模式、TRUNCATE 信号或任务级副本。
11. 预检风险展示的全局/数据集/任务继承属于治理策略，物理字段将在后续“任务和治理覆盖”批次与 `task_governance_override` 一并闭环，不混入同步、校验或消息表。

## 2. 数据集同步事务

一次管理员人工同步按以下事务边界执行：

```text
读取医共体规范库完整定义
→ 校验本次结果非空、数据集身份和字段身份不重复
→ 使用当前 ACTIVE 字段转换合同规范化定义
→ 计算 definition_hash
→ 锁定 standard_dataset 身份行
→ Hash 未变化：只更新同步时间和结果
→ Hash 变化：插入 version 和全部 field 行
→ 延迟外键校验通过
→ 切换 current_version_id
→ 提交
```

固定规则：

- 本次规范库读取结果为空时，整次同步失败，不能把全部本地数据集批量作废。
- 同一次同步中的外部数据集 ID、数据集编码、字段 ID、字段编码和顺序号必须唯一。
- Hash 必须覆盖数据集业务身份、源定义版本、字段顺序、标准类型/格式、空值、业务主键顺序、值域、转换合同版本、转换规则及最终 Doris 类型。
- 只有规范化内容发生变化时新增版本；单纯重复点击同步不产生空版本。
- 新版本插入、字段插入和当前版本指针切换在一个事务完成。
- 数据集版本和字段版本永不原地更新；错误的已提交版本通过新的版本修正。
- 同步成功或失败均记录操作审计。失败时保存错误码和脱敏摘要，不保存规范库密码或完整连接串。

## 3. `standard_dataset`

职责：标准数据集长期身份和当前版本指针。

### 3.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 内部主键 |
| `external_dataset_id` | `varchar(64)` | NOT NULL | 医共体规范库中的稳定数据集 ID |
| `dataset_code` | `varchar(100)` | NOT NULL | 标准数据集编码，保存规范化大写值 |
| `name` | `varchar(200)` | NOT NULL | 数据集名称 |
| `status` | `varchar(16)` | NOT NULL DEFAULT `'ACTIVE'` | `ACTIVE/VOID` |
| `current_version_id` | `bigint` | NULL | 当前不可变版本；首次版本写入同一事务后必须非空 |
| `first_imported_at` | `timestamptz` | NOT NULL | 首次成功导入时间 |
| `last_synced_at` | `timestamptz` | NOT NULL | 最近一次同步处理时间 |
| `last_sync_result` | `varchar(20)` | NOT NULL | `CREATED/UPDATED/UNCHANGED/REACTIVATED/VOIDED/FAILED` |
| `last_sync_error` | `varchar(1000)` | NULL | 最近失败的脱敏错误摘要；成功时清空 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 当前指针和同步摘要的乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 身份行创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 最近身份行更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 3.2 约束

```text
CHECK (btrim(external_dataset_id) <> '')
CHECK (dataset_code = upper(btrim(dataset_code)))
CHECK (btrim(dataset_code) <> '')
CHECK (btrim(name) <> '')
CHECK (status IN ('ACTIVE','VOID'))
CHECK (last_sync_result IN
       ('CREATED','UPDATED','UNCHANGED','REACTIVATED','VOIDED','FAILED'))
CHECK (revision >= 0)
CHECK ((last_sync_result = 'FAILED') OR last_sync_error IS NULL)
```

当前版本同父约束：

```text
FOREIGN KEY (id, current_version_id)
REFERENCES standard_dataset_version(dataset_id, id)
DEFERRABLE INITIALLY DEFERRED
```

`current_version_id` 初次插入身份行时可以暂时为空；事务结束前必须已经写入第一个版本并完成指针切换。服务读取到 `ACTIVE + current_version_id IS NULL` 时视为元数据损坏并拒绝继续。

### 3.3 唯一与索引

```text
UNIQUE (external_dataset_id)

UNIQUE INDEX uk_standard_dataset_code_ci
    ON standard_dataset (lower(dataset_code))

INDEX idx_standard_dataset_status_code
    ON standard_dataset (status, dataset_code, id)

INDEX idx_standard_dataset_name_ci
    ON standard_dataset (lower(name), id)

INDEX idx_standard_dataset_last_synced
    ON standard_dataset (last_synced_at DESC, id)
```

### 3.4 生命周期

- 不提供手工新增、物理删除和手工作废接口。
- 权威来源本次不存在的数据集改为 `VOID`，保留 `current_version_id` 和全部历史。
- 作废数据集不能用于新建链路或任务，已有运行中执行按启动时快照完成；后续维护由管理员处理。
- 同一外部 ID 再次出现时恢复为 `ACTIVE`。定义 Hash 未变化时不新增版本；变化时新增版本后切换指针。
- 数据集身份一旦被链路、任务、策略或历史引用，不允许物理删除。

## 4. `standard_dataset_version`

职责：保存一次规范化后的完整数据集定义版本。只插入，不保存 `DRAFT/PUBLISHED/SUPERSEDED` 状态。

### 4.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 版本主键 |
| `dataset_id` | `bigint` | NOT NULL | FK `standard_dataset(id)`，`ON DELETE RESTRICT` |
| `version_no` | `integer` | NOT NULL | 父数据集内从 1 递增 |
| `source_definition_version` | `varchar(100)` | NULL | 规范库提供的版本号快照 |
| `definition_hash` | `char(64)` | NOT NULL | 规范化定义 SHA-256 |
| `conversion_contract_version` | `varchar(64)` | NOT NULL | FK `field_conversion_contract(contract_version)`，`ON DELETE RESTRICT` |
| `institution_code_field_code` | `varchar(100)` | NOT NULL | 标准医疗机构代码字段编码 |
| `incremental_field_code` | `varchar(100)` | NULL | 当前有效时间增量字段；没有时为空 |
| `field_count` | `integer` | NOT NULL | 字段总数 |
| `business_key_count` | `integer` | NOT NULL | 包含机构代码后的联合业务主键字段数；无业务主键数据集为 0 |
| `imported_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 版本导入时间 |
| `imported_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 4.2 约束

```text
CHECK (version_no > 0)
CHECK (definition_hash ~ '^[0-9a-f]{64}$')
CHECK (institution_code_field_code = upper(btrim(institution_code_field_code)))
CHECK (incremental_field_code IS NULL OR
       incremental_field_code = upper(btrim(incremental_field_code)))
CHECK (field_count > 0)
CHECK (business_key_count >= 0 AND business_key_count <= field_count)
```

唯一与父指针支撑约束：

```text
UNIQUE (dataset_id, version_no)
UNIQUE (dataset_id, definition_hash)
UNIQUE (dataset_id, id)
```

字段归属延迟外键：

```text
FOREIGN KEY (id, institution_code_field_code)
REFERENCES standard_dataset_field(dataset_version_id, field_code)
DEFERRABLE INITIALLY DEFERRED

FOREIGN KEY (id, incremental_field_code)
REFERENCES standard_dataset_field(dataset_version_id, field_code)
DEFERRABLE INITIALLY DEFERRED
```

`incremental_field_code` 为空时不校验。这样能够由数据库保证机构字段和增量字段确实属于同一版本，而不是只保存一个可能拼错的字符串。

### 4.3 跨字段规则

同步服务在提交事务前验证：

1. `field_count` 等于该版本实际字段行数。
2. `business_key_ordinal` 非空的行数等于 `business_key_count`。
3. 业务主键顺序连续为 `1..N`，没有重复和空洞。
4. `institution_code_field_code` 唯一命中一个字段。
5. 当 `business_key_count > 0` 时，机构代码字段必须在联合业务主键中；无业务主键时机构代码只承担范围过滤。
6. `incremental_field_code` 如存在，必须是当前合同支持的日期时间字段，并且当前数据集有真实业务主键。
7. 无业务主键时任务类型固定为 `FULL_ONLY + REPLACE_INSTITUTION_SCOPE`，不能因技术字段生成假主键。
8. 定义 Hash 必须使用数据库中即将提交的规范化字段顺序和合同值重新核对。

### 4.4 不可变性

- 版本行和字段行在创建事务完成后禁止 UPDATE/DELETE。
- `status` 不进入版本表；是否当前只由 `standard_dataset.current_version_id` 表达。
- 已被链路版本或任务版本引用的版本始终保留。
- 转换合同升级不会原地改写旧版本；管理员再次同步定义并在规范化内容变化时生成新数据集版本。

## 5. `standard_dataset_field`

职责：某个数据集版本中的不可变标准字段定义和已解析 Doris 合同。

### 5.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 字段版本主键 |
| `dataset_version_id` | `bigint` | NOT NULL | FK `standard_dataset_version(id)`，`ON DELETE RESTRICT` |
| `external_field_id` | `varchar(64)` | NOT NULL | 规范库字段 ID 快照 |
| `field_code` | `varchar(100)` | NOT NULL | 标准字段编码，大写 |
| `field_name` | `varchar(200)` | NULL | 字段名称 |
| `ordinal_no` | `integer` | NOT NULL | 标准定义字段顺序，从 1 开始 |
| `standard_type` | `varchar(30)` | NOT NULL | 医疗标准类型代码 |
| `standard_format` | `varchar(100)` | NULL | 原始标准格式，例如 `AN..50`、`N..15,3` |
| `declared_length` | `integer` | NULL | 解析后的逻辑长度 |
| `declared_precision` | `integer` | NULL | 解析后的数值精度 |
| `declared_scale` | `integer` | NULL | 解析后的小数位 |
| `standard_nullable` | `boolean` | NOT NULL | 规范定义是否允许空 |
| `business_key_ordinal` | `smallint` | NULL | 联合业务主键顺序；非主键为空 |
| `value_domain_code` | `varchar(100)` | NULL | 值域编码快照 |
| `conversion_rule_code` | `varchar(100)` | NULL | 实际命中的字段转换规则；未支持时为空 |
| `conversion_status` | `varchar(16)` | NOT NULL | `RESOLVED/UNSUPPORTED` |
| `doris_type` | `varchar(128)` | NULL | 最终 Doris 类型；未支持时为空 |
| `doris_nullable` | `boolean` | NULL | 最终 Doris 空值合同；未支持时为空 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 版本字段创建时间 |

字段使用数据集版本的 `conversion_contract_version`。`conversion_rule_code` 与版本号共同定位 `field_conversion_rule`，不复制可变规则文本。

### 5.2 约束

```text
CHECK (btrim(external_field_id) <> '')
CHECK (field_code = upper(btrim(field_code)))
CHECK (btrim(field_code) <> '')
CHECK (ordinal_no > 0)
CHECK (btrim(standard_type) <> '')
CHECK (declared_length IS NULL OR declared_length > 0)
CHECK (declared_precision IS NULL OR declared_precision > 0)
CHECK (declared_scale IS NULL OR declared_scale >= 0)
CHECK (declared_precision IS NULL OR declared_scale IS NULL OR
       declared_scale <= declared_precision)
CHECK (business_key_ordinal IS NULL OR business_key_ordinal > 0)
CHECK (business_key_ordinal IS NULL OR standard_nullable = false)
CHECK (conversion_status IN ('RESOLVED','UNSUPPORTED'))
CHECK (
  (conversion_status = 'RESOLVED'
    AND conversion_rule_code IS NOT NULL
    AND doris_type IS NOT NULL
    AND doris_nullable IS NOT NULL)
  OR
  (conversion_status = 'UNSUPPORTED'
    AND conversion_rule_code IS NULL
    AND doris_type IS NULL
    AND doris_nullable IS NULL)
)
```

唯一与查询索引：

```text
UNIQUE (dataset_version_id, external_field_id)
UNIQUE (dataset_version_id, field_code)
UNIQUE (dataset_version_id, ordinal_no)

UNIQUE INDEX uk_dataset_field_business_key_order
    ON standard_dataset_field (dataset_version_id, business_key_ordinal)
    WHERE business_key_ordinal IS NOT NULL

INDEX idx_dataset_field_order
    ON standard_dataset_field (dataset_version_id, ordinal_no, id)

INDEX idx_dataset_field_conversion_status
    ON standard_dataset_field (dataset_version_id, conversion_status, ordinal_no)
```

### 5.3 Doris 字段名和未知合同

- Doris 业务字段名不额外持久化，固定为 `lower(field_code)`；页面和执行通过合同函数生成。
- 标准字段与源 JDBC 字段只允许大小写差异；真实 JDBC 字段名在链路版本的 `route_field_resolution` 中保存。
- `UNSUPPORTED` 是可以查询和展示的真实定义状态，不把未知类型替换为兜底类型。
- 预检结构阶段展示未支持类型；任务创建仍可展示风险。正式执行、Doris 建表或重建在使用该版本时必须明确失败。
- 医疗 `L`、`B/BY`、数值和日期时间的最终类型及规范化规则全部由版本化转换合同提供，不能由页面自由修改 `doris_type`。

## 6. `field_conversion_contract`

职责：字段转换合同版本头。一个版本包含一组不可变规则。

### 6.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `contract_version` | `varchar(64)` | PK | 稳定版本，例如 `MEDICAL_DORIS_V1` |
| `status` | `varchar(16)` | NOT NULL | `ACTIVE/RETIRED` |
| `contract_hash` | `char(64)` | NOT NULL | 全部规则规范化后的 SHA-256 |
| `description` | `text` | NULL | 版本说明 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `retired_at` | `timestamptz` | NULL | 停止用于新数据集同步的时间 |
| `retired_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 6.2 约束和索引

```text
CHECK (btrim(contract_version) <> '')
CHECK (status IN ('ACTIVE','RETIRED'))
CHECK (contract_hash ~ '^[0-9a-f]{64}$')
CHECK ((status = 'ACTIVE' AND retired_at IS NULL AND retired_by IS NULL)
    OR (status = 'RETIRED' AND retired_at IS NOT NULL))

UNIQUE (contract_hash)
UNIQUE INDEX uk_field_conversion_contract_active
    ON field_conversion_contract ((1))
    WHERE status = 'ACTIVE'
```

固定规则：

- 同一时间只允许一个合同版本用于新数据集同步。
- 合同版本发布后，版本头和规则不可修改；新规则通过新合同版本发布。
- 退休只影响后续人工同步，已经引用该版本的数据集、链路、任务和执行继续可追溯。
- 被数据集版本引用的合同不可物理删除。

## 7. `field_conversion_rule`

职责：字段转换合同版本中的不可变选择和转换规则。

### 7.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 规则主键 |
| `contract_version` | `varchar(64)` | NOT NULL | FK `field_conversion_contract(contract_version)`，`ON DELETE CASCADE` |
| `rule_code` | `varchar(100)` | NOT NULL | 合同版本内稳定规则编码 |
| `priority` | `integer` | NOT NULL DEFAULT `0` | 匹配优先级，值越大越优先 |
| `medical_type` | `varchar(30)` | NOT NULL | 医疗标准类型选择器 |
| `format_pattern` | `varchar(256)` | NULL | 标准格式正则；为空表示该类型默认规则 |
| `key_scope` | `varchar(16)` | NOT NULL DEFAULT `'ANY'` | `ANY/KEY/NON_KEY` |
| `doris_type_template` | `varchar(128)` | NOT NULL | Doris 类型模板，例如 `VARCHAR({bytes})` |
| `normalization_rule_code` | `varchar(100)` | NOT NULL | Reader/主键规范化规则编码 |
| `checksum_rule_code` | `varchar(100)` | NOT NULL | Checksum 规范化规则编码 |
| `validation_rule_code` | `varchar(100)` | NOT NULL | 预检/正式写入校验规则编码 |
| `description` | `text` | NULL | 规则说明 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |

### 7.2 约束与索引

```text
CHECK (btrim(rule_code) <> '')
CHECK (btrim(medical_type) <> '')
CHECK (priority >= 0)
CHECK (key_scope IN ('ANY','KEY','NON_KEY'))
CHECK (btrim(doris_type_template) <> '')
CHECK (btrim(normalization_rule_code) <> '')
CHECK (btrim(checksum_rule_code) <> '')
CHECK (btrim(validation_rule_code) <> '')

UNIQUE (contract_version, rule_code)

INDEX idx_conversion_rule_match
    ON field_conversion_rule
       (contract_version, medical_type, key_scope, priority DESC, id)
```

应用发布合同前必须完成：

- 同一输入在一个合同版本内只能命中一个最高优先级规则；歧义时拒绝发布。
- 所有模板变量均可由标准类型/格式解析结果确定。
- 主键规则不能生成 Doris `STRING` 或超出 key 限制的无界类型。
- `L` 必须生成 Doris `BOOLEAN` 并接受标准 `0/1`；`B/BY` 必须生成 Doris `STRING` 并使用标准 Base64 规范化。
- 未知类型或格式无规则命中时，字段保存为 `UNSUPPORTED`，不执行隐式 fallback。

## 9. `dataset_sync_policy`

职责：某个标准数据集创建新任务或显式生成新任务版本时使用的执行类默认值。它不是已有任务的热更新配置。

### 9.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `dataset_id` | `bigint` | PK/FK | FK `standard_dataset(id)`，`ON DELETE CASCADE` |
| `fetch_size` | `integer` | NOT NULL DEFAULT `5000` | Reader Fetch Size；Reader 并发固定为 1 |
| `upper_bound_delay_minutes` | `integer` | NOT NULL DEFAULT `5` | 增量上界延迟 |
| `lookback_seconds` | `integer` | NOT NULL DEFAULT `0` | 特殊源端回看窗口；默认不回看 |
| `schedule_mode` | `varchar(20)` | NOT NULL DEFAULT `'INHERIT'` | `INHERIT/MANUAL/EVERY_N_HOURS/CRON` |
| `schedule_interval_hours` | `integer` | NULL | `EVERY_N_HOURS` 时必填 |
| `schedule_cron` | `varchar(128)` | NULL | `CRON` 时必填 |
| `schedule_timezone` | `varchar(64)` | NULL | 非 `INHERIT` 时必填 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

全局默认调度仍是每 4 小时和默认自动错峰，由已注册系统设置提供。`INHERIT` 表示新任务创建时读取全局默认并固化到任务版本。

### 9.2 约束

```text
CHECK (fetch_size BETWEEN 1 AND 1000000)
CHECK (upper_bound_delay_minutes BETWEEN 0 AND 1440)
CHECK (lookback_seconds BETWEEN 0 AND 2592000)
CHECK (schedule_mode IN ('INHERIT','MANUAL','EVERY_N_HOURS','CRON'))
CHECK (revision >= 0)

CHECK (
  (schedule_mode = 'INHERIT'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NULL
    AND schedule_timezone IS NULL)
  OR
  (schedule_mode = 'MANUAL'
    AND schedule_interval_hours IS NULL
    AND schedule_cron IS NULL
    AND schedule_timezone IS NOT NULL)
  OR
  (schedule_mode = 'EVERY_N_HOURS'
    AND schedule_interval_hours BETWEEN 1 AND 8760
    AND schedule_cron IS NULL
    AND schedule_timezone IS NOT NULL)
  OR
  (schedule_mode = 'CRON'
    AND schedule_interval_hours IS NULL
    AND btrim(schedule_cron) <> ''
    AND schedule_timezone IS NOT NULL)
)
```

索引只需要主键。数据集策略按数据集详情读取，不建立低选择度状态索引。

### 9.3 明确删除和生效边界

本表不保存：

```text
write_mode
sync_template
incremental_field
increment_mode
reader_parallelism
任务运行状态
```

- 任务种类、写入方式、Doris key 模型和增量字段由不可变数据集合同确定。
- `fetch_size`、上界延迟和回看窗口属于执行合同。修改数据集默认值不会自动影响已有任务；管理员需要查看差异并显式生成任务新版本。
- 调度修改同样通过任务当前版本和 Quartz 投影应用，不直接用数据集策略驱动已存在的 Trigger。
- 策略更新成功和失败都写操作审计。

## 10. `global_validation_policy`

职责：正式同步校验的全局默认。P0 只有一行，不建设任意多套策略模板。

### 10.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `smallint` | PK，固定为 `1` | 单例行 |
| `enabled` | `boolean` | NOT NULL DEFAULT `true` | 正式同步默认自动校验 |
| `validation_method` | `varchar(32)` | NOT NULL DEFAULT `'ROW_COUNT'` | `ROW_COUNT/ROW_COUNT_CHECKSUM` |
| `row_tolerance` | `numeric(8,4)` | NOT NULL DEFAULT `0` | 百分比容差，默认零 |
| `lookback_hours` | `integer` | NOT NULL DEFAULT `0` | 默认不回看 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 10.2 约束

```text
CHECK (id = 1)
CHECK (validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (row_tolerance >= 0 AND row_tolerance <= 100)
CHECK (lookback_hours BETWEEN 0 AND 8760)
CHECK (revision >= 0)
```

不保存：

```text
trigger_mode
fail_block
revalidate_enabled
revalidate_delay
```

固定语义：

- 与同步执行绑定的最终校验始终在写入后执行；开启时不一致或技术失败均阻止执行成功和水位推进。
- 默认自动复检关闭；人工重新校验新建独立 `validation_run`。
- 无业务主键数据集不能使用 `ROW_COUNT_CHECKSUM`。若全局方法配置为该值，无主键任务在策略解析时明确回退到其唯一支持的 `ROW_COUNT` 并把来源记录为合同强制值，而不是执行中静默降级。

| `validation_method` | `varchar(32)` | NULL | 覆盖时必填 |
| `row_tolerance` | `numeric(8,4)` | NULL | 覆盖时必填 |
| `lookback_hours` | `integer` | NULL | 覆盖时必填 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |

### 11.2 约束

```text
CHECK (override_mode IN ('INHERIT','OVERRIDE'))
CHECK (validation_method IS NULL OR
       validation_method IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))

       (row_tolerance >= 0 AND row_tolerance <= 100))

       lookback_hours BETWEEN 0 AND 8760)

    AND enabled IS NULL
    AND validation_method IS NULL
    AND row_tolerance IS NULL
    AND lookback_hours IS NULL)

  (override_mode = 'OVERRIDE'
    AND enabled IS NOT NULL
    AND validation_method IS NOT NULL
    AND row_tolerance IS NOT NULL
    AND lookback_hours IS NOT NULL)
```

### 11.3 业务约束和生效

- `ROW_COUNT_CHECKSUM` 只有当前数据集版本存在真实业务主键时才允许保存；保存接口必须检查当前版本。
- 无业务主键数据集固定解析为 `ROW_COUNT`，页面禁用内容 Checksum。
- 数据集策略变化会在选择继承的数据集任务下一次执行开始前重新解析；运行中执行继续使用启动时快照。
- 任务级明确覆盖不受数据集策略变化影响。
- 最终生效策略、来源层级和 revision 保存到 `sync_execution` 的有效配置快照。

## 12. `dataset_message_policy`

职责：数据集级 RabbitMQ 消息业务策略。所有任务只能读取该策略，不能覆盖。

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |

| `topic` | `varchar(100)` | NULL | 默认与 Routing Key 相同 |
| `key_template` | `varchar(500)` | NULL | 旧协议 `messageKey` 模板 |
| `rate_limit_per_second` | `integer` | NOT NULL DEFAULT `1000` | 发布速率限制，0 表示不额外限制 |

### 12.2 约束

```text
CHECK (btrim(source_system) <> '')
CHECK (btrim(tenant_id) <> '')
CHECK (rate_limit_per_second >= 0)
CHECK (page_size BETWEEN 1 AND 1000000)
CHECK (revision >= 0)
CHECK (
  enabled = false
  OR (
    routing_key IS NOT NULL AND btrim(routing_key) <> ''
    AND topic IS NOT NULL AND btrim(topic) <> ''
    AND key_template IS NOT NULL
  )
)
```

关闭策略时保留 Routing Key、Topic 和模板，方便后续重新启用，不要求清空配置。

### 12.3 固定数据集映射

P0 只允许以下三项启用：

| `standard_dataset.dataset_code` | Routing Key | Topic 默认值 |
| --- | --- | --- |
| `ODS_YL_HUANZHEJBXX` | `YL_HUANZHEJBXX` | `YL_HUANZHEJBXX` |
| `ODS_YL_KESHIXX` | `YL_KESHIXX` | `YL_KESHIXX` |
| `ODS_YL_ZHIGONGXX` | `YL_ZHIGONGXX` | `YL_ZHIGONGXX` |

该约束依赖父表数据集编码，PostgreSQL `CHECK` 不能跨表表达，因此由保存服务在锁定 `standard_dataset` 后校验。数据库主键保证每个数据集只有一条消息策略。

### 12.4 明确删除和运行规则

本表不保存：

```text
transport
exchange_name
full_sync_mode
send_truncate_signal
任务级消息配置
```

固定运行语义：

- RabbitMQ Exchange 固定为 `YL`，连接参数来自部署 Secret，不进入本表。
- 全量执行发送本次全量全部业务数据；增量执行发送本次增量全部业务数据。
- 不支持 `SKIP`、`NOTIFY_ONLY`、完成通知或 TRUNCATE 信号。
- 每次执行启动时直接读取当前数据集消息策略并保存执行/Outbox 指令快照。
- 字段不存在或值为 `NULL` 时按旧协议替换为空字符串；`messageId` 每次发送重新生成 27 位 ID。
- 消息策略变化只影响后续新执行，不修改运行中执行或历史 Outbox。

## 13. 策略创建、更新和审计

### 13.1 初始化

第一次导入数据集时在同一事务中创建：

```text
dataset_sync_policy
dataset_validation_policy
dataset_message_policy
```

默认值：

- 同步：Fetch Size 5000、上界延迟 5 分钟、回看 0、调度继承全局每 4 小时。
- 校验：继承全局 `ROW_COUNT + 容差 0 + lookback 0`。
- 消息：三项协议数据集按固定 Routing Key 初始化启用，其余默认关闭；管理员仍可关闭或重新启用。

如果数据集再次从 `VOID` 恢复，保留原策略及 revision，不重复创建或覆盖管理员配置。

### 13.2 更新

- 所有策略更新使用 `revision` 乐观锁。
- 保存成功后增加 revision、更新时间和更新人。
- 未知字段、旧传输模式和旧自动复检参数明确拒绝，不静默忽略。
- 同步执行类默认变化不自动改任务；治理类校验和数据集消息按已确认生效规则处理。
- 成功和失败都写 `audit_log`，敏感值和 RabbitMQ 连接参数不进入摘要。

## 14. 查询和索引方向

### 14.1 数据集列表

列表主查询只读取数据集身份和当前版本摘要：

```text
standard_dataset
LEFT JOIN standard_dataset_version current_version
```

支持按以下条件数据库分页：

- 数据集编码；
- 名称；
- `ACTIVE/VOID`；
- 最近同步时间；
- 是否存在业务主键；
- 是否支持增量；
- 消息是否启用。

策略和字段不在列表中逐数据集 N+1 加载；使用批量投影或聚合查询。

建议索引：

```text
INDEX idx_dataset_version_capability
    ON standard_dataset_version
       (dataset_id, business_key_count, incremental_field_code)

INDEX idx_dataset_message_enabled
    ON dataset_message_policy (enabled, dataset_id)
```

### 14.2 数据集详情

详情按以下独立查询组织：

1. 身份和当前版本；
2. 当前版本字段，按 `ordinal_no`；
3. 同步策略；
4. 最终生效校验策略和来源；
5. 消息策略；
6. 关联链路数量及版本状态摘要。

不把全部字段、链路和策略做成一个笛卡尔积 Join。

### 14.3 版本历史

```text
INDEX idx_dataset_version_history
    ON standard_dataset_version (dataset_id, version_no DESC)
```

字段历史只按明确版本查询，不提供跨全部版本的默认字段明细扫描。

## 15. 旧对象到目标对象的修正

| 老对象或字段 | 目标处理 |
| --- | --- |
| `dfetl_dataset` 当前行快照 | 拆为 `standard_dataset` 身份和不可变版本 |
| `dfetl_field` 当前字段及 `field_status=VOID` | 每个版本保存完整字段集合，不在版本内作废字段 |
| `contract_hash VARCHAR(128)` | 规范为 SHA-256 `char(64)` |
| `target_field_code` | 删除；Doris 字段名固定 `lower(field_code)` |
| `primary_key boolean` | 改为可排序的 `business_key_ordinal` |
| 未知类型回退 `VARCHAR(256)` | 保存 `UNSUPPORTED` 并在正式执行前失败 |
| `dfetl_sync_policy.write_mode/sync_template/incremental_field` | 删除；由当前数据集合同确定 |
| `reader_parallelism` | 删除；第一阶段固定为 1 |
| 校验 `trigger_mode/fail_block/revalidate_*` | 删除；同步门禁和人工复检语义固定 |
| 校验默认 `lookback=2/自动复检=true` | 改为 lookback 0、自动复检关闭 |
| 消息 `transport/full_sync_mode` | 删除；只保留 RabbitMQ 且发布范围固定 |
| 消息策略复制到任务 | 删除；任务/执行只保存当次快照 |
| 通用 JDBC 类型规则覆盖医疗合同 | 禁止；两套规则物理和服务边界分离 |

## 16. 本批次验收结论

本批次未发现需要新增业务确认的问题。物理设计均由已经确认的业务基线和旧代码实际字段直接推导，并修正了以下真实旧实现问题：

- 当前数据集/字段行无法完整追溯定义版本；
- 字段删除通过修改旧行状态表达，不能还原历史完整合同；
- 未知类型使用兜底 Doris 类型；
- 同步策略允许人工改写由业务主键和增量字段决定的任务类型；
- Reader 并发策略与已确认的单并发冲突；
- 校验默认自动复检和非零回看与新基线冲突；
- 消息保留已废止的 transport 和全量模式。

下一批物理字典继续复核：

```text
collection_route
collection_route_institution
collection_route_version
collection_route_version_institution
route_field_resolution
sync_task
sync_task_version
task_governance_override
task_watermark
```

下一批同时补齐已经确认但当前逻辑模型表达不足的“数据预检提示/风险展示策略”全局、数据集和任务覆盖字段，不重新讨论其业务语义。
