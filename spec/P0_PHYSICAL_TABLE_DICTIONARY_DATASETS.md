## 1. 当前对象

本文件只定义以下目标对象：

```text
standard_dataset
standard_dataset_version
standard_dataset_field
field_conversion_contract
field_conversion_rule
generic_jdbc_type_mapping
dataset_sync_policy
dataset_message_policy
```

明确不建立：

```text
global_validation_policy
dataset_validation_policy
task_validation_policy
```

正式同步校验配置统一收敛为：

```text
system_setting[validation.default_method]
standard_dataset.validation_method_override
sync_task.validation_method_override
```

运行时最终生效结果固定到 `sync_execution` 校验快照；历史校验事实保存在 `validation_run`。

## 2. 固定业务结论

1. 标准数据集只能由管理员从医共体规范库人工同步，不允许手工新增，不设置自动同步。
2. 数据集长期身份与不可变定义版本分离；只有规范化定义 Hash 变化时才新增 `standard_dataset_version`。
3. 标准字段版本只插入不更新；历史定义通过版本追溯，不使用当前字段行 + VOID 字段模拟历史。
4. 标准字段与 Source JDBC 字段只允许大小写差异，不支持人工重命名、别名、默认值和转换表达式改变字段身份。
5. 未知医疗字段类型或格式保存为 `UNSUPPORTED`，正式执行不得回退成任意 VARCHAR 兜底类型。
6. Reader 第一阶段固定单并发；`dataset_sync_policy` 只保存创建新 Task 所需的执行类默认值。
7. 正式同步校验不能关闭，最低为严格 `ROW_COUNT`；不保存容差、校验回看、自动复检和失败动作配置。
8. 消息策略只保存于 Dataset 级；Task 不复制或覆盖消息配置。
9. Dataset 定义同步不得覆盖管理员维护的 `validation_method_override`、同步默认值和消息策略。
10. `standard_dataset_version`、`collection_route_version` 和字段转换合同继续保持不可变版本化；**Task 不版本化**。

## 3. 数据集同步事务

一次管理员人工同步固定按以下边界执行：

```text
读取医共体规范库完整定义
→ 校验读取结果非空、Dataset/Field 身份不重复
→ 使用当前 ACTIVE 字段转换合同规范化定义
→ 计算 definition_hash
→ 锁定 standard_dataset
→ Hash 未变化：更新同步摘要
→ Hash 变化：插入 standard_dataset_version + 全部 field
→ 延迟外键校验
→ 切换 standard_dataset.current_version_id
→ 提交
```

固定规则：

- 规范库读取为空时整次同步失败，不批量把本地 Dataset 作废。
- 同一次同步中的外部 Dataset ID、Dataset Code、Field ID、Field Code、字段顺序必须唯一。
- `definition_hash` 覆盖 Dataset 身份、源定义版本、字段顺序、标准类型/格式、空值、业务主键顺序、值域、转换合同及最终 Doris 类型。
- 重复同步且规范化内容未变化时不产生空版本。
- 新版本、字段集合和当前版本指针切换必须在一个事务完成。
- 已提交版本不原地修补；错误通过新的不可变版本修正。
- 成功和失败均记录 `audit_log`，不记录规范库密码和完整敏感连接信息。
- 数据集定义同步**不得**修改 `standard_dataset.validation_method_override`、`dataset_sync_policy` 或 `dataset_message_policy`。

## 4. `standard_dataset`

职责：标准数据集稳定身份、当前不可变定义版本指针，以及少量 Dataset 当前管理配置。

### 4.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | PK | 内部主键 |
| `external_dataset_id` | `varchar(64)` | NOT NULL | 医共体规范库稳定 ID |
| `dataset_code` | `varchar(100)` | NOT NULL | 标准 Dataset 编码，规范化为大写 |
| `name` | `varchar(200)` | NOT NULL | Dataset 名称 |
| `status` | `varchar(16)` | NOT NULL DEFAULT `'ACTIVE'` | `ACTIVE/VOID` |
| `current_version_id` | `bigint` | NULL | 当前不可变定义版本；首次成功导入事务结束前必须非空 |
| `validation_method_override` | `varchar(32)` | NULL | `NULL/ROW_COUNT/ROW_COUNT_CHECKSUM`；NULL 表示继承全局 |
| `first_imported_at` | `timestamptz` | NOT NULL | 首次成功导入时间 |
| `last_synced_at` | `timestamptz` | NOT NULL | 最近一次同步处理时间 |
| `last_sync_result` | `varchar(20)` | NOT NULL | `CREATED/UPDATED/UNCHANGED/REACTIVATED/VOIDED/FAILED` |
| `last_sync_error` | `varchar(1000)` | NULL | 最近失败的脱敏摘要；成功时为空 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 当前版本指针、校验覆盖等可变配置的乐观锁版本 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |
| `updated_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 4.2 约束

```text
CHECK (btrim(external_dataset_id) <> '')
CHECK (dataset_code = upper(btrim(dataset_code)))
CHECK (btrim(dataset_code) <> '')
CHECK (btrim(name) <> '')
CHECK (status IN ('ACTIVE','VOID'))
CHECK (validation_method_override IS NULL OR
       validation_method_override IN ('ROW_COUNT','ROW_COUNT_CHECKSUM'))
CHECK (last_sync_result IN
       ('CREATED','UPDATED','UNCHANGED','REACTIVATED','VOIDED','FAILED'))
CHECK (revision >= 0)
CHECK ((last_sync_result = 'FAILED') OR last_sync_error IS NULL)
```

当前版本同父约束：

```text
FOREIGN KEY (id,current_version_id)
REFERENCES standard_dataset_version(dataset_id,id)
DEFERRABLE INITIALLY DEFERRED
```

### 4.3 唯一与索引

```text
UNIQUE (external_dataset_id)

UNIQUE INDEX uk_standard_dataset_code_ci
    ON standard_dataset(lower(dataset_code))

INDEX idx_standard_dataset_status_code
    ON standard_dataset(status,dataset_code,id)

INDEX idx_standard_dataset_name_ci
    ON standard_dataset(lower(name),id)

INDEX idx_standard_dataset_last_synced
    ON standard_dataset(last_synced_at DESC,id)
```

`validation_method_override` 选择度低，不单独建立索引。

### 4.4 生命周期和校验覆盖

- 不提供手工新增、物理删除和手工作废入口。
- 权威来源中消失的 Dataset 置为 `VOID`，保留当前版本和历史。
- `VOID` Dataset 不能用于新建 Route/Task；已有已接受运行按启动快照完成。
- 同一外部 ID 再次出现时恢复 `ACTIVE`；定义无变化时不创建版本。
- `validation_method_override=NULL` 表示继承 `system_setting[validation.default_method]`，不保存 `override_mode=INHERIT`。
- 无真实业务主键的数据集不得保存 `ROW_COUNT_CHECKSUM`；保存接口必须检查当前 Dataset 合同能力。
- 修改校验覆盖使用 `standard_dataset.revision`，并记录成功/失败审计。
- Dataset 定义同步、恢复 ACTIVE、重复同步均不得静默重置管理员校验覆盖。

## 5. `standard_dataset_version`

职责：一次规范化后的完整不可变 Dataset 定义。

### 5.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 版本主键 |
| `dataset_id` | `bigint` | NOT NULL | FK `standard_dataset(id)`，`ON DELETE RESTRICT` |
| `version_no` | `integer` | NOT NULL | 父 Dataset 内从 1 递增 |
| `source_definition_version` | `varchar(100)` | NULL | 规范库版本快照 |
| `definition_hash` | `char(64)` | NOT NULL | 规范化定义 SHA-256 |
| `conversion_contract_version` | `varchar(64)` | NOT NULL | FK `field_conversion_contract(contract_version)` |
| `institution_code_field_code` | `varchar(100)` | NOT NULL | 标准医疗机构代码字段 |
| `incremental_field_code` | `varchar(100)` | NULL | 时间增量字段；没有时为空 |
| `field_count` | `integer` | NOT NULL | 字段数量 |
| `business_key_count` | `integer` | NOT NULL | 联合业务主键字段数量；无业务主键为 0 |
| `imported_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 导入时间 |
| `imported_by` | `bigint` | NULL | FK `app_user(id)`，`ON DELETE SET NULL` |

### 5.2 约束和支撑唯一键

```text
CHECK (version_no > 0)
CHECK (definition_hash ~ '^[0-9a-f]{64}$')
CHECK (institution_code_field_code = upper(btrim(institution_code_field_code)))
CHECK (incremental_field_code IS NULL OR
       incremental_field_code = upper(btrim(incremental_field_code)))
CHECK (field_count > 0)
CHECK (business_key_count >= 0 AND business_key_count <= field_count)

UNIQUE (dataset_id,version_no)
UNIQUE (dataset_id,definition_hash)
UNIQUE (dataset_id,id)
```

字段归属延迟外键：

```text
FOREIGN KEY (id,institution_code_field_code)
REFERENCES standard_dataset_field(dataset_version_id,field_code)
DEFERRABLE INITIALLY DEFERRED

FOREIGN KEY (id,incremental_field_code)
REFERENCES standard_dataset_field(dataset_version_id,field_code)
DEFERRABLE INITIALLY DEFERRED
```

### 5.3 跨字段规则

提交前服务校验：

1. `field_count` 与字段行数一致。
2. `business_key_ordinal` 非空行数等于 `business_key_count`。
3. 业务主键顺序连续为 `1..N`。
4. 机构代码字段必须唯一存在。
5. 有业务主键时机构代码字段属于联合业务主键；无业务主键时机构代码只承担范围隔离。
6. 增量字段必须属于当前版本、能按日期时间合同处理，并且数据集存在真实业务主键。
7. 无业务主键固定生成 `FULL_ONLY + REPLACE_INSTITUTION_SCOPE + DUPLICATE_KEY` 任务组合。
8. `definition_hash` 由将提交的规范化字段和合同重新计算核对。

### 5.4 不可变性

- Dataset Version 和 Field Version 创建后禁止业务 UPDATE/DELETE。
- 当前版本只由 `standard_dataset.current_version_id` 表达。
- 被 `collection_route_version`、当前 `sync_task`、`sync_execution` 或 `validation_run` 历史上下文引用的版本必须长期保留。
- 不存在“Task Version 引用 Dataset Version”的目标关系。

## 6. `standard_dataset_field`

职责：某个 Dataset Version 中的不可变标准字段定义和已解析 Doris 合同。

### 6.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | `bigint identity` | PK | 字段版本主键 |
| `dataset_version_id` | `bigint` | NOT NULL | FK `standard_dataset_version(id)` |
| `external_field_id` | `varchar(64)` | NOT NULL | 规范库字段 ID 快照 |
| `field_code` | `varchar(100)` | NOT NULL | 标准字段编码，大写 |
| `field_name` | `varchar(200)` | NULL | 字段名称 |
| `ordinal_no` | `integer` | NOT NULL | 定义顺序，从 1 开始 |
| `standard_type` | `varchar(30)` | NOT NULL | 医疗标准类型 |
| `standard_format` | `varchar(100)` | NULL | 原始标准格式 |
| `declared_length` | `integer` | NULL | 逻辑长度 |
| `declared_precision` | `integer` | NULL | 数值精度 |
| `declared_scale` | `integer` | NULL | 小数位 |
| `standard_nullable` | `boolean` | NOT NULL | 是否允许 NULL |
| `business_key_ordinal` | `smallint` | NULL | 联合业务主键顺序 |
| `value_domain_code` | `varchar(100)` | NULL | 值域编码快照 |
| `conversion_rule_code` | `varchar(100)` | NULL | 命中的转换规则 |
| `conversion_status` | `varchar(16)` | NOT NULL | `RESOLVED/UNSUPPORTED` |
| `doris_type` | `varchar(128)` | NULL | 最终 Doris 类型 |
| `doris_nullable` | `boolean` | NULL | 最终 Doris 空值合同 |
| `created_at` | `timestamptz` | NOT NULL DEFAULT `CURRENT_TIMESTAMP` | 创建时间 |

### 6.2 约束与索引

```text
CHECK (btrim(external_field_id) <> '')
CHECK (field_code = upper(btrim(field_code)))
CHECK (ordinal_no > 0)
CHECK (btrim(standard_type) <> '')
CHECK (declared_length IS NULL OR declared_length > 0)
CHECK (declared_precision IS NULL OR declared_precision > 0)
CHECK (declared_scale IS NULL OR declared_scale >= 0)
CHECK (declared_precision IS NULL OR declared_scale IS NULL OR
       declared_scale <= declared_precision)
CHECK (business_key_ordinal IS NULL OR business_key_ordinal > 0)
CHECK (business_key_ordinal IS NULL OR standard_nullable = false)
CHECK (conversion_status IN ('RESOLVED','UNSUPPORTED'))
CHECK (
  (conversion_status='RESOLVED'
    AND conversion_rule_code IS NOT NULL
    AND doris_type IS NOT NULL
    AND doris_nullable IS NOT NULL)
  OR
  (conversion_status='UNSUPPORTED'
    AND conversion_rule_code IS NULL
    AND doris_type IS NULL
    AND doris_nullable IS NULL)
)

UNIQUE (dataset_version_id,external_field_id)
UNIQUE (dataset_version_id,field_code)
UNIQUE (dataset_version_id,ordinal_no)
UNIQUE (dataset_version_id,id)

UNIQUE INDEX uk_dataset_field_business_key_order
    ON standard_dataset_field(dataset_version_id,business_key_ordinal)
    WHERE business_key_ordinal IS NOT NULL

INDEX idx_dataset_field_order
    ON standard_dataset_field(dataset_version_id,ordinal_no,id)
```

### 6.3 固定边界

- Doris 业务列名固定为 `lower(field_code)`，不额外持久化目标字段改名。
- JDBC 实际字段名保存在 `route_field_resolution`，只允许大小写差异。
- `UNSUPPORTED` 必须如实展示；正式建表、重建和同步执行在使用该版本时明确失败。
- 医疗 L、B/BY、数值、日期时间等最终类型与规范化行为只能来自版本化字段转换合同。

## 7. `field_conversion_contract`

职责：不可变字段转换合同版本头。

建议核心字段：

```text
contract_version varchar(64) PK
status varchar(16) NOT NULL             # ACTIVE/RETIRED
contract_hash char(64) NOT NULL UNIQUE
description text NULL
created_at timestamptz NOT NULL
created_by bigint NULL
retired_at timestamptz NULL
retired_by bigint NULL
```

关键约束：

```text
CHECK status IN ('ACTIVE','RETIRED')
CHECK contract_hash ~ '^[0-9a-f]{64}$'
UNIQUE INDEX uk_field_conversion_contract_active
    ON field_conversion_contract((1)) WHERE status='ACTIVE'
```

- 同一时间只允许一个合同版本用于新 Dataset 同步。
- 合同发布后规则不可修改；新逻辑发布新合同版本。
- RETIRED 只影响后续同步；已有 Dataset Version 和历史运行继续可解释。
- 被 Dataset Version 引用的合同不可物理删除。

## 8. `field_conversion_rule`

职责：字段转换合同版本中的不可变匹配、Doris 类型、Reader 规范化、Checksum 和 Validation 规则。

建议核心字段：

```text
id bigint identity PK
contract_version varchar(64) NOT NULL
rule_code varchar(100) NOT NULL
priority integer NOT NULL DEFAULT 0
medical_type varchar(30) NOT NULL
format_pattern varchar(256) NULL
key_scope varchar(16) NOT NULL DEFAULT 'ANY'   # ANY/KEY/NON_KEY
doris_type_template varchar(128) NOT NULL
normalization_rule_code varchar(100) NOT NULL
checksum_rule_code varchar(100) NOT NULL
validation_rule_code varchar(100) NOT NULL
description text NULL
created_at timestamptz NOT NULL
```

关键规则：

- `UNIQUE(contract_version,rule_code)`。
- 同一输入在同一合同版本内只能命中一个最高优先级规则，歧义时拒绝发布。
- 主键规则不得生成无界不可索引 Key 类型。
- `L` 统一按 BOOLEAN/0/1 合同；`B/BY` 按 STRING + Base64 合同。
- 无规则命中时保存 `UNSUPPORTED`，不得隐式 fallback。

## 9. `generic_jdbc_type_mapping`

职责：非标准/诊断场景的 JDBC → Doris 类型建议；绝不能覆盖医疗标准字段合同。

建议核心字段：

```text
id bigint identity PK
profile_name varchar(64) NOT NULL
profile_version integer NOT NULL
rule_code varchar(100) NOT NULL
source_db_type varchar(24) NOT NULL
source_type_pattern varchar(128) NOT NULL
recommended_doris_type varchar(128) NOT NULL
compatibility_level varchar(16) NOT NULL       # PASS/WARN/REJECT
reason text NULL
enabled boolean NOT NULL DEFAULT true
priority integer NOT NULL DEFAULT 0
revision bigint NOT NULL DEFAULT 0
created_*/updated_*
```

- `UNIQUE(profile_name,profile_version,rule_code)`。
- 修改通用映射只影响后续诊断/预览，不热更新 Dataset Version、Route Version、当前 Task 或 Doris 结构。

## 10. `dataset_sync_policy`

职责：创建新 `sync_task` 时读取的 Dataset 执行类默认值；它不是已有 Task 的动态父配置，也不生成 Task Version。

### 10.1 字段

| 列 | PostgreSQL 类型 | 空值/默认 | 说明 |
| --- | --- | --- | --- |
| `dataset_id` | `bigint` | PK/FK | FK `standard_dataset(id)`，`ON DELETE CASCADE` |
| `fetch_size` | `integer` | NOT NULL DEFAULT `5000` | Reader Fetch Size |
| `upper_bound_delay_minutes` | `integer` | NOT NULL DEFAULT `5` | 增量上界延迟 |
| `lookback_seconds` | `integer` | NOT NULL DEFAULT `0` | 增量读取回看，默认 0 |
| `schedule_mode` | `varchar(20)` | NOT NULL DEFAULT `'INHERIT'` | `INHERIT/MANUAL/EVERY_N_HOURS/CRON` |
| `schedule_interval_hours` | `integer` | NULL | EVERY_N_HOURS 时填写 |
| `schedule_cron` | `varchar(128)` | NULL | CRON 时填写 |
| `schedule_timezone` | `varchar(64)` | NULL | 非 INHERIT 时填写 |
| `revision` | `bigint` | NOT NULL DEFAULT `0` | 乐观锁 |
| `created_at/created_by` |  |  | 创建审计 |
| `updated_at/updated_by` |  |  | 更新审计 |

### 10.2 语义

- `INHERIT` 表示**创建 Task 时**读取全局调度默认并把最终值固化到 `sync_task`；不是运行时动态继承。
- Dataset 默认变化不自动修改已有 `sync_task`；管理员如需改变已有 Task，显式编辑 Task 当前配置。
- `sync_task.schedule_source/schedule_source_revision` 保存当前配置最初来自 GLOBAL/DATASET/TASK 的来源信息，但运行仍以 `sync_task` 当前值为准。
- Dataset 同步策略不保存 `write_mode/task_kind/doris_key_model/incremental_field_code`；这些由当前 Dataset 合同确定。
- Reader 并发固定为 1，不保存 `reader_parallelism`。

## 11. 正式校验配置：不建立 Policy 表

本文件不再定义任何独立 Validation Policy 表。

### 11.1 全局

```text
system_setting[validation.default_method]
```

允许：

```text
ROW_COUNT
ROW_COUNT_CHECKSUM
```

数据库没有设置行时使用代码注册默认 `ROW_COUNT`。

### 11.2 Dataset

```text
standard_dataset.validation_method_override
```

允许：

```text
NULL
ROW_COUNT
ROW_COUNT_CHECKSUM
```

`NULL` 即继承，不保存 `override_mode`。

### 11.3 Task 与运行

Task 覆盖由 `sync_task.validation_method_override` 保存。执行启动时按：

```text
Task override
→ Dataset override
→ system_setting[validation.default_method]
→ 注册默认 ROW_COUNT
→ Dataset 合同能力强制
```

解析出唯一最终方法，并固定到 `sync_execution`：

```text
validation_method
validation_source
validation_source_revision
validation_contract_forced
```

具体物理约束以 `P0_PHYSICAL_TABLE_DICTIONARY_VALIDATION_POLICY.md` 为权威来源。

## 12. `dataset_message_policy`

职责：Dataset 级 RabbitMQ 消息业务策略；Task 无覆盖。

建议核心字段：

```text
dataset_id bigint PK/FK
 enabled boolean NOT NULL DEFAULT false
source_system varchar(50) NOT NULL DEFAULT 'HIS'
tenant_id varchar(50) NOT NULL DEFAULT '0'
routing_key varchar(100) NULL
topic varchar(100) NULL
key_template varchar(500) NULL
rate_limit_per_second integer NOT NULL DEFAULT 1000
page_size integer NOT NULL DEFAULT 1000
revision bigint NOT NULL DEFAULT 0
created_*/updated_*
```

P0 固定可启用 Dataset：

| Dataset Code | Routing Key |
| --- | --- |
| `ODS_YL_HUANZHEJBXX` | `YL_HUANZHEJBXX` |
| `ODS_YL_KESHIXX` | `YL_KESHIXX` |
| `ODS_YL_ZHIGONGXX` | `YL_ZHIGONGXX` |

固定运行语义：

- Exchange 固定 `YL`；RabbitMQ 连接参数来自部署 Secret。
- 全量发送本次全量全部业务数据，增量发送本次增量全部业务数据。
- 不支持 `SKIP/NOTIFY_ONLY`、完成通知或 TRUNCATE 信号。
- 执行启动时读取当前 Dataset 消息策略并形成运行/Outbox 快照。
- 消息策略变化只影响后续新执行；不修改运行中 Execution 或历史 Outbox。
- 不建立 Task 级消息策略副本。

## 13. Dataset 初始化、更新与审计

### 13.1 首次成功导入

同一事务创建/初始化：

```text
standard_dataset + first standard_dataset_version + fields
dataset_sync_policy
dataset_message_policy
```

不创建：

```text
global_validation_policy
dataset_validation_policy
```

`standard_dataset.validation_method_override` 默认 `NULL`；全局默认校验方式由 `system_setting` 注册值解析，Flyway V1 不要求插入固定策略行。

Dataset 从 VOID 恢复时保留原同步默认、校验覆盖和消息策略，不覆盖管理员配置。

### 13.2 更新

- Dataset 当前配置更新使用各自 `revision` 乐观锁。
- `validation_method_override` 与 `standard_dataset.revision` 共用并发控制。
- Dataset 定义同步不得覆盖同步默认、校验覆盖和消息策略。
- 同步默认变化不热更新已有 Task。
- 消息策略变化只影响后续 Execution。
- 所有业务写操作成功/失败均写 `audit_log`。

## 14. 查询方向

### Dataset 列表

主查询：

```text
standard_dataset
LEFT JOIN standard_dataset_version current_version
```

支持按编码、名称、状态、最近同步时间、业务主键能力、增量能力、消息启用状态分页。

### Dataset 详情

按独立查询组织：

1. Dataset 身份、当前版本和 Dataset 校验覆盖；
2. 当前版本字段；
3. 同步默认；
4. 解析后的最终校验方法及来源；
5. 消息策略；
6. 关联 Route 数量/状态摘要。

不把字段、Route、策略一次性做笛卡尔积 Join。

## 15. 旧模型机械清理映射

| 旧对象或描述 | 当前处理 |
| --- | --- |
| `global_validation_policy` | 删除；全局默认使用 `system_setting[validation.default_method]` |
| `dataset_validation_policy` | 删除；覆盖合并到 `standard_dataset.validation_method_override` |
| `task_validation_policy` | 删除；覆盖合并到 `sync_task.validation_method_override` |
| validation `override_mode` | 删除；`NULL` 直接表示继承 |
| validation `enabled` | 删除；正式同步校验不可关闭 |
| `row_tolerance/tolerance_*` | 删除；ROW_COUNT 严格相等 |
| validation `lookback_hours` | 删除；校验使用 Execution 精确范围 |
| `revalidate_enabled/revalidate_delay/fail_block` | 删除；自动复检不作为配置，SYNC_GATE 固定阻断 |
| “生成新 Task Version 后应用 Dataset 默认” | 改为“创建新 Task 时解析并固化默认值” |
| “Task Version 引用 Dataset Version” | 改为当前 `sync_task.dataset_version_id` + 历史 Execution/Validation 快照 |
| 通用 JDBC 类型规则覆盖医疗合同 | 禁止；两套规则边界分离 |

## 16. 验收

- 当前对象清单不存在三张独立 Validation Policy 表。
- `standard_dataset` 直接保存可空 `validation_method_override`。
- Dataset 定义同步不会重置校验覆盖。
- `NULL` 正确表示继承，不存在 validation `override_mode`。
- 无真实业务主键 Dataset 不能保存 `ROW_COUNT_CHECKSUM`。
- Dataset Version/Field/Field Contract 保持不可变；Task 不版本化。
- `dataset_sync_policy` 只作为创建新 Task 的默认来源，不热更新已有 Task。
- Dataset Message Policy 仍只存在于 Dataset 级。
- 历史运行使用 Execution/Validation 启动快照，不依赖已废止 Task Version。
