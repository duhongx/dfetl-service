# Vue 前端开发

## 工作目标

在现有产品和设计体系内完成可用、可维护、可验证的前端变更。除非用户明确要求重新设计，否则不要借功能修改更换视觉风格、交互模式或项目架构。

## 开始前

1. 读取适用范围内的 `AGENTS.md`、产品结论、页面说明和验收要求。
2. 检查 `package.json`、锁文件、构建配置和源码，确认 Vue 版本、JavaScript/TypeScript、Vite/Webpack、组件库、路由、状态管理、HTTP 封装、样式方案和测试工具。
3. 查找同类页面和公共组件，沿用现有目录、命名、布局、权限、表单、表格、弹窗和反馈方式。
4. 区分评审与实施：用户只要求分析时不修改代码；用户要求实现时完成必要改动和验证。

不要假设项目使用 Composition API、Pinia、Vuex、Element Plus、Element UI、Ant Design Vue 或其他特定方案。

## 实施流程

### 1. 确定影响范围

- 从路由和页面入口追踪组件、状态、API、类型、权限和样式依赖。
- 明确桌面端、移动端、浏览器兼容和响应式要求中已确认的部分。
- 只修改目标所需代码，不进行无关格式化、组件改名或全局样式重写。
- 若交互或业务能力仍存在阻塞性选择，先使用 `$pragmatic-requirements-design` 处理。

### 2. 复用项目现有模式

- 优先复用公共组件、布局、图标、设计令牌、API 封装和工具函数。
- 页面状态、组件状态和全局状态按项目现有边界选择，不为局部功能新增全局状态。
- 保持路由、菜单、按钮和数据权限一致，不能只隐藏界面而忽略实际权限边界。
- 使用现有国际化、主题和样式约定；项目没有这些能力时不要为单个页面新增体系。
- 不引入新依赖，除非现有能力无法实现已确认需求，并说明必要性。

### 3. 完成交互闭环

根据功能实际需要处理：

- 初始加载、刷新、提交和重复点击；
- 加载中、空数据、成功、失败和权限不足；
- 表单初值、校验、重置、编辑回填和提交数据转换；
- 表格分页、排序、筛选、横向/纵向滚动和稳定列宽；
- 弹窗或抽屉的打开、关闭、取消、保存和脏数据处理；
- 请求取消、竞态和卸载后的状态更新风险；
- 键盘操作、标签关联等项目已有的可访问性要求。

不要为低概率情况建立复杂前端状态机。用户可以通过重新选择、修改配置和再次执行解决的问题，保持操作灵活并如实展示结果。

### 4. 协同后端契约

- 接口或字段发生变化时，同时使用 `$java-vue-api-contract` 核对后端 DTO、前端 API、类型及所有调用方。
- 不擅自转换空值、枚举、日期、金额、长整型 ID 和分页结构。
- 前端校验不得与服务端规则冲突；服务端错误应使用项目统一方式展示。
- Mock 数据必须符合真实接口契约，不能为了页面可用而掩盖接口差异。

## 验证

1. 运行受影响范围的类型检查、lint、单元测试或组件测试。
2. 运行项目构建，检查编译、打包和资源引用。
3. 按验收路径验证主要交互、空数据、失败、权限和重复操作场景。
4. 检查浏览器控制台错误、未处理 Promise、请求参数和响应映射。
5. 审查最终差异，确认没有无关视觉变化、临时 Mock、调试日志或新增依赖残留。

不要通过删除校验、使用大范围 `any`、关闭 lint 或忽略构建错误来完成任务。无法执行浏览器验证时，明确说明未验证内容。

## 完成输出

简要说明：

- 修改了哪些页面、组件和交互；
- 是否影响路由、权限、接口、类型或公共组件；
- 执行的检查和构建结果；
- 未验证内容及可能风险。
